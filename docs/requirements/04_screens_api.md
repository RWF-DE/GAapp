# 画面とAPI

## 画面仕様

画面は[概要](00_overview.md)の画面一覧に対応する。Next.js の静的書き出し（output: 'export'）で作るため、id をパスに埋め込む動的な URL は使わず、クエリ文字列で渡す（/stock?room=…）。画面の中の切り替え（タブ・品目・団体・行・絞り込み）もクエリ文字列に入れ、再読み込みと共有で同じ表示に戻れるようにする。サーバーのデータは TanStack Query で持ち、書き込みの後に関係するものを読み直す。UI 部品は shadcn/ui（ソースを手で置く）、表は TanStack Table。すべての画面で、読み込み中・データが空・権限なしの3状態と、読み込みの失敗（もう一度読み込むボタンつき）を表示する。年度の状態で書けないときは入力欄を無効にし、理由を帯で出す（「年度が確定中のため編集できません」など）。日時は Asia/Tokyo で表示する。データの多い画面には、最後に読み込んだ日時と「読み直す」を出す。招待されていない人がログインすると「総務から招待されていません」だけを表示する。

### 共通レイアウト（P-03）

- ログインが要る画面は共通レイアウトの中に置く。ログインしていなければ /login に送り、ログイン後に元のページへ戻す（戻り先は同じサイトのパスだけ）
- ログインのたび（ページを開いたときも）に `accept_my_invitations` を呼んでから、自分の year_roles・group_members を読む。今の年度は、既定ではロールか団体代表の行がある年度のうち1日目が最も遅いもの（最新の年度）。そうした年度が2つ以上ある人には、ヘッダーに年度の選択（1日目の新しい順。「R9（準備中）」）を出し、選んだ年度はそのタブの中でだけ覚える（新しいタブや部屋の QR から開いたときは最新の年度）。覚えた年度にロールも団体代表もなくなっていれば既定に戻す。年度は URL に入れない（部屋の QR の URL を年度によらず同じにするため。在庫入力は開いている年度に書く）。最新でない年度を開いているときは「最新でない年度（R8・終了）を表示しています」と、最新の年度に切り替えるボタンを帯で出す。在庫入力・申請・了承の回答では、最新でない年度に書く前に確かめる（D-31）
- どの年度にもロールも団体代表もなければ「総務から招待されていません」とログアウトのボタンだけを出す（ナビゲーションも年度も出さない）
- ヘッダーに今の年度と状態、表示名と立場、ログアウト。ナビゲーションは PC では左、スマホではメニューのボタンで開く。項目は開いている年度の立場で出し分ける（[概要](00_overview.md)の画面一覧のロール。admin は総務の画面すべて、staff は在庫入力・在庫一覧・申請一覧・振り分け（閲覧）、viewer は振り分け（確定後の閲覧）、団体代表は申請・自団体の振り分け、兼ねた人は両方）。URL を直接開いたときも同じ立場で出し分ける（合わなければ権限なしの表示）。表示の出し分けは見た目だけで、データは RLS と RPC が守る
- 画面の中では、読み込み中・データが空・権限なし（立場が合わない）の3状態の部品と、読み込みの失敗の部品を使う
- 印刷（部屋の QR のカード）のときはヘッダーとナビゲーションを隠す。ログアウトはその端末のセッションだけを終える（同じ人のほかの端末は抜けない）。ログアウトと利用者の切り替えでは、画面が持っているデータ（キャッシュ）を消す。保存していない入力の下書きは、手動のログアウトでは（保存していない入力があれば確かめてから）その人の分を消し、別の人がログインしたときは前の人の分を消す（共用の PC で前の人のデータを残さない）。セッションが切れて強制的にログアウトしたときは下書きを消さない（同じ人がログインし直せば戻せる）
- 権限や年度の状態が変わったと分かって立場を読み直すときは、読み直しの間も今の画面を出したままにする（入力・開いているダイアログを消さない。読み込み中の表示に置き換えるのは、最初の読み込みと利用者が変わったときだけ）
- 画面の中のリンクは、行き先の画面を開ける立場のときだけリンクにする（開けない立場には件数や文字だけを出す）
- 保存していない入力がある画面では、アプリの中で別の画面へ移る前と、年度を切り替える前に確かめる。ブラウザの戻る・タブの破棄・別のアプリへの切り替えは止められないので、入力をそのブラウザに下書きとして置き、開き直したときに戻せるようにする（保存に成功したら消す）
- 書き込みのボタンは、送っている間は押せなくする（二重に送らない）。通信が切れて保存されたか分からないときは、読み直して確かめてから送り直す

### ログイン /login（PC・スマホ）

- 「学校の Google アカウントでログイン」のボタン。ブラウザの PKCE フローで、リダイレクト先は basePath 込みの /auth/callback/（Supabase の Redirect URLs に登録する）
- フックで拒否されたとき（学校以外のアカウント）は「学校の Google アカウントでログインしてください」と出す。URL に付いたエラーの文言はそのまま表示しない
- ローカルだけ、メール＋パスワードのテスト用ログイン（E2E 用。D-02）を出す。ビルド時のフラグがあり、Supabase の URL がローカルのときだけ出し、本番のビルドにはコードごと入れない
- ログイン状態はブラウザに保存し（supabase-js）、トークンは自動で更新する
- LINE などのアプリの中のブラウザで開いたと分かるときは、「アプリの中では Google でログインできません。Safari か Chrome で開いてください」と URL のコピーのボタンを出す（Google のボタンは隠さない）

### ダッシュボード /（PC）

- 年度のステータス、申請の提出数／団体数、在庫を数えた保管場所の数／保管場所の数、検証の error・warning の件数、キャスター机交換の了承状況
- 年度の状態を進めるボタン（管理者のみ、理由の入力欄つき。確定と確定の解除では理由が必須）
- 確定ボタン：画面を開いたときに、ほかのデータより先に years.allocation_version を読み、その版で検証（validate）を実行する。確定のときは検証した版を `set_year_status` の `p_base_version` に渡す。conflict が返ったら、読み直して検証をやり直し、結果を見せてから、もう一度確定を押してもらう（自動では再送しない）。受付開始は締切（request_close_at）が未来に入っていないとエラーになるので、先に受付期間の入力を促す

### 在庫入力 /stock?room=…（スマホ）

- 表示：場所名、前回入力者と日時、品目ごとの行（品目名、数、前年の数）
- 操作：＋－ボタンと数字入力、「保存」。保存すると DB が counted_by（保存した人）と counted_at（保存した日時）を入れる（画面から送らない）
- 場所の選び方：一覧から選ぶか、部屋に貼った QR（/stock?room=… の URL）を読む
- 状態：年度が allocating 以降なら部員は読み取り専用。管理者は数え直しを入力でき、入力すると検証をやり直す。ただし確定中は、振り分けの合計より少なくなる数は保存できない（「確定を解除してから」と表示する）。終了した年度は読み取り専用。使用不可の部屋は先頭に「今年は使用不可」と表示する（数えることはできる）

### 在庫一覧 /stocks（PC）

- 保管場所×品目の表、前年との差、まだ数えていない場所（W104）、部屋に貼る QR の印刷

### 申請 /request（スマホ）

- 表示：団体名、使用場所、締切日時、その団体の区分で申請できる品目だけの入力欄（初期値0）、備考欄（数には影響しないと明記）
- 操作：「提出」で全品目と備考を RPC `submit_requests` で1回で保存し、submitted_at を記録する（日時は DB が入れる）。締切前なら何度でも修正できる。申請できない区分の品目は DB でも拒否する（E006。企業以外の長机(3人掛)は除く）。数は 10000 まで、備考は 2000 字まで
- 状態：締切後は読み取り専用で「変更は総務へ」と表示。複数団体の代表なら団体を切り替える

### 申請一覧 /requests（PC）

- 表示：団体×品目の表、区分フィルタ、未提出団体の一覧、備考がある団体に印
- 操作：セルを直接編集（締切後は理由の入力を必須にして RPC で保存）、企業・休憩所の代理入力、Googleフォーム回答の取り込み（下の「CSV取り込み」）

### 振り分け /allocation（PC、中心の画面）

- 見る人：管理者は振り分け中に編集できる。部員は読み取りだけ（在庫・余り・検証を含む。Excel 出力もできる）。閲覧のみは確定後だけ、行の一覧（運び元・運び先・団体・品目・数）を見る（在庫と申請は RLS で読めないので、余り・検証・団体別の差は出さない）（Q1）
- 上部：「自動振り分け」「最小変更で再実行」「確定」（確定中は「確定を解除」）「Excel出力」ボタン、年度ステータス、最終実行日時、最後に読み込んだ日時と「読み直す」。ほかの人が版を進めたら帯で知らせる（ダッシュボードの版の見張りと同じ）
- 左：品目タブ（R8 のシートと同じ並び。机(木)と不可机、椅子(木)と不可椅子はそれぞれ1つのタブ。ほかの品目は後ろに品目の並び順）。各タブは運び元ごとにまとめた表（運び先〔残すは「残す」〕、団体、品目〔2品目のタブだけ〕、申請品目〔品目と違うときだけ。列にせず、品目のセル〔品目の列がなければ団体のセル〕の2行目に「…の代わり」と出す〕、数、備考、自動／手動、固定）＋場所ごとの余り（在庫から、その部屋のその品目の行の合計を引いたもの。マイナスは E001 の印。使用不可の部屋は「使用不可（在庫 n）」で余りに数えない）。`?view=item&tab=<品目コード>`、`?row=<id>` でその行のタブを開き、行を目立たせる
- 右：検証結果（画面の幅が 1280px 未満なら表の下。error → warning → info の順。コードで絞れる）。クリックで該当行（rowIds）、部屋と品目のまとまり、団体（団体別の表示）、ルール（管理者はルール画面の `?code=`。ルール画面を開けない部員には、ルールのコードと内容の文をその場で出す）に移動。検証は未保存の変更を当てた行で回す
- 切替：「品目別」と「団体別」の表示。団体別では需要（前処理1・2を当てた後の申請。企業以外の長机(3人掛)は長机(2人掛)に、未提出の設営は固定の数に。D-05・D-07）と振り分け数（申請品目ベース）を並べて差を表示（不足は E003、多いのは W101）。内訳に運ぶ品目と運び元を出す。`?view=group&group=<id>`
- 読み込み：年度の版（years.allocation_version）を、ほかのデータより先に読む。保存と確定にはこの版を渡す
- 行の操作：追加・数の変更（1〜10000。0 にするときは削除）・運び元の変更・備考・削除・固定。手で変えた行は origin = manual（備考だけの変更も manual。固定だけなら origin は変えない）。自動の行に備考を書くと、その行は次の自動振り分け・最小変更で変わらなくなることを、備考の入力のところに出す。変更はすぐに送らず「未保存の変更」として画面に溜め、「保存」で理由（必須）を入れて1回の RPC で送る（1回に 1000 件まで）。保存は RPC で、他の人が先に変えていたら読み直す（ぶつからなかった未保存の変更は当て直し、当て直せなかったものは一覧で知らせる）。保存の返り値の版は、ロックした時点の版（allocation_version_before）が自分の持つ版と同じときだけ覚え直し、違えば読み直す。行の追加は、団体 → 申請品目 → 品目（ルールでその団体に許される代替先。ほかの品目は「ルール外（E004 になります）」と添える）→ 運び元（余りを添える）→ 数 → 固定するか、の順に選ぶ。未保存の変更があるうちは、自動振り分け・確定・Excel 出力を押せず、画面を離れるときは確かめる（未保存の変更は下書きとしても残し、開き直したときに当て直す）。保存の応答が届かず保存されたか分からないときは、そのまま送り直さず（行の追加が二重になるため）、版を読み直して、進んでいれば読み直した行と突き合わせ、保存されていたかを確かめてから知らせる
- 部屋の見出しから、その部屋を今年は使用不可にできる（管理者・振り分け中。マスタ設定の「今年の使用」と同じ）。使用不可にする前に、その部屋からの固定・手動の行を一覧にし、先に直して保存してもらう（固定の自動の行は固定を外す・運び元を変える・削除、手動の行は運び元を変える・削除。手動の行は固定を外しても再実行で動かない）。一覧が空になり、保存していない変更がなくなってから使用不可にする。順番を逆にすると、使用不可の部屋の行には運び元の変更と削除しか保存できず（固定を外すだけの変更も E002 で拒否される）、その行は検証の E002（error）として残って確定できないため（自動振り分け・最小変更で再実行は、固定・手動の行の E002 では止まらない。下の precheck）。すでに使用不可の部屋の行は、運び元を変えるか削除するだけにする（固定を外すには、先に部屋を使用可に戻す）。マスタ設定から振り分け中の年度の部屋を使用不可にするときも、その部屋からの固定・手動の行があれば振り分け画面へ案内する
- 「自動振り分け」：実行前に「自動の行 N 件を置き換えます。固定・手動の行は残ります」と確認。計算は Web Worker で行い、その間は画面をロック（段階〔計算エンジンの読み込み・組み立て・計算・保存・読み直し〕と経過秒数を出す。計算エンジンの読み込み・組み立て・計算の段階では、10 秒を過ぎたら「中止」を出す。保存を送った後は中止できず、結果を待つ。中止の後は版を読み直す）。計算エンジン（highs の wasm）は、管理者が振り分け中にこの画面を開いたときに読み込み始める（読み込み中は「計算エンジンを読み込み中」と出し、終わるまで実行できない）。結果が ok: false のときは振り分けを書き換えず、reason ごとに見出しを変えて出す（下）。入力を組み立てたときの版を保存の RPC に渡し、計算中に他の人が振り分け・了承・在庫・申請・ルールなどを変えていたら「他の人が変更しました」と出して読み直す（自動ではやり直さない）。計算の時間を結果に出す
  - invalid_input：「入力に誤りがあります」。inputErrors（項目とルールのコード）の一覧
  - precheck：「振り分けの前に直すものがあります」。issues（E001・E002・E005）の一覧。クリックで該当の行・ルールへ移動。precheck の E002 は、残すのルール（S08）の部屋が使用不可のときだけ出る（ルールを直す。ルールへ移動）。使用不可の部屋からの固定・手動の行は precheck では止めず、保存の後の検証の E002（error）として出て確定を止める（[振り分けの仕様](03_allocation.md)）。検証の一覧のその E002 の項目には、行ごとに運び元を変える・行を削除する操作だけを添える（固定を外すだけでは直らない〔使用不可の部屋の行は、固定だけの変更も E002 で拒否される〕ので出さない。固定を外したいときは部屋を使用可に戻してから）
  - infeasible：「解けません」。shortages（品目全体の不足 → 団体ごとの不足。groupId が null の行は品目全体）と causes（原因のルールと、需要・在庫合計）の一覧。「代替を含めても在庫が足りません」の cause は、代替先を共有する申請品目の組の不足を details の1件（itemIds の品目名を並べ、需要・在庫は組の合計）で出す。品目ごとの不足の行には混ぜない
  - solver_error：「計算できませんでした」。message（計算エンジンの読み込みの失敗か、計算中のエラーか）。読み込みの失敗なら、もう一度実行すると読み直す
- 申請できない品目の申請（E006）を除いて計算したときは、結果の上に「申請できない品目の申請 N 件を除いて計算しました」と出し、検証の E006 を示す
- 「確定」：error 0 件で、入力の誤り（設定の壊れたルール、消した団体・場所を参照したままのルールなど）がないときだけ押せる。理由の入力が必須。検証に使った版を一緒に送り、その後に何かが変わっていれば確定せずに読み直す（ダッシュボードの確定ボタンと同じ）。確定後は編集不可（編集のボタンを隠し、「確定中です。直すときは確定を解除してください」と出す。years に確定の日時の列がないので日時は出さない）。「確定を解除」は理由入力必須
- 「Excel出力」：その年度の全行（備考つき）を R8 様式で出す（[振り分けの仕様](03_allocation.md)の「Excel出力仕様」）。団体名が Excel の集計に使えないときは出力せず、マスタ設定で名前を変えるよう促す。振り分け中（確定前）に出すときは「確定前の振り分けです」と確かめ、ファイル名に「_確定前」を付ける（Q3）
- 状態：振り分けの行がない（「まだ自動振り分けをしていません」）、準備中・受付中（「締切の後に振り分けます」。ボタンは無効）、閲覧のみで確定前（「確定後に表示されます」）

### キャスター机交換 /swaps（PC）

- 対象：了承が要る代替ルール（needsConsent。R8 は S07）の（団体・元の品目・先の品目）のうち、今の置き換え台数（固定・手動・自動を問わない行の合計）が1以上のもの、または了承の記録があるもの。表：団体・企画名・使用場所・今の置き換え台数・依頼した台数・状況・団体へのコメント（substitution_consents.note。団体代表の「自団体の振り分け」に「コメント：」として出るので、総務の内部のメモには使わない）・注意
- 置き換えが入った団体ごとに、置き換え台数と了承状況（未依頼・依頼済み・了承・拒否）を表示・更新する。「依頼済み」にすると、その時点の置き換え台数を団体に見せる台数として記録する。依頼した後に置き換えが増えたら、了承を記録する前に依頼し直す。了承の後に再実行などで置き換えが増えた団体は、了承待ち（W102）として出すので、依頼し直す
- 「了承」にするとその団体の置き換え行が固定される。「拒否」にするとその団体を置き換えの対象から外し、「最小変更で再実行」が必要なことを表示する
- 総務が団体の代わりに了承・拒否を記録できる。「未依頼に戻す」は依頼済みと拒否のときだけできる（了承から未依頼に戻しても、了承で固定した置き換えの行は固定のまま残るため。了承を取り消すときは拒否を記録するか、振り分け画面で固定を外す）。操作は振り分け中だけ（ほかの状態では読み取り）。注意の列に、依頼の後に増えた・了承の後に増えた（W102）・拒否なのに置き換えが残っている（振り分け画面へのリンク）を出す。操作のたびに読み直す（行の固定と版が変わるため）
- 交換依頼一覧（Excel）を出力する

### 自団体の振り分け /my（スマホ）

- 確定前：「振り分け作業中」と申請内容（品目と数、提出日時、備考）だけ表示。キャスター机への交換を依頼されていれば、依頼の台数（「机(木) 6 台をキャスター机に交換してほしい」）と「了承する」「了承しない」ボタン（任意のコメントつき。回答は RPC で記録）。答えた後は答えと日時を出し、確定までは「回答を変える」を出す（Q4）。依頼の後に置き換えが増えていて記録できないときは「総務が依頼し直すのを待ってください」と出す
- 確定後：品目ごとの数と運び元（「机(木) 12台：1-1 から 8台、1-2 から 4台」）。代替があれば「机(木)の代わりにキャスター机」のように表示。残すは「使用場所にあるものを使う（残す）」
- 複数団体の代表なら団体を切り替える（`?group=<id>`）。振り分けの行は確定後にしか読めない（RLS）ので、確定前は読みに行かない
- フェーズ2：受け取り時刻

### マスタ設定 /settings（PC）

- 年度：作成（最新の年度からの複製。最新の年度の管理者だけができ、作った人が新しい年度の管理者になる）、申請の受付期間（受付開始の前に締切を入れる）
- 場所・品目・団体：表で追加・編集。団体は CSV 取り込み可
- 距離：建物間の距離の上書き、場所ごとの追加コスト
- ユーザー：招待（メール・ロール・団体）、ロールの変更と外す（年度の最後の管理者は外せない。終了した年度でも外せる）、招待の取り消し（未使用のものだけ。終了した年度でも）、団体代表を外す
- データの書き出し：年度データ（JSON）と振り分け表（Excel）。年度末のバックアップに使う

### ルール /rules（PC）

- 種別ごとのフォーム（団体・場所・品目は選択式）、有効／無効、メモ

### 履歴 /history（PC、管理者のみ）

- audit_logs を表・団体・日時で絞り込んで表示

### CSV取り込み（申請一覧・マスタ設定から）

- 取り込めるのは模擬店・部門・企業の3種類の Googleフォームの回答。種類ごとに列の対応表を持つ
- 模擬店フォームの団体名は「飲食模擬店を運営しますか？」の答えで2つの列に分かれるので、空でない方を使う。groups.name と aliases で対応付け、合わなかった行は一覧で示して手で対応させる
- 企業フォームは団体名が入っていない（R8 ではすべて「オプション 1」）ので、取り込み時に手で団体を選ぶ
- 同じ団体の回答が複数あるときは、タイムスタンプが一番新しいものを使い、古いものは画面に出して確認させる
- 列がずれている行（見出しのない列に値がある行）は取り込まず、一覧で示す
- 品目の列名はフォームでの表記（items.aliases）で品目に対応させる。企業以外の長机(3人掛)は長机(2人掛)に読み替える（S03）。読み替えた後は団体・品目ごとに合計して1行にする（長机(3人掛)と長机(2人掛)の両方を申請した回答で、同じ品目の行が2つにならないように）
- フォームのタイムスタンプを、その団体の提出日時（request_submissions.submitted_at）として保存する（Excel の団体別集計の「申請順」に使う）。取り込みは管理者だけの RPC で行い、DB はそのときだけ渡した日時を保つ（団体代表の提出は今までどおり DB の時刻）
- メールアドレスは、どの列にあっても（見出しのない列も含めて）パターンで見つけて捨て、保存もログ出力もしない

## DB関数とブラウザ側の処理

サーバーを持たないので、Route Handler と Server Action は使わない。読み取りと、理由の要らない書き込み（在庫入力、締切前の申請一覧のセル編集、マスタの編集）は、画面から Supabase クライアントで直接行い、RLS で守る。理由が要る書き込みと、複数の表をまとめて変える書き込み（申請の提出を含む）は DB 関数（RPC）で行う。重い計算とファイルの作成は管理者のブラウザで行う。

**DB関数（RPC）**

引数名は PL/pgSQL の列名とぶつからないよう `p_` を付ける（下の表では省略。supabase-js では `supabase.rpc('save_auto_allocations', { p_year_id, p_rows, p_mode, p_base_version })` のように呼ぶ）。

| 名前 | 呼べる人 | 動作 |
| --- | --- | --- |
| set_year_status(year_id, to, reason, base_version) | admin | 状態遷移の図に合わない遷移はエラー。requesting へは締切が未来のときだけ。confirmed へは、base_version（検証に使った版）が今の版と同じで、E001・E002・E005 がないときだけ。確定と確定の解除は理由必須。遷移のたびに版を増やす |
| update_year(year_id, patch, reason) | admin | 年度名・1日目・受付期間を変える（patch に入れたキーだけ。ほかのキーは invalid_input）。1日目は複製元（prev_year_id）より後で、この年度を複製元にした年度より前（違えば invalid_input）。1日目は 2000-01-01〜2200-12-31（infinity なども含め、範囲外は invalid_input（field: festival_start）。D-18）。requesting の間は締切を消せない。終了した年度は変えられない |
| create_year_from(prev_year_id, label, festival_start) | 複製元の年度の admin（複製元が終了していてもよい） | 複製元が最新の年度のときだけ（それを複製元にした年度も、1日目が同じか後の年度もない）。1日目は複製元より後で、2000-01-01〜2200-12-31（範囲外は invalid_input（field: festival_start））。年度を作り、団体・ルール・場所の状態を複製してルールの団体 id を付け替える。呼んだ人を新しい年度の admin にする |

| accept_my_invitations() | ログインしている人 | 自分のメール（本人のものと確かめられるときだけ。`private.verified_email`）あての未使用の招待（終了していない年度）を受け入れ、件数を返す。画面がログインのたびに呼ぶ |
| save_auto_allocations(year_id, rows, mode, base_version) | admin | 版が base_version と同じときだけ、auto かつ未固定の行を差分で入れ替える。年度の一致・E002・E005 を保存前に、在庫超過を保存後に確かめ、だめなら全体を取り消す。振り分け中のみ（確定中はエラー） |
| save_allocation_rows(year_id, changes, reason) | admin | 行の追加・変更・削除・固定。データを変えた行は origin = manual。各行の updated_at で楽観ロック。理由必須。ロックした時点の版と保存後の版を返す。振り分け中のみ（確定中はエラー） |

| check_delivery(delivery_id, status, problem_note, returned) | admin、staff | 運搬の状態・問題・返却を更新（フェーズ2）。確定中と終了後 |

**ブラウザ側の処理**

| 名前 | 置き場所 | 動作 |
| --- | --- | --- |
| allocate(input, solver) | packages/allocator | 振り分けの計算（Web Worker で実行。solver は Worker の中で1回だけ読み込んだ highs のインスタンス） |
| validate(data, rows) | packages/allocator | 検証コードの一覧を返す（data は年度のデータ、rows はその年度の全行） |
| exportAllocationXlsx({ yearLabel, data, rows }) | packages/exporter | R8 様式の Excel（data は年度のデータ、rows はその年度の全行。余り・計は exporter が計算する） |
| exportSwapsXlsx({ yearLabel, data, rows }) | packages/exporter | キャスター机交換依頼一覧（了承が要る代替の行と了承の状況） |
| exportYearJson(yearExport) | packages/exporter | 年度データの書き出し（バックアップ。メールアドレスは含めない） |
| parseFormCsv(kind, csv, items) | packages/importer | Googleフォーム回答の読み取り（品目の列は items の aliases で対応。メールアドレスを捨てる） |
| resolveResponses(parsed, groups, items, manual) | packages/importer | 読み取った回答を団体に対応させ、申請（読み替えの後、団体・品目ごとに1行）と提出（フォームのタイムスタンプ）を作る。合わない行・古い回答を返す |

- RPC は SECURITY DEFINER にして `search_path = ''` を設定し、関数の最初でロールを確かめる。次に年度の行をロックし（`for no key update`）、ロールをもう一度確かめてから状態を確かめ、入力を確かめてから理由を置いて書き込む。入力はブラウザで zod、DB では関数の中でもう一度確かめる
- エラーは `raise exception`（SQLSTATE P0001）で返し、message にコード、detail に該当する行の id などを JSON で入れる（メールアドレスは入れない）。PostgREST は HTTP 400 で `{ code: 'P0001', message, details }` を返す。コードは forbidden（ロールがない。対象が見つからないときも）、not_found、invalid_state（状態が違う、確定中に変えられない）、conflict（版・updated_at が違う、重複）、invalid_input（形や参照が違う、上限を超える）、reason_required、検証コード（E001・E002・E005・E006）。RPC の中で起きた形の誤り（jsonb の中の uuid・日付など）と CHECK 違反も invalid_input にして、生の SQLSTATE は返さない。ただし、RPC のトップレベルの型つきの引数（uuid・enum・date・integer）は PostgREST が関数の前に変換するので、形が違うと 22P02・22007 などがそのまま返る（関数の中では直せない）。画面は zod で先に確かめ、22 で始まる SQLSTATE は「入力の形が違う」として扱う。画面で日本語に直して表示する
- 楽観ロックの updated_at は、受け取った文字列をそのまま返す（Date に変換しない）
- 振り分けの行を渡す JSON は、03 の AllocationRow と同じ camelCase（sourceRoomId、groupId、itemId、requestedItemId、count、isKeep）にする
- 書き込みがデッドロック（SQLSTATE 40P01。PostgREST は HTTP 500 で返す）で失敗したときは、何も保存されていない（1リクエスト＝1トランザクション）ので、入力を残したまま「ほかの人の保存と重なりました。もう一度保存してください」と出す。HTTP 500 を一律に扱わず、エラーの code で分ける
- highs-js の wasm は振り分け画面を開いたときだけ読み込む（その画面のコンポーネントで `new Worker(new URL('…worker.ts', import.meta.url))` を作り、Worker の中で highs を読み込む）。wasm は highs の `highs/runtime`（highs の package.json の exports。`require.resolve('highs/runtime')` が build/highs.wasm を指す。`highs/package.json` は exports にないので引けない）を `apps/web/public/highs.wasm` にコピーして静的ファイルとして公開し（git には入れず .gitignore に書く）、locateFile で basePath を付けた URL（`${origin}${basePath}/highs.wasm?v=<highs の版>`）を渡す。コピーは apps/web の predev と prebuild の両方で行う（`pnpm dev` でも 404 にならないように）。basePath を付け忘れると GitHub Pages で 404 になり、`CompileError: expected magic word` で落ちる。読み込みに失敗したら、次の実行で読み直す（失敗を覚えたままにしない。読み直しの URL に回数を付け、404 のキャッシュを避ける）。Worker は1つだけ作り、画面を離れて戻っても使い回す（ログアウトで止める）。`next build --webpack` は highs.mjs の `node:module` で失敗するので使わない
- validate と Excel の作成は主スレッドで行う（R8 規模で validate は数十 ms、Excel の作成は 0.1 秒ほど）。ExcelJS を含む exporter は、出力するときに読み込む（動的 import。最初の読み込みを重くしない）
- 画面は、エラーを code（P0001 の message と details、22 で始まる SQLSTATE、42501、23505・23503・23514、40P01、PGRST301・PGRST302・PGRST303 と HTTP 401、通信の失敗）で分けて日本語にし、読み直すか・入力を残すかを決める。分け方と文言は apps/web/lib/errors.ts の1か所に置く（D-33）。details にある団体・部屋・品目・行の id は、画面が持っている名前に直して出す。JWT のエラー（PGRST301〜303・401）は、セッションの更新を1回試し、だめならその端末のセッションを消してからログインの画面へ送る（消さずに送ると、ログインの画面が「ログイン済み」としてすぐ戻すため）
- 直接の更新と削除は、変わった行を返させて確かめる。RLS で拒否された update・delete はエラーにならず 0 行で成功するので、0 行なら読み直して「ほかの人が変えた・消した」か「権限か年度の状態が変わった」かを分ける
- 通信が切れて応答が届かなかった書き込みは、自動で送り直さない。版・updated_at・一意のキーで保存されたかを読み直して確かめてから送り直す（save_allocation_rows の行の追加には冪等の鍵がなく、確かめずに送り直すと二重にできる）
