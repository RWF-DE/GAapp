# 画面とAPI

## 画面仕様

画面は[概要](00_overview.md)の画面一覧に対応する。Next.js の静的書き出し（output: 'export'）で作るため、id をパスに埋め込む動的な URL は使わず、クエリ文字列で渡す（/stock?room=…）。画面の中の切り替え（タブ・品目・団体・行・絞り込み）もクエリ文字列に入れ、再読み込みと共有で同じ表示に戻れるようにする。サーバーのデータは TanStack Query で持ち、書き込みの後に関係するものを読み直す。UI 部品は shadcn/ui（ソースを手で置く）、表は TanStack Table。すべての画面で、読み込み中・データが空・権限なしの3状態と、読み込みの失敗（もう一度読み込むボタンつき）を表示する。年度の状態で書けないときは入力欄を無効にし、理由を帯で出す（「年度が確定中のため編集できません」など）。日時は Asia/Tokyo で表示する。データの多い画面には、最後に読み込んだ日時と「読み直す」を出す。招待されていない人がログインすると「総務から招待されていません」だけを表示する。

画面は、アプリ全体の画面（ログイン・ダッシュボード・マスタ設定・履歴）と、機能ごとの画面に分かれる（D-51）。今の機能は机椅子とお知らせ（T17）と締切と予定（T18）。机椅子の画面は「机椅子の状況」から「自団体の振り分け」までと「CSV取り込み」の節、お知らせの画面は「お知らせ一覧」の節、締切と予定の画面は「締切と予定」の節。ほかの機能（T19〜）の画面の節は、その機能のチケットが足す（D-52）。

画面の出し分けは、権限の3つの段（D-48。02「権限とRLS」）に合わせる（T15b。D-50）：**管理者だけ**（admin）、**部門長以上**（管理者・総務部門長・総務副部門長＝admin・head・deputy_head）、**総務**（部門長以上と総務部門員＝staff）。閲覧のみ（viewer）と団体代表（店長・副店長）は段の外で、画面ごとに決める。画面と段の対応は「共通レイアウト」の表、画面の中の操作は各画面の節に書く。段はロールの一覧（部門長以上・総務）から作り、画面ごとにロールを並べ直さない。画面の出し分けは見た目だけで、データは RLS と RPC が守る（画面は DB より狭く出してよい。ユーザーのタブのロールの変更など）。

### 共通レイアウト（P-03）

- ログインが要る画面は共通レイアウトの中に置く。ログインしていなければ /login に送り、ログイン後に元のページへ戻す（戻り先は同じサイトのパスだけ）
- ログインのたび（ページを開いたときも）に `accept_my_invitations` を呼んでから、自分の year_roles・group_members を読む。今の年度は、既定ではロールか団体代表の行がある年度のうち1日目が最も遅いもの（最新の年度）。そうした年度が2つ以上ある人には、ヘッダーに年度の選択（1日目の新しい順。「R9（準備中）」）を出し、選んだ年度はそのタブの中でだけ覚える（新しいタブや部屋の QR から開いたときは最新の年度）。覚えた年度にロールも団体代表もなくなっていれば既定に戻す。年度は URL に入れない（部屋の QR の URL を年度によらず同じにするため。在庫入力は開いている年度に書く）。最新でない年度を開いているときは「最新でない年度（R8・終了）を表示しています」と、最新の年度に切り替えるボタンを帯で出す。在庫入力・申請・了承の回答では、最新でない年度に書く前に確かめる（D-31）
- 画面を開くまでの読み込み（D-33・D-45。スマホの 4G で 2 秒以内に開くため）：立場を読むとき（上の years）に年度の行（状態・版・受付期間）も一緒に読み、画面はそれを使って年度の行を読み直さない（自団体の振り分けだけは、振り分けの行を使うかを年度の状態で決めるので、年度の行も画面のデータと並行に毎回読み直す）。振り分けに関わらない画面（在庫入力・申請・自団体の振り分けなど）は、年度の行を待たずに画面のデータを並行に読む（書けるかは今までどおり年度の行の状態で決める。版は使わない）。振り分けに関わる画面（机椅子の状況・振り分け・キャスター机交換）は今までどおり版を先に読む。ダッシュボード（/）は版を使わない（年度の行は立場と一緒に読んだものを使い、機能ごとの軽い読み取りを並行に行う。下の「ダッシュボード」）。前に開いた年度と、その年度のロールと団体の id をそのブラウザに覚え（利用者ごと。下書きと同じく、手動のログアウトでその人の分を、別の人がログインしたときに前の人の分を消す）、次に開いたときは立場の読み込みと同時に、その年度・団体の画面のデータを読み始める（先読み）。立場が届いて開く年度・団体（ダッシュボードはロールも）が同じならそれを使い、違えば捨てる。あわせて、ページを開いたときにアプリが Supabase に送った読み取り（GET と、引数のない accept_my_invitations。URL と応答を変えるヘッダーだけで、トークンは覚えない。部屋・団体の id はページのクエリから当てはめる）をパスごとに覚え、次にそのパスを開いたときは HTML の中の小さな script が、そのブラウザのセッションのトークン（期限内のときだけ）で JS より先に同じリクエストを送り、アプリは同じリクエストの応答として受け取る（ページを開いてから 15 秒の間と、書き込みを送るまでと、覚え終えるまで〔立場が届いて 2 秒後〕と、その画面にいる間だけ。送り先はその Supabase の /rest/v1/ だけ）。先読み・記録・先送りは版を使わない画面（ダッシュボード・在庫入力・申請・自団体の振り分け）だけで行い、振り分けに関わる画面（机椅子の状況・振り分け・キャスター机交換）は記録も先送りもしない（先送りすると版とデータが同時に読まれ、版を先に読む決まりが崩れて、新しい版に古いデータを組み合わせてしまうため）。ダッシュボード（/）は版・振り分けの行を読まないので対象にする（T16。団体代表の / を 2 秒以内に開くため。D-45・D-51）。ダッシュボードの先読みは、立場の種類ごとに欄が読むもの（総務には机椅子の軽い読み取りと総務内のお知らせの新着、店長・副店長には自団体の提出と了承とお知らせの新着、閲覧のみにはお知らせの新着。下の「ダッシュボード」。お知らせは T17。締切と予定の項目〔T18〕は、団体代表の / が 4G で 2 秒以内のままであることを `pnpm e2e:perf` で確かめてから、総務・閲覧のみ・ロールのない店長・副店長に足す。「締切と予定」の「ダッシュボードに出すもの」）で、総務か・閲覧のみかは覚えたロールで決める。ダッシュボードから振り分けに関わる画面へ移ったら、残りの先送りの応答は捨てる（その画面の版の読み取りに渡さない）。先読みしたデータも、立場で開けると決まるまでは画面に出さない（読める範囲は RLS が守る）
- どの年度にもロールも団体代表もなければ「総務から招待されていません」とログアウトのボタンだけを出す（ナビゲーションも年度も出さない）
- ヘッダーに今の年度と状態、表示名と立場、ログアウト。立場は、ロールの表示名（管理者・総務部門長・総務副部門長・総務部門員・閲覧のみ。02 の列挙型の表示名）と、代表する団体ごとの「{団体名} の店長」「{団体名} の副店長」（店長・副店長の権限は同じで、表示だけが違う）。ダッシュボードの立場の一覧も同じ言い方にする。ナビゲーションは PC では左、スマホではメニューのボタンで開く。項目は見出しごとにまとめる：「ホーム」（ダッシュボード /）、機能ごとの見出し（機能の登録の順。「机椅子」：机椅子の状況・在庫入力・在庫一覧・申請一覧・ルール・振り分け・キャスター机交換・申請・自団体の振り分け、「お知らせ」：お知らせ一覧〔T17〕、「締切と予定」：締切と予定〔T18。見出しと項目が同じ名前〕）、「共通」（マスタ設定・履歴）。項目のない見出しは出さず、「ホーム」の見出しは項目が「ホーム」1つなので見た目では出さない（読み上げでは見出しとして読む）（D-51・D-52）。項目は開いている年度の立場で出し分ける（下の表。部門長以上は総務の画面すべて〔マスタ設定は段ごとのタブだけ〕、総務部門員は机椅子の状況・在庫入力・在庫一覧・申請一覧・振り分け（閲覧）、閲覧のみは振り分け（確定後の閲覧）、店長・副店長は申請・自団体の振り分け、お知らせ一覧と締切と予定は招待されている全員、兼ねた人〔管理者・閲覧のみで店長・副店長も務める人。部門長・副部門長・部門員は同じ年度の店長・副店長を兼ねられない。D-49〕は両方）。URL を直接開いたときも同じ立場で出し分ける（合わなければ権限なしの表示。閲覧のみが確定前に振り分けを開いたときは「振り分けは確定後に表示されます」と添える）。ナビゲーション・ページの守り・画面の中のリンクは、同じ画面の表（立場はロールの一覧から作る）から引く。表示の出し分けは見た目だけで、データは RLS と RPC が守る

- 印刷（部屋の QR のカード）のときはヘッダーとナビゲーションを隠す。ログアウトはその端末のセッションだけを終える（同じ人のほかの端末は抜けない）。ログアウトと利用者の切り替えでは、画面が持っているデータ（キャッシュ）を消す。保存していない入力の下書きは、手動のログアウトでは（保存していない入力があれば確かめてから）その人の分を消し、別の人がログインしたときは前の人の分を消す（共用の PC で前の人のデータを残さない）。セッションが切れて強制的にログアウトしたときは下書きを消さない（同じ人がログインし直せば戻せる）
- 権限や年度の状態が変わったと分かって立場を読み直すときは、読み直しの間も今の画面を出したままにする（入力・開いているダイアログを消さない。読み込み中の表示に置き換えるのは、最初の読み込みと利用者が変わったときだけ）
- 画面の中のリンクは、行き先の画面を開ける立場のときだけリンクにする（開けない立場には件数や文字だけを出す）。マスタ設定のタブへのリンク（`/settings?tab=…`）は、そのタブを開ける立場のときだけリンクにする（部門長・副部門長には団体・品目・距離・書き出しのタブへのリンクを出さない）
- 保存していない入力がある画面では、アプリの中で別の画面へ移る前と、年度を切り替える前に確かめる。ブラウザの戻る・タブの破棄・別のアプリへの切り替えは止められないので、入力をそのブラウザに下書きとして置き、開き直したときに戻せるようにする（保存に成功したら消す）
- 書き込みのボタンは、送っている間は押せなくする（二重に送らない）。通信が切れて保存されたか分からないときは、自動では送り直さない。読み直して決める決まりは書き込みの種類で分ける（「DB関数とブラウザ側の処理」の通信が切れたときの項）

### ログイン /login（PC・スマホ）

- 「学校の Google アカウントでログイン」のボタン。ブラウザの PKCE フローで、リダイレクト先は basePath 込みの /auth/callback/（Supabase の Redirect URLs に登録する）
- フックで拒否されたとき（学校以外のアカウント）は「学校の Google アカウントでログインしてください」と出す。URL に付いたエラーの文言はそのまま表示しない
- ローカルだけ、メール＋パスワードのテスト用ログイン（E2E 用。D-02）を出す。ビルド時のフラグがあり、Supabase の URL がローカルのときだけ出し、本番のビルドにはコードごと入れない
- ログイン状態はブラウザに保存し（supabase-js）、トークンは自動で更新する
- LINE などのアプリの中のブラウザで開いたと分かるときは、「アプリの中では Google でログインできません。Safari か Chrome で開いてください」と URL のコピーのボタンを出す（Google のボタンは隠さない）

### ダッシュボード /（PC・スマホ）

- 総務アプリのトップ（D-51）。招待されている人は全員開ける（ナビの「ホーム」の見出しの項目「ホーム」）。h1 は、総務（管理者・総務部門長・総務副部門長・総務部門員）には「ダッシュボード」、閲覧のみ・店長・副店長には「ホーム」。どの立場にも、最初に立場の一覧（今の年度・あなた・立場。`home-year`・`home-roles`。ヘッダーと同じ言い方）を出す
- 欄（ウィジェット）と立場。兼ねた人（管理者・閲覧のみで店長・副店長も務める人。部門長・副部門長・部門員は同じ年度の店長・副店長を兼ねられない。D-49）は、両方の立場の欄を出し、要対応と締切と予定は1つの欄にまとめる（同じ項目は1回だけ）。「お知らせ」の欄も1つにまとめる（同じお知らせは1回だけ）

  | 要対応の一覧 | 出す（中身は段で変わる） | 出さない | 出す（自団体の分） |

- 並び：立場の一覧 → 見出し（今の年度と状態は立場の一覧に出すので、見出しの横には出さない）→ 要対応の一覧と締切と予定（PC では横に並べ、スマホでは縦に）→ 総務内のお知らせ・お知らせ（全幅。2つとも出す人は、広い PC〔lg 以上〕で横に並べる）→ 代表する団体 → 機能ごとのカード

- 操作：＋－ボタンと数字入力（0〜10000 の整数）、「保存」（画面の下に固定）。保存は部屋の全品目（0 を含む）を1回で書く（同じ数でも数え直した記録が残る）。保存すると DB が counted_by（保存した人）と counted_at（保存した日時）を入れる（画面から送らない）。保存の直前にその部屋を読み直し、読み込んだ後にほかの人が保存していれば、その人と時刻、相手の数と自分の数を並べて「上書きする」「読み直す」を選んでもらう。通信が切れて保存の応答が届かなかったときは、入力を残して「保存できたか分かりません。もう一度「保存」を押すと、確かめてから送ります」と知らせる（確かめるためのボタンは置かない）。もう一度「保存」を押すと同じく読み直し、すでに入力と同じ数が保存されていれば送らずに「保存されていました」とする（応答が届かなかった自分の保存は、ほかの人の保存として扱わない）。数を変えた・下書きを戻した・「保存」を押した後は、保存が決まるまで、裏で読み直した行で入力を置き換えない（ほかの人が保存していれば「ほかの人が保存しました」と知らせ、ほかの人の数にするのは利用者が選んだときだけ。入力がほかの人の数と違う間は、読み込んだときの数へ戻しても保存していない入力として扱う。下書きを捨てても入力は置き換えない）。書けなくなった（読み取り専用になった）ときは、読み直した数を出し（入力は下書きに残る）、「保存できたか分かりません」の知らせ・ほかの人の保存の確かめ・振り分けの合計の確かめを閉じ、確かめの途中でも送らない（また書けるようになっても知らせは出ない。開き直して下書きを戻せば、「保存」で確かめてから送る）。「保存できたか分かりません」は、このほかは次の保存が決まるまで消さない。保存の後は「次の部屋へ」（並び順で次の、まだ数えていない保管場所）を出す。保存していない入力があるまま離れるときは確かめ、入力は下書きとして残す（カメラで次の QR を読んだ・別のアプリへ行った後に開き直しても戻せる。下書きを消すのは、保存したとき・捨てたとき・読み込んだ行に下書きの数が書かれていたときだけ。ほかの人の数を読み直しても、戻していない下書きは残す。下書きを戻さずに「保存」を押した後に保存していない入力になったとき〔ほかの人が先に保存していた・保存できたか分からない〕は、「保存」を押した入力を選んだものとして、戻していない下書きをその入力で置き換える。入力に保存していないものがなくなったときは、書く中身がないので入力の分を書かない）。開いている年度が最新でないときは、最新の年度に切り替えるボタンを大きく出し、保存の前に「最新でない年度（R8）に保存します」と確かめる
- 場所の選び方：一覧から選ぶか、部屋に貼った QR（/stock/?room=… の URL）を読む。room がないときは保管場所の一覧（建物ごと、名前で絞れる、各部屋に「数えた（日時・人）」か「まだ」と使用不可の印）を出す。room が保管場所の一覧にない（消した部屋・形が違う）ときは「この場所は見つかりません」と一覧へのリンクを出す
- 状態：年度が allocating 以降なら総務部門員は読み取り専用（「振り分けが始まったので、在庫は管理者・総務部門長・総務副部門長だけが直せます」）。部門長以上は数え直しを入力でき、入力すると検証をやり直す。振り分け中に、振り分けの合計より少なくなる品目があれば、保存の前に「保存すると振り分けに在庫超過（E001）が出ます。振り分け画面で直してください」と確かめる。確定中は、振り分けの合計より少なくなる数は保存できない（「確定を解除してから」と表示する。DB の守りと同じ条件を画面でも先に確かめる）。終了した年度は読み取り専用。使用不可の部屋は先頭に「今年は使用不可」と理由のメモを表示する（数えることはできる）
- 端末：スマホ（幅 390px）を基本にする。ボタンは 44px 以上、数字の欄では数字のキーボードを出す

### 申請 /request（スマホ）

- 表示：団体名、使用場所（なければ「校内に分散」）、締切日時（残りの日数）、その団体の区分で申請できる品目だけの入力欄（初期値は今の申請の数、なければ0）、備考欄（数には影響しないと明記）、提出の状況（「提出済み（日時）」「未提出」）。区分で申請できない品目に 0 でない申請が残っているとき（企業以外の長机(3人掛)など）は、入力欄の下に読み取り専用の行で出す（「長机(3人掛) 2台（長机(2人掛)として扱います。変えるときは総務へ）」。提出では送らない品目なので、団体代表は直せない）
- 操作：「提出」で確認（0 でない品目の一覧。すべて0なら「何も借りない申請として提出しますか」）をしてから、全品目と備考を RPC `submit_requests` で1回で保存し、submitted_at を記録する（日時は DB が入れる）。提出は毎回、送る前に自団体の申請と提出の記録を読み直す。読み直した値が入力と同じなら送らずに「提出されていました」で終え、編集を始めた後にほかの人（提出の記録は書いた人が自分でない、申請の行は数が編集を始めたときの値とも入力とも違う）が変えていれば、上書きしてよいか確かめる。自分の書いたもの（前に送って応答が届かなかった提出。提出の記録の書いた人が自分で、申請の行の更新時刻がその記録と同じ）はほかの人の変更としない。比べる元（編集を始めたとき〔編集せずに「提出」を押したときはその時〕の申請と提出の記録）で入力欄と提出の欄を出し（画面の値と比べる元を同じ時点にそろえる。送る値も同じ）、画面の裏の読み直し（通信が戻ったとき・下書きを戻した後など）では変えない。裏で届いた行に比べる元より新しいほかの人の変更があれば、入力は置き換えずに「編集を始めた後に、ほかの人がこの団体の申請を変えました。変わったもの：品目（前 → 今）、提出日時、備考」と知らせ、「ほかの人の値を読み込む」を押したときだけ、変わった品目と備考をその値にする（ほかの入れた数と書き換えた備考は残す）。知らせと読み込みで「変わった」とするのは値が変わったものだけ：品目は数が変わったもの（行が書き直されても数が同じ品目〔ほかの人の初めての提出で 0 の行が入った品目など〕は挙げず、入れた数を残す）、提出の記録は提出日時と備考を分けて変わったものだけを出す（備考を変えない出し直しでは、書き換えた備考を残す。どちらも同じ出し直しは「提出の記録」）。画面の読み込みも提出の記録の書いた人（updated_by）を読み、自分の提出（応答が届かなかったものを含む）で書かれた行と記録は知らせない。編集する前は、届いた行をそのまま出す。比べる元は下書きにも入れる（下書きを戻した後の提出も、それと比べる）。送る前の読み直しで比べる元を読み直した記録にするときは、読み直した値と同じ入力だけを外し、ほかの入力（編集を始めたときの値に戻した数・備考を含む）は残す。応答が届かず提出できたか分からないときは、入力を残して「提出できたか分かりません。もう一度「提出」を押すと、確かめてから送ります」と出す（もう一度押すと、上の読み直しで決まる。読み直しが通信できなければ送らない）。締切前なら何度でも修正できる。申請できない区分の品目は DB でも拒否する（E006。企業以外の長机(3人掛)は除く）。数は 10000 まで、備考は 2000 字まで
- 状態：準備中と受付開始の前は入力欄を無効にし、「受付の前です」「受付は {日時} からです」と表示。締切後と振り分け中以降は読み取り専用で「変更は総務へ」と表示。提出が状態のエラーで拒否されたら、年度を読み直して表示を合わせる。年度の状態が受付中のまま（端末の時計がずれていて、DB は受付期間の外と判断した）なら、読み取り専用にして「締切を過ぎました（または受付の前です）。端末の時計がずれている可能性があります」と出す（端末の時計に頼らない）。保存していない入力は下書きとして残し、離れるときは確かめる。開いている年度が最新でないときは、提出の前に確かめる。複数団体の代表なら団体を切り替える（`?group=<id>`）

### 申請一覧 /requests（PC）

- 表示：団体×品目の表（行は団体の並び順、列は品目の並び順、団体名の列を固定）と品目ごとの合計、区分フィルタ（`?category=`）、「未提出だけ」「備考ありだけ」（`?filter=`）、未提出団体の一覧、提出日時、備考がある団体に印（押すと備考を出す）。その団体の区分で申請できない品目のセルは「—」（0 でない申請が残っていれば、その数を灰色で出して印をつける。企業以外の長机(3人掛)は「長机(2人掛)として扱う」）。締切までの残り（締切後は「変更には理由が要ります」）。総務部門員は読み取りだけ（「総務部門員は申請一覧を見るだけです」）。下の操作（セルの編集・代理入力・提出済みにする・取り込み）は部門長以上。年度に団体が1つもないときは、管理者には「マスタ設定で団体を登録すると、ここに申請が並びます」とマスタ設定の団体へのリンク、ほかの人には「管理者に団体の登録を頼んでください」と出す（団体はマスタ。取り込みと同じ）
- 操作：セルを直接編集（部門長以上）。編集したセルは「未保存の変更」になり、「保存（N件）」でまとめて送る。締切前（準備中と、受付中の締切前）は直接書き込み（行ごとの updated_at で楽観ロック）、締切後（受付中の締切後と振り分け中）は理由の入力を必須にして RPC で団体ごとに保存する。保存は毎回、送る前に表を読み直す：DB がすでに入れた数のセルは送らずに「保存されていました」とし、編集した後にほかの人が変えたセル（数が編集したときの値とも入れた数とも違う）があれば、送らずに一覧を出して「上書きして保存する」か「読み直す」（読み直した値に戻して印をつける）かを確かめる（セルは書いた人を記録しないので、前に送って応答が届かなかった自分の保存の後に入れ直したセルも、数で決めて確かめる）。表を読み直したとき（「読み直す」・通信が戻ったとき・下書きを戻したとき・代理入力や取り込みの後）は入れた数を捨てない（DB が入れた数と同じになったセルだけ未保存から外す。ほかの人の変更かは保存のときの読み直しで決める）。読み直した表で、未保存のセルの数が編集したときの値とも入れた数とも違えば、入力は置き換えずに一覧で知らせ、「変わったセルを読み直した値に戻す」を押したときだけ戻して印をつける。一度入れたセルは、編集したときの数に戻しても未保存として残す（表が古いままだと DB の今の数と違うことがあるため。表の数と同じセルも未保存として色をつけ、「保存（N件）」の件数と離れるときの確かめに含める。押すと保存の前の読み直しで決まる）。「上書きして保存する」の読み直しでまた変わっていれば、送らずにダイアログを開いたまま最新の値で確かめ直す。応答が届かず保存できたか分からないときは、入力を残して「保存できたか分かりません。もう一度「保存」を押すと、確かめてから送ります」と出す（読み直しが通信できなければ送らない）。締切前の書き方が DB に拒否され、年度の状態が受付中のままなら（端末の時計のずれ）、締切後の書き方に切り替える（編集したセルは残す）。編集したセルは下書きとして残し、離れるときは確かめる。確定中と終了後は読み取り専用
- 企業・休憩所の代理入力（部門長以上）：団体の行から申請と同じ入力欄を開く。休憩所は前年度の申請の数（previous_year_requests。団体名で対応）を初期値にできる。比べる元は最初に触ったとき（数・備考を変えた・前年の数を入れた・送った）の表の行で、触る前は裏で届いた表の行をそのまま出す。触った後に裏で届いた行に比べる元より新しいほかの人の変更があれば、入力は置き換えずに知らせ、「ほかの人の値を読み込む」を押したときだけ変わった品目と備考をその値にする（申請と同じ。値が変わったものだけを挙げ、自分の提出は知らせない。表の提出の記録も書いた人を読む）。締切前は `submit_requests`、締切後は `update_requests_after_deadline` に提出を付ける（理由が必須）。保存は締切の前後とも毎回、送る直前にその団体の申請（updated_at）と提出の記録（submitted_at・備考・updated_at・書いた人）を読み直す（`submit_requests` は楽観ロックを取らないため）。読み直した値が入力と同じなら送らずに「保存されていました」で閉じる。比べる元からほかの人が変えていれば（提出の記録は書いた人が自分でない、申請の行は数が比べる元の値とも入力とも違う。自分の提出で書かれた行は除く）送らずに読み直して（読み直した値と同じ入力だけを外し、比べる元の値に戻した数を含むほかの入力は残す）、上書きしてよいか確かめる（確かめた後に送るときも読み直し、また変わっていれば確かめ直す）。応答が届かず保存できたか分からないときは入力を残して知らせ、もう一度押すと上の読み直しで決まる。分からないまま閉じるときは「保存できたか分かりません。閉じると入力は消えます（表を読み直します）」と確かめ、閉じたら表を読み直す。締切後の備考は、書き換えたときだけ送る（ほかの人が変えた備考を上書きしない）
- 提出済みにする（部門長以上）：締切前は提出の記録を直接（提出日時は DB が入れる。何かの値を送ると DB の時刻に置き換わる）、締切後は `update_requests_after_deadline` の submission で。どちらも送る前に提出の記録を読み直し、すでに提出済みの団体には書かない（書くと最初の提出日時が今に変わるため。応答が届かなかった後に押し直したときも、これで決まる）。未提出に戻す操作は出さない（D-07・D-19）
- Googleフォーム回答の取り込み（部門長以上。準備中〜振り分け中。下の「CSV取り込み」。マスタにない団体は管理者がマスタ設定で作るので、管理者でない人には「管理者に団体の登録を頼んでください」と出す）

### 振り分け /allocation（PC、中心の画面）

- 見る人：部門長以上（管理者・総務部門長・総務副部門長）は振り分け中に編集できる。総務部門員は読み取りだけ（在庫・余り・検証を含む。Excel 出力もできる。「総務部門員は振り分けを見るだけです（自動振り分け・編集・確定は管理者・総務部門長・総務副部門長が行います）。」と出す）。閲覧のみは確定後だけ、行の一覧（運び元・運び先・団体・品目・数）を見る（在庫と申請は RLS で読めないので、余り・検証・団体別の差は出さない）（Q1）
- 上部：「自動振り分け」「最小変更で再実行」「確定」（確定中は「確定を解除」と、管理者にだけ「終了」。机椅子の状況と同じ部品）「Excel出力」ボタン、年度ステータス、最終実行日時、最後に読み込んだ日時と「読み直す」。ほかの人が版を進めたら帯で知らせる（机椅子の状況の版の見張りと同じ）
- 左：品目タブ（R8 のシートと同じ並び。机(木)と不可机、椅子(木)と不可椅子はそれぞれ1つのタブ。ほかの品目は後ろに品目の並び順）。各タブは運び元ごとにまとめた表（運び先〔残すは「残す」〕、団体、品目〔2品目のタブだけ〕、申請品目〔品目と違うときだけ。列にせず、品目のセル〔品目の列がなければ団体のセル〕の2行目に「…の代わり」と出す〕、数、備考、自動／手動、固定）＋場所ごとの余り（在庫から、その部屋のその品目の行の合計を引いたもの。マイナスは E001 の印。使用不可の部屋は「使用不可（在庫 n）」で余りに数えない）。`?view=item&tab=<品目コード>`、`?row=<id>` でその行のタブを開き、行を目立たせる

- 行の操作：追加・数の変更（1〜10000。0 にするときは削除）・運び元の変更・備考・削除・固定。手で変えた行は origin = manual（備考だけの変更も manual。固定だけなら origin は変えない）。自動の行に備考を書くと、その行は次の自動振り分け・最小変更で変わらなくなることを、備考の入力のところに出す。変更はすぐに送らず「未保存の変更」として画面に溜め、「保存」で理由（必須）を入れて1回の RPC で送る（1回に 1000 件まで）。保存は RPC で、他の人が先に変えていたら読み直す（ぶつからなかった未保存の変更は当て直し、当て直せなかったものは一覧で知らせる）。保存の返り値の版は、ロックした時点の版（allocation_version_before）が自分の持つ版と同じときだけ覚え直し、違えば読み直す。行の追加は、団体 → 申請品目 → 品目（ルールでその団体に許される代替先。ほかの品目は「ルール外（E004 になります）」と添える）→ 運び元（余りを添える）→ 数 → 固定するか、の順に選ぶ。未保存の変更があるうちは、自動振り分け・確定・Excel 出力を押せず、画面を離れるときは確かめる（未保存の変更は下書きとしても残し、開き直したときに当て直す）。保存の応答が届かず保存されたか分からないときは、そのまま送り直さず（行の追加が二重になるため）、版を読み直して、進んでいれば読み直した行と突き合わせ、保存されていたかを確かめてから知らせる。版も読めず確かめられない間は、保存に加えて、未保存の変更を変える操作（行の編集・追加・「取り消す」）も押せなくし、「確かめる」を押すよう知らせる（確かめるのは送った時点の変更なので、その間の変更が知らせなく消えたり戻ったりしないように）
- 部屋の見出しから、その部屋を今年は使用不可にできる（部門長以上・振り分け中。マスタ設定の「今年の使用」と同じ）。使用不可にする前に、その部屋からの固定・手動の行を一覧にし、先に直して保存してもらう（固定の自動の行は固定を外す・運び元を変える・削除、手動の行は運び元を変える・削除。手動の行は固定を外しても再実行で動かない）。一覧が空になり、保存していない変更がなくなってから使用不可にする。順番を逆にすると、使用不可の部屋の行には運び元の変更と削除しか保存できず（固定を外すだけの変更も E002 で拒否される）、その行は検証の E002（error）として残って確定できないため（自動振り分け・最小変更で再実行は、固定・手動の行の E002 では止まらない。下の precheck）。すでに使用不可の部屋の行は、運び元を変えるか削除するだけにする（固定を外すには、先に部屋を使用可に戻す）。マスタ設定から振り分け中の年度の部屋を使用不可にするときも、その部屋からの固定・手動の行があれば振り分け画面へ案内する
- 「自動振り分け」：実行前に「自動の行 N 件を置き換えます。固定・手動の行は残ります」と確認。計算は Web Worker で行い、その間は画面をロック（段階〔計算エンジンの読み込み・組み立て・計算・保存・読み直し〕と経過秒数を出す。計算エンジンの読み込み・組み立て・計算の段階では、10 秒を過ぎたら「中止」を出す。保存を送った後は中止できず、結果を待つ。中止の後は版を読み直す）。計算エンジン（highs の wasm）は、部門長以上が振り分け中にこの画面を開いたときに読み込み始める（読み込み中は「計算エンジンを読み込み中」と出し、終わるまで実行できない）。結果が ok: false のときは振り分けを書き換えず、reason ごとに見出しを変えて出す（下）。入力を組み立てたときの版を保存の RPC に渡し、計算中に他の人が振り分け・了承・在庫・申請・ルールなどを変えていたら「他の人が変更しました」と出して読み直す（自動ではやり直さない）。計算の時間を結果に出す
  - invalid_input：「入力に誤りがあります」。inputErrors（項目とルールのコード）の一覧
  - precheck：「振り分けの前に直すものがあります」。issues（E001・E002・E005）の一覧。クリックで該当の行・ルールへ移動。precheck の E002 は、残すのルール（S08）の部屋が使用不可のときだけ出る（ルールを直す。ルールへ移動）。使用不可の部屋からの固定・手動の行は precheck では止めず、保存の後の検証の E002（error）として出て確定を止める（[振り分けの仕様](03_allocation.md)）。検証の一覧のその E002 の項目には、行ごとに運び元を変える・行を削除する操作だけを添える（固定を外すだけでは直らない〔使用不可の部屋の行は、固定だけの変更も E002 で拒否される〕ので出さない。固定を外したいときは部屋を使用可に戻してから）

  - solver_error：「計算できませんでした」。message（計算エンジンの読み込みの失敗か、計算中のエラーか）。読み込みの失敗なら、もう一度実行すると読み直す
- 申請できない品目の申請（E006）を除いて計算したときは、結果の上に「申請できない品目の申請 N 件を除いて計算しました」と出し、検証の E006 を示す
- 「確定」：error 0 件で、入力の誤り（設定の壊れたルール、消した団体・場所を参照したままのルールなど）がないときだけ押せる。理由の入力が必須。検証に使った版を一緒に送り、その後に何かが変わっていれば確定せずに読み直す（机椅子の状況の確定ボタンと同じ）。確定後は編集不可（編集のボタンを隠し、「確定中です。直すときは確定を解除してください」と出す。years に確定の日時の列がないので日時は出さない）。「確定を解除」は理由入力必須

### マスタ設定 /settings（PC）

- 開ける人は部門長以上。タブで切り替える（`?tab=years|rooms|items|groups|distance|users|export`）。タブは段で出し分ける（D-50）：管理者はすべて、総務部門長・総務副部門長は年度・場所・ユーザーだけ（品目・団体・距離・書き出しのタブは出さない）。`?tab=` が知らない値か、開けないタブ（部門長・副部門長の groups など）なら、開けるタブの最初（年度）を出す。終了した年度では、ロールを外す、店長・副店長を外す、招待の取り消し、新しい年度の作成のほかは読み取り専用（年度末に終了してから翌年の年度を作るため。部門長・副部門長に残るのは、総務部門員のロールを外す、店長・副店長を外す、招待の取り消しだけで、上の帯もその文にする）。削除は、実際に消えたことを確かめてから「削除しました」と出す（権限や年度の状態が変わって消えなかったときは、読み直して知らせる）。建物・表示名・備考などの任意の欄は、空欄なら「なし」として保存する
- 年度：作成（最新の年度からの複製。最新の年度の管理者だけができ〔その年度が終了していてもよい〕、作った人が新しい年度の管理者になる。年度名は空にできず、1日目は複製元の1日目より後）、申請の受付期間（受付開始の前に締切を入れる）。年度名・1日目・受付期間の変更（1日目は 2000-01-01〜2200-12-31 で、前の年度より後・次の年度より前。受付中は締切を空にできない）。作るときは、複製されるもの（団体・ルール・使用不可の設定）とされないもの（在庫・申請・振り分け・了承・ほかの人のロール・招待）を画面に書く。作った後は、付け替えられずに無効になったルールの数とルール画面へのリンクを出し、新しい年度に切り替える。部門長・副部門長が変えられるのは受付期間（受付開始・締切）だけで、年度名と1日目は入力欄でなく文字で出し、「管理者が変えます」と添える（書ける欄と見分けられるように。`update_year` が、管理者でない人の受付期間以外のキーを forbidden にする）。部門長・副部門長には作成の欄を出さない（「新しい年度は、最新の年度（R9）の管理者が作ります」と知らせる）
- 場所・品目・団体：表で追加・編集。団体は CSV 取り込み可。場所・品目は全年度に効くことを書く（開いている年度の管理者が直せる）。品目のコードは作った後に変えない（ルールがコードで参照するため）。場所の今年の使用（使用不可と理由のメモ）は年度ごとで、部門長以上が変えられる。部門長・副部門長の場所のタブは、場所の一覧を読み取りで出し（追加・編集・削除のボタンを出さない。開いている年度のどれかの管理者でもあれば D-01 のとおり直せる）、変えられるのは今年の使用だけ。説明も、場所の追加・編集・削除は管理者が行い、今年の使用は各行の「変える」から変えられることだけを書く（建物の入れ方は直せる人に出す）。使われている場所（在庫・振り分け・団体の使用場所・どれかの年度の今年の使用）は消せない。振り分け中の年度で場所を使用不可にするとき、その場所からの固定・手動の行があれば、振り分け画面の部屋の見出しから行う（先に行を直すため）。団体を消すと申請・振り分け・団体代表・招待も消えることを確かめる。団体・場所を参照している有効なルールがあれば、削除の確認にそのコードを出し、先にルール画面で無効にするか参照を直すまで削除できない（ルールの団体・場所の参照には外部キーがなく、消すと参照の切れたルールが残って検証ができなくなるため。無効のルールの参照は件数だけ添える）。団体名は Excel の集計に使える名前だけ（D-27。年度の中の重複を含めて保存の前に確かめる）。団体の CSV は見出し `団体名,表示名,区分,飲食,使用場所,別名,並び順` で、プレビュー（追加・変更・変わらない・エラーの件数と行）の後に1回で保存する（削除はしない）

- データの書き出し（管理者）：年度データ（JSON。無効なルール・メモ・別名・備考を含む。メールアドレスは含めない）と振り分け表（Excel）。年度末のバックアップに使う

### ルール /rules（PC）

- 種別ごとのフォーム（団体・場所・品目は選択式。団体・場所は id、品目はコードで保存）、有効／無効、メモ。保存の前と有効にする前に、params の形と、参照・ほかの有効なルールとの重なりを確かめ（packages/shared の ruleRowSchema・checkRuleRefs）、エラーを欄の下に出す。「残す」の部屋が今年使用不可なら、場所の欄の下に知らせる（保存は止めない。場所の使用はマスタ設定で年度ごとに変えるため）。「残す」で選んだ団体に使用場所がなければ、管理者には「マスタ設定で団体の使用場所を決めてください」、ほかの人には「管理者に団体の使用場所の登録を頼んでください」と出す（団体はマスタ。D-50）。編集で何も変えていなければ、保存を押しても確かめるだけで送らない（update で振り分けの版を上げない）
- R8 の初期ルール（S01〜S08）のひな形から追加できる（まだないコードだけ。団体・場所が要るものは選んでもらう）
- 削除はしない。使わなくなったルールは無効にしてメモに理由を書く（無効のルールも次の年度に引き継がれる）
- 振り分け中は「ルールを変えると、振り分け画面で再実行が要ります」と出す。確定中は「確定を解除してから変えてください」とし、メモだけ直せる（確定中にルールを変えると、公開中の振り分けの検証が黙って変わるため。DB は書き込みを許すが画面で止める）。終了した年度はメモだけ直せる

### CSV取り込み（申請一覧・マスタ設定から）

- 取り込めるのは模擬店・部門・企業の3種類の Googleフォームの回答。種類ごとに列の対応表を持つ
- 模擬店フォームの団体名は「飲食模擬店を運営しますか？」の答えで2つの列に分かれるので、空でない方を使う。groups.name と aliases で対応付け、合わなかった行は一覧で示して手で対応させる
- 企業フォームは団体名が入っていない（R8 ではすべて「オプション 1」）ので、取り込み時に手で団体を選ぶ
- 同じ団体の回答が複数あるときは、タイムスタンプが一番新しいものを使い、古いものは画面に出して確認させる。一番新しい回答が取り込まない行（列のずれ・数が読めない）になっているとき（取り込まない行のうち、タイムスタンプと団体名が読めて団体名がその団体だけに当たり、読めた回答より新しいものがあるとき）は、その団体を自動では取り込まず、プレビューに「新しい回答が読めない」団体として行番号・日時・理由を出し、既定では上書きしない（取り込む人が選べば、読めた回答のうち一番新しいもので上書きする）。タイムスタンプか団体名が読めない行は、取り込まない行に出すだけ
- 列がずれている行（見出しのない列に値がある行）は取り込まず、一覧で示す
- 品目の列名はフォームでの表記（items.aliases）で品目に対応させる。企業以外の長机(3人掛)は長机(2人掛)に読み替える（S03）。読み替えた後は団体・品目ごとに合計して1行にする（長机(3人掛)と長机(2人掛)の両方を申請した回答で、同じ品目の行が2つにならないように）
- フォームのタイムスタンプを、その団体の提出日時（request_submissions.submitted_at）として保存する（Excel の団体別集計の「申請順」に使う）。取り込みは部門長以上だけの RPC（`update_requests_after_deadline`）で行い、DB はそのときだけ渡した日時を保つ（団体代表の提出は今までどおり DB の時刻）
- メールアドレスは、どの列にあっても（見出しのない列も含めて）パターンで見つけて捨て、保存もログ出力もしない
- 文字コードは UTF-8 を先に試し、読めなければ Shift_JIS で読む（Excel で保存し直した CSV のため）。どちらでも読めなければ、その旨だけを出す
- 流れ：種類とファイルを選ぶ → 読み取り → その種類の区分の団体に対応させる → プレビュー（回答・対応した・対応しない・取り込まない・古い回答の件数、対応しない行を手で団体に対応させる欄、団体ごとの CSV の数と今の数と提出日時の比較、長机の読み替えの印、新しい回答が読めない団体）→ 理由を確かめて保存。取り込まない行は、行番号と理由だけを出す（中身は出さない。新しい回答が読めない団体には、その行の日時も添える）
- 保存は団体ごとに `update_requests_after_deadline`（締切の前後によらない。提出日時を残すため）で、その団体の申請全体を送る（CSV にない品目は 0）。申請できない品目（E006）は送らず、団体ごとに印を出す（送るとその団体の全部が拒否されるため）。団体ごとに成否を出し、終わったら申請一覧を読み直す
- 団体ごとに送る直前に提出の記録（提出日時・備考・updated_at）を読み直し、プレビューを作った後に変わっていた団体は送らない（行の楽観ロックは requests の行にしかかからず、数を変えない出し直し・備考だけの変更・「提出済みにする」では行の updated_at が変わらないため。2.3）。結果には「取り込みの前に、ほかの人がこの団体の申請を変えました」と出し、読み直した表で取り込み直すと Q2 の既定で決め直す
- 上書きの既定は「CSV のタイムスタンプがアプリの提出日時より新しい団体だけ」にし、取り込む人が団体ごとに選び直せる（Q2）。同じ時刻の団体（同じ CSV を取り込み直したとき）は「同じ時刻（取り込み済み）」と出し、既定では上書きしない。新しい回答が読めない団体も、既定では上書きしない
- プレビューの数は取り込んだ後の数を出す（申請できない品目で送らないものは、今の数のまま「変えない」と出す）
- 備考が 2000 字を超える回答は、プレビューで示し、2000 字に切って保存する（超えたまま送るとその団体の全部が拒否されるため）。切った団体は結果にも出す
- 理由の既定は「Googleフォームの回答の取り込み（{種類}）」（編集できる）。ファイル名は入れない（理由は履歴に残り続け、ファイル名には人の名前が入りうるため）
- ファイルの中身は画面の中にだけ持ち、閉じたら消す（保存もログ出力もしない）
- マスタ設定の団体の CSV は別の形（「マスタ設定」）

### お知らせ一覧 /notices（PC・スマホ）

- お知らせの機能（T17。D-53）の入口（ナビの見出し「お知らせ」の項目「お知らせ一覧」）。開ける人は招待されている全員（総務・閲覧のみ・店長・副店長）。h1 は「お知らせ一覧」。表と読める人は [データ設計](02_data.md) の「お知らせ」と「お知らせの権限」、書き込みは下の DB 関数 save_notice・delete_notice
- 読むもの：開いている年度のお知らせ（題名・本文・宛先・ピン留め・書いた人と日時・直した日時）と宛先の団体の行、その年度の団体の名前。総務には書いた人の表示名（profiles）も。どれも RLS が返したものをそのまま出し、画面では宛先で絞らない（総務の絞り込みを除く）：総務はその年度の全部、閲覧のみは団体あて（全団体・指定の団体。総務内は出ない）、店長・副店長は全団体あてと自団体を宛先に含む指定の団体あて。件数の上限は設けない（v1。全部読む）。最後に読み込んだ日時と「読み直す」を出す
- 並び：ピン留めのものを先に、その中と残りはそれぞれ出した日時（created_at）の新しい順（同じなら id の順）
- 1件に出すもの：
  - ピン留めの印「ピン留め」（ピン留めのものだけ）と、宛先の印「総務内」「全団体」「指定の団体」
  - 指定の団体あては、宛先の団体の名前（読めた行の団体を、団体の並び〔sort_order → 名前 → id〕で「・」でつなぐ）。店長・副店長には自団体の行しか読めないので、自団体の名前だけが出る（ほかにどの団体へ出したかは出ない）。宛先の団体が団体の削除で 0 になったお知らせは「宛先の団体がありません」を注意の色で出す（DB は変えない。読めるのは総務と閲覧のみ）
  - 題名と本文。本文は書いたとおりの文字で出す（改行を残し、長い語も折り返す。リンクにしない・HTML として読まない）。空なら出さない
  - 出した日時（Asia/Tokyo）。直していれば（updated_at が created_at より後）「（{日時} に更新）」を添える
  - 書いた人の表示名は総務にだけ出す（読めない・記録がない〔アカウントが消えた・アプリの外で入れた〕ときは「名前を表示できません」）。閲覧のみ・店長・副店長は profiles を読めないので、書いた人を出さない
- 形：広い PC（lg 以上）は表のような並び（列：宛先・題名と本文・書いた人と日時・操作。列の見出しの行つき）、それより狭い幅（スマホと、左のナビの分だけ狭い md）は1件ずつ縦に重ねる（印・題名・本文・書いた人と日時・操作の順）。1つの一覧を幅で並べ替える（同じお知らせを2回描かない）
- 絞り込み（総務だけ）：宛先で「すべて」「総務内」「全団体」「指定の団体」（それぞれ件数つき）。URL の `?audience=soumu|all_groups|groups`（知らない値は「すべて」）。閲覧のみ・店長・副店長には出さない。絞り込んで 0 件なら「この宛先のお知らせはありません」
- `?notice={お知らせの id}`（ダッシュボードの欄から来る）：そのお知らせを目立たせ、見える所に送る（絞り込みより優先し、絞り込みは「すべて」にする）。読めない・ないお知らせなら何もしない
- 書く（総務。終了した年度を除く）：見出しの横の「お知らせを書く」でダイアログ（見出し「お知らせを書く」、ボタン「出す」）を開く
  - 宛先：部門長以上は「総務内」「全団体」「指定の団体」から選ぶ（既定は総務内。それぞれに読める人の説明：総務内は「総務だけが読みます」、全団体は「すべての団体の店長・副店長と、閲覧のみの人が読みます」、指定の団体は「選んだ団体の店長・副店長と、閲覧のみの人が読みます」）。総務部門員は総務内だけなので、選ぶ欄を出さずに「総務内（総務部門員が出せるのは総務内のお知らせだけです）」と出す
  - 宛先の団体（宛先が指定の団体のときだけ）：その年度の団体を区分ごとに並べたチェックの一覧（団体の並び。名前と別名で探せる）。選んだ数「{N} 団体を選んでいます」と「選択を外す」。1つ以上
  - 題名（必須。前後の空白を除いて 1〜100 字）と本文（任意。4000 字まで。空白だけなら空として送る）。字数は文字（Unicode のコードポイント）で数え、DB の length と同じにする。題名から除く空白は zod の trim（JavaScript の trim）で、DB と同じ 25 文字（02 の notices）。入れた字数を「{n}/100」「{n}/4000」と出す
  - ピン留めする（部門長以上だけに出す。既定は外す。「一覧とダッシュボードの欄の先頭に出します」）
  - 「出す」で save_notice（notice_id なし）を呼ぶ。成功したら「お知らせ「{題名}」を出しました」と閉じ、一覧とダッシュボードのお知らせの欄を読み直す
- 編集・削除（総務。終了した年度を除く）：部門長以上はどのお知らせにも「編集」「削除」を出す。総務部門員は、自分が書いた総務内のお知らせに「編集」、自分が書いたお知らせに「削除」を出す（DB は、総務部門員が自分の書いた団体あてのお知らせを総務内に変えて直すことも許すが、画面では出さない。画面は DB より狭く出してよい）
  - 「編集」：同じダイアログ（見出し「お知らせを編集」、ボタン「保存」）を今の値で開く。総務部門員は宛先を変えられず（総務内のまま）、ピン留めの欄を出さない（ピン留めされていれば「ピン留めされています（付け外しは部門長以上）」と出し、今の値のまま送る）。総務部門員の「今の値」（宛先とピン留め）は入力の元の行（開いたときの行。conflict の後は読み直した行）の値で、下書きを戻しても宛先とピン留めは戻さない（戻すのは題名と本文。下書きの値は古いことがある）。保存は全部の欄を送り（本文を空にするときは本文を送らない。DB が空にする）、base_updated_at に読んだときの updated_at の文字列をそのまま渡す。何も変えていなければ送らずに「変更はありません」で閉じる。成功したら「「{題名}」を保存しました」
  - 「削除」：確かめのダイアログ（「「{題名}」を削除しますか」「宛先の人もこのお知らせを読めなくなります。元に戻せません。」「削除する」）。delete_notice に読んだときの updated_at を渡す。成功したら「「{題名}」を削除しました」
- 保存していない入力：ダイアログに入力があれば、閉じる前（「保存していない入力を捨てますか」）・アプリの中で移る前・年度を切り替える前に確かめる。入力はそのブラウザに下書きとして置き（作るときと、お知らせごと。直すときは読んだときの updated_at も一緒に）、同じダイアログを開き直したときに戻す（保存に成功したら消す）。戻した下書きは下書きの updated_at で送るので、間にほかの人が変えていれば conflict になる（下の conflict の扱い）
- 書けないとき：終了した年度では「お知らせを書く」「編集」「削除」を出さず、総務には「終了した年度のため、お知らせは読むだけです」の帯を出す。閲覧のみ・店長・副店長には書くためのもの（ボタン・帯）を何も出さない
- エラー（apps/web/lib/errors.ts。下の DB 関数 save_notice・delete_notice のエラーの順）：
  - 入力の誤り（invalid_input）は欄の下に出す：題名（「題名は、前後の空白を除いて 1〜100 字にしてください」）、本文（「本文は 4000 字までです」）、宛先の団体（団体が 0：「宛先の団体を1つ以上選んでください」、多すぎる：「宛先の団体は 1000 までです」、重なり：「同じ団体が重なっています」、その年度にない団体：「選んだ団体の中に、この年度にない団体があります（消された可能性があります）。団体を読み直しました」〔団体を読み直す〕、総務内・全団体に団体を渡した：「総務内・全団体のお知らせには団体を選べません」）
  - conflict（ほかの人が先に変えた）：そのお知らせを1回読み直し、中身が入力と同じなら「保存されていました」として閉じる。違えば入力を残したまま、ダイアログに「ほかの人がこのお知らせを先に変えました。読み直しました。入力は残してあります。確かめてから、もう一度「保存」を押してください（押すと、この入力で上書きします）」と、読み直した今の題名と更新の日時を出し、一覧も読み直す。次の保存は読み直した updated_at で送る（(B1)）。総務部門員の次の保存は、読み直した行の宛先とピン留めで送る（上の「編集」）。読み直したお知らせが総務部門員の編集できないもの（宛先が総務内でなくなった）になっていれば、「保存」を押せなくし、「ほかの人がこのお知らせを先に変えました。読み直しました。総務部門員が編集できるのは、自分が書いた総務内のお知らせだけなので、このお知らせは保存できません。入力は残してあります。必要なら写してから閉じてください」と、今の題名・宛先・更新の日時を出す（黙って総務内に戻さない）
  - 直すときに forbidden が返ったとき：save_notice はピン留めを変える確かめ（forbidden）を楽観ロック（conflict）より先に行うので、部門長以上が間にピン留めを付け外ししたお知らせを総務部門員が保存すると forbidden になる。そのお知らせを1回読み直し、版が進んでいれば上の conflict と同じに扱う（中身が入力と同じなら「保存されていました」）。版が同じ・読み直せない・ない（総務のまま消えたお知らせなら not_found が返るので、ないのは総務でなくなって読めないとき）ときは、下の forbidden の扱い
  - 直す間にお知らせが消えた（読み直してもない。not_found）：「このお知らせは見つかりません（ほかの人が削除した可能性があります）」と出し、「保存」を押せなくする（入力は残すので、写してから閉じられる）。一覧を読み直す
  - 削除で forbidden が返ったとき（delete_notice は、ないお知らせにも forbidden を返す）：そのお知らせを読み直し、なければ「すでに削除されていました（ほかの人が削除した可能性があります）」として一覧を読み直す。あれば今の forbidden の扱い。消せたか分からなかった（下の通信の失敗で決められなかった）後に、同じ確かめのダイアログでもう一度「削除する」を押して、読み直すとなかったときは「「{題名}」は削除されていました」とする（前の削除が通っていた可能性があるので、「ほかの人が削除した」とは言わない）
  - forbidden・invalid_state（立場や年度の状態が変わった）：年度の行と立場を読み直し、書けない形に切り替える（入力と開いているダイアログは残す）。文言は lib/errors.ts の今のもの（「権限がありません。立場が変わった可能性があります」「年度が「終了」のため、この操作はできません」）
  - 通信が切れて応答が届かないとき（下の「ブラウザ側の処理」の通信の失敗）：編集・削除は (B1)（そのお知らせを1回読み直し、編集は中身が入力と同じなら、削除は消えていれば、成功と同じに扱う。決められなければ入力を残して「保存できたか分かりません。もう一度「保存」を押すと、確かめてから送ります」〔削除は「削除」〕）。出すは (B2)：自分が出したその年度の最近のお知らせを読み直し、同じ中身で、ダイアログを開いたときの一覧になかったものがあれば「お知らせ「{題名}」は出されていました」として閉じる。なければ入力を残し、もう一度「出す」を押せる。読み直せなければ「出せたか確かめられません。通信が戻ったら「確かめる」を押してください」と出し、確かめるまで「出す」の代わりに「確かめる」を出す
- 読み込み中・読み込みの失敗（もう一度）・空（「お知らせはまだありません」。書ける総務には「「お知らせを書く」から出せます」を添える）の表示はほかの画面と同じ部品を使う

- 空の表示：既定で 0 件なら「これからの締切と予定はありません」（登録できる部門長以上には「「締切・予定を登録」から足せます」を添える）、過去も表示して 0 件なら「締切と予定はまだありません」、絞り込んで 0 件なら「条件に合う締切と予定はありません」
- 日付の出し方（ダッシュボードの「締切と予定」の欄と同じ決め方。Asia/Tokyo で決め、端末のタイムゾーンによらない）：
  - 日付には曜日を付ける（「10/16（土）」「9/30（木）17:00」）。年が今年（Asia/Tokyo）と違えば年も付ける（「2028/1/5（水）」）。終日の項目は日付だけ（時刻を出さない）
  - 相対の言い方は、Asia/Tokyo の暦の日付の差で決める（時刻の差を 24 時間で割らない。Asia/Tokyo には夏時間がないので、日付の差は暦の差と同じ）。締切：期限（終わりがあれば終わり、なければ開始）を過ぎていれば「締切を過ぎました」（時刻のあるものは期限の時刻から、日付だけのものは期限の日の翌日から）。過ぎていなければ、期限の日が今日なら「今日」、明日なら「明日」、それより後なら「あと N 日」。予定：開始の日が明日なら「明日」、それより後なら「あと N 日」、開始の日から最後の日までの間（今日のうちに終わったものも）なら「今日」、最後の日を過ぎていれば「N 日前」（N は最後の日から今日までの日数）。日の見出しも同じ決め方（その日の予定として）
- 登録・編集・削除（部門長以上。終了した年度を除く。総務部門員・閲覧のみ・店長・副店長には書くためのもの〔ボタン・帯〕を何も出さない。DB の権限と同じ：02「予定と締切の権限」）：
  - 見出しの横の「締切・予定を登録」でダイアログ（見出し「締切・予定を登録」、ボタン「登録」）を開く。項目ごとに「編集」（見出し「締切・予定を編集」、ボタン「保存」。今の値で開く）と「削除」を出す
  - 欄：種類（「締切」「予定」。既定は予定）、対象（「総務」「団体」「全員」。既定は総務。それぞれ読む人の説明：総務は「総務だけが見ます」、団体は「団体の店長・副店長に向けた項目です。総務と閲覧のみの人も見ます」、全員は「全員に向けた項目です。総務・閲覧のみの人と、団体の店長・副店長が見ます」）、題名（必須。前後の空白を除いて 1〜100 字。「{n}/100」）、終日（チェック。既定は外す）、日付と時刻（終日なら「日付」〔必須〕と「最後の日」〔任意。2日以上のとき〕、終日でなければ「開始」〔日時。必須〕と「終わり」〔日時。任意〕。日時は Asia/Tokyo として読む）、メモ（任意。1000 字まで。「{n}/1000」）。締切にも終わりを入れられる（期限は終わり。D-54）
  - 終日を切り替えたとき：入れると、開始・終わりの日時の日付を「日付」「最後の日」に入れる（同じ日なら最後の日は空）。外すと、日付の 09:00 を「開始」に入れ、「終わり」は空にする
  - 送る前の確かめ（zod。DB の CHECK と同じ）：題名は zod の trim（JavaScript の trim。DB の CHECK と同じ 25 文字を除く）の後に 1〜100 字。メモは前後の空白を除き、空なら null、1000 字まで（字数はどちらも Unicode のコードポイントで数え、DB の length と同じにする）。最後の日・終わりは開始より前にしない（同じはよい）。日付は 2000年1月1日〜2200年12月31日（Asia/Tokyo）。誤りは欄の下に出す（「題名を入れてください」「題名は 100 字までです」「メモは 1000 字までです」「日付を入れてください」「開始の日時を入れてください」「最後の日は、開始の日と同じか後にしてください」「終わりは、開始と同じか後にしてください」「2000年1月1日〜2200年12月31日の日付にしてください」）

  - 「登録」：ダイアログを開いたときに画面が作った id（uuid）で insert し、行を返させる。応答が届かずにもう一度押しても同じ id で送る（下書きにも id を置く。送り直しは主キーの重複〔23505〕で止まり、二重にならない。(B1)）。成功したら「「{題名}」を登録しました」と閉じ、一覧とダッシュボードの締切と予定を読み直す
  - 「保存」：全部の欄を、読んだときの updated_at の文字列のまま条件に入れて update し（`update … where id = … and updated_at = …`）、変わった行を返させる。何も変えていなければ送らずに「変更はありません」で閉じる。成功したら「「{題名}」を保存しました」
  - 「削除」：確かめのダイアログ（「「{題名}」を削除しますか」「この項目は、一覧とダッシュボードの締切と予定から消えます。元に戻せません。」「削除する」）。読んだときの updated_at を条件に入れて delete し、消えた行を受け取る。成功したら「「{題名}」を削除しました」
- 保存していない入力：ダイアログに入力があれば、閉じる前（「保存していない入力を捨てますか」）・アプリの中で移る前・年度を切り替える前に確かめる。入力はそのブラウザに下書きとして置き（登録はダイアログで作った id も、編集は項目ごとに読んだときの updated_at も一緒に）、同じダイアログを開き直したときに戻す（保存に成功したら消す）。戻した下書きの編集は下書きの updated_at で送るので、間にほかの人が変えていれば下の conflict になる
- 書けないとき：終了した年度では「締切・予定を登録」「編集」「削除」を出さず、部門長以上には「終了した年度のため、締切と予定は読むだけです」の帯を出す
- エラーと読み直し（下の「ブラウザ側の処理」の直接の更新と削除、(B1)）：
  - 保存（編集）が 0 行で、読み直すと版が違う（conflict）：中身が入力と同じなら「保存されていました」として閉じる。違えば入力を残したまま、ダイアログに「ほかの人がこの項目を先に変えました。読み直しました。入力は残してあります。確かめてから、もう一度「保存」を押してください（押すと、この入力で上書きします）」と、読み直した今の題名と更新の日時を出し、一覧も読み直す。次の保存は読み直した updated_at で送る
  - 読み直すとない（not_found）：「この項目は見つかりません（ほかの人が削除した可能性があります）」と出し、「保存」を押せなくする（入力は残すので、写してから閉じられる）。一覧を読み直す
  - 0 行で版が同じ・insert が 42501（forbidden。権限か年度の状態が変わった）：年度の行と立場を読み直し、書けない形に切り替える（入力と開いているダイアログは残し、送るボタンを押せなくして横に「今の立場・年度の状態では保存できません」。文言は lib/errors.ts の今のもの〔「権限がありません。立場が変わった可能性があります」など〕）
  - 登録で同じ id がすでにある（23505。前の送信が通っていた）：その id の項目を読み直し、中身が入力と同じなら「「{題名}」は登録されていました」として閉じる。違えば（間にほかの人が直した）、読み直した項目の編集に切り替えて入力を残し、上の conflict と同じ知らせを出す
  - 削除が 0 行：読み直すとない→「すでに削除されていました（ほかの人が削除した可能性があります）」、版が違う→「ほかの人がこの項目を先に変えました。読み直しました。内容を確かめてから、もう一度削除してください」、版が同じ→上の forbidden と同じ。どれも一覧を読み直す
  - 通信が切れて応答が届かないとき（(B1)）：その項目を1回読み直し、登録・保存は中身が入力と同じなら、削除は消えていれば、成功と同じに扱う（「「{題名}」は登録されていました」「保存されていました」「「{題名}」を削除しました」）。決められなければ入力を残して「保存できたか分かりません。もう一度「保存」を押すと、確かめてから送ります」（登録は「登録」、削除は「削除」）。もう一度押すと同じ id・同じ updated_at でふつうに送る（前の送信が通っていれば DB が 23505 か版の違いで止め、上のとおり読み直して決める）。消せたか分からなかった後のもう一度で、読み直すと消えていたときは「「{題名}」は削除されていました」（前の削除が通っていた可能性があるので、ほかの人が削除したとは言わない）
  - CHECK の違反（23514。zod を通せば起きない）：「入力が範囲を超えています」
- 履歴（/history。部門長以上）：項目の登録・変更・削除は監査に残る（理由は置かないので、理由の列は「—」）。表の名前は「締切と予定」、対象は題名、種類（kind）と対象（audience）は表示名（締切・予定、総務・団体・全員。お知らせの宛先の表示名と取り違えない）、書いた人・直した人（created_by・updated_by）は表示名で出す
- 読み込み中・読み込みの失敗（もう一度）・空の表示はほかの画面と同じ部品を使う

**ダッシュボードに出すもの（締切と予定。D-52・D-54）**

- 欄：締切と予定にだけ出す（「ダッシュボード」の欄の表）。要対応・機能ごとのカード・お知らせの欄には出さない（要対応にする「済んだ」の印を持たず、カードは欄と同じものを数えるだけになるため）
- 読むもの：events の id・kind・title・starts_at・ends_at・all_day だけ（対象・メモ・書いた人は読まない）を、開いている年度で、開始の早い順・id の順に全部（読める範囲は RLS：総務は全部、閲覧のみ・店長・副店長は対象が団体・全員のもの）。1人1回だけ読む（店長・副店長も務める管理者は総務として、閲覧のみで店長・副店長も務める人は閲覧のみとして読む。結果が同じ）。どれを出すかはブラウザで決める（下）
- 1件：題名、日時（終日の項目は日付だけで、最後の日があれば「〜」でつなぐ）、種類。行き先は `/calendar?event={id}`（一覧でその項目を目立たせる）。選び方・並び・日付の出し方は「ダッシュボード」の締切と予定のとおり
- 読み取りの結果を使う欄：締切と予定だけ（読み込み中・失敗はこの欄にだけ出し、要対応・カード・お知らせの欄には出さない。年度の行だけで決まる項目はない）。失敗の文言は「締切と予定：{文言}」と「もう一度」で、机椅子の日付（年度の行から）は出したまま
- 先読み：ダッシュボードの先読み（「共通レイアウト」の読み込みの項）に、この読み取りを足す（総務は総務として、閲覧のみは閲覧のみとして、ロールのない店長・副店長は店長・副店長として）。軽いモジュール（読み取りとキーだけ。並べ方や組み立てを持たない）から読む（D-52）。団体代表の / が 4G で 2 秒以内のままであることを `pnpm e2e:perf` で確かめてから足す（超えたら先読みに入れず、04 と notes/T18.md を直す）

## DB関数とブラウザ側の処理

サーバーを持たないので、Route Handler と Server Action は使わない。読み取りと、理由の要らない書き込み（在庫入力、締切前の申請一覧のセル編集、マスタの編集、予定と締切の登録・変更・削除〔T18。画面は「締切と予定」〕）は、画面から Supabase クライアントで直接行い、RLS で守る。理由が要る書き込みと、複数の表をまとめて変える書き込み（申請の提出を含む）は DB 関数（RPC）で行う。重い計算とファイルの作成は使う人のブラウザで行う（振り分けの計算は部門長以上、振り分け表の Excel は総務、年度データの書き出しは管理者）。

- RPC は SECURITY DEFINER にして `search_path = ''` を設定し、関数の最初でロールを確かめる。次に年度の行をロックし（`for no key update`）、ロールをもう一度確かめてから状態を確かめ、入力を確かめてから理由を置いて書き込む。入力はブラウザで zod、DB では関数の中でもう一度確かめる
- エラーは `raise exception`（SQLSTATE P0001）で返し、message にコード、detail に該当する行の id などを JSON で入れる（メールアドレスは入れない）。PostgREST は HTTP 400 で `{ code: 'P0001', message, details }` を返す。コードは forbidden（ロールがない、段の外。対象が見つからないときも）、not_found、invalid_state（状態が違う、確定中に変えられない）、conflict（版・updated_at が違う、重複、別のロール〔field: role〕・別の立場〔field: group_role〕を持つ）、invalid_input（形や参照が違う、上限を超える）、reason_required、role_overlap（兼任の禁止。同じ年度で部門のロールと団体代表を兼ねる書き込み。detail は year_id と、分かれば user_id。invite の早めのエラーでは reason〔requested_together・current_membership・pending_invitation〕も入れる。D-49）、検証コード（E001・E002・E005・E006）。画面は role_overlap を種類 conflict として扱い、「総務の部門員・部門長・副部門長は、同じ年度の団体の店長・副店長を兼ねられません（管理者と閲覧のみは兼ねられます）」と出す。RPC の中で起きた形の誤り（jsonb の中の uuid・日付など）と CHECK 違反も invalid_input にして、生の SQLSTATE は返さない。ただし、RPC のトップレベルの型つきの引数（uuid・enum・date・integer）は PostgREST が関数の前に変換するので、形が違うと 22P02・22007 などがそのまま返る（関数の中では直せない）。画面は zod で先に確かめ、22 で始まる SQLSTATE は「入力の形が違う」として扱う。画面で日本語に直して表示する
- 楽観ロックの updated_at は、受け取った文字列をそのまま返す（Date に変換しない）
- 振り分けの行を渡す JSON は、03 の AllocationRow と同じ camelCase（sourceRoomId、groupId、itemId、requestedItemId、count、isKeep）にする
- 書き込みがデッドロック（SQLSTATE 40P01。PostgREST は HTTP 500 で返す）で失敗したときは、何も保存されていない（1リクエスト＝1トランザクション）ので、入力を残したまま「ほかの人の保存と重なりました。もう一度保存してください」と出す。HTTP 500 を一律に扱わず、エラーの code で分ける
- highs-js の wasm は振り分け画面を開いたときだけ読み込む（その画面のコンポーネントで `new Worker(new URL('…worker.ts', import.meta.url))` を作り、Worker の中で highs を読み込む）。wasm は highs の `highs/runtime`（highs の package.json の exports。`require.resolve('highs/runtime')` が build/highs.wasm を指す。`highs/package.json` は exports にないので引けない）を `apps/web/public/highs.wasm` にコピーして静的ファイルとして公開し（git には入れず .gitignore に書く）、locateFile で basePath を付けた URL（`${origin}${basePath}/highs.wasm?v=<highs の版>`）を渡す。コピーは apps/web の predev と prebuild の両方で行う（`pnpm dev` でも 404 にならないように）。basePath を付け忘れると GitHub Pages で 404 になり、`CompileError: expected magic word` で落ちる。読み込みに失敗したら、次の実行で読み直す（失敗を覚えたままにしない。読み直しの URL に回数を付け、404 のキャッシュを避ける）。Worker は1つだけ作り、画面を離れて戻っても使い回す（ログアウトで止める）。`next build --webpack` は highs.mjs の `node:module` で失敗するので使わない
- validate と Excel の作成は主スレッドで行う（R8 規模で validate は数十 ms、Excel の作成は 0.1 秒ほど）。ExcelJS を含む exporter は、出力するときに読み込む（動的 import。最初の読み込みを重くしない）
- 画面は、エラーを code（P0001 の message と details、22 で始まる SQLSTATE、42501、23505・23503・23514、40P01、PGRST301・PGRST302・PGRST303 と HTTP 401、通信の失敗）で分けて日本語にし、読み直すか・入力を残すかを決める。分け方と文言は apps/web/lib/errors.ts の1か所に置く（D-33）。details にある団体・部屋・品目・行の id は、画面が持っている名前に直して出す。JWT のエラー（PGRST301〜303・401）は、セッションの更新を1回試し、だめならその端末のセッションを消してからログインの画面へ送る（消さずに送ると、ログインの画面が「ログイン済み」としてすぐ戻すため）
- 直接の更新と削除は、変わった行を返させて確かめる。RLS で拒否された update・delete はエラーにならず 0 行で成功するので、0 行なら読み直して「ほかの人が変えた・消した」か「権限か年度の状態が変わった」かを分ける
- 通信が切れて応答が届かなかった書き込みは、自動で送り直さない。書き込みの種類で次の3つに分ける。どれも、確かめるためだけの状態（押せない保存のボタンなど）は (B2) のほかには持たない
  - (A) 数を絶対値で書く書き込み（在庫・申請）：保存のたびに、送る前に今の行を読み直して決める（入力と同じ値になっていれば送らずに「保存されていました」）
  - (B1) 楽観ロックの更新（updated_at）と、一意のキーのある insert（マスタ・ルール・今年の使用。お知らせの更新と削除〔save_notice の notice_id あり・delete_notice。T17〕も楽観ロックなのでこれ。予定と締切〔T18〕も、変更・削除は updated_at を条件に入れた直接の update・delete、登録は画面が id を作って送る insert〔主キーが一意のキー〕なのでこれ）：応答が届かなかったその場で行を1回読み直し、入力と同じなら「保存されていました」とする。決められなければ入力を残し、もう一度の保存はふつうに送ってよい。前の送信が通っていれば DB が updated_at の違い（conflict）か重複（23505）で止めるので上書きにならず、止まった後に行を読み直して入力と比べる（同じなら保存されていた、違えばほかの人の変更として扱う）
  - (B2) save_allocation_rows（行の追加に冪等の鍵がなく、確かめずに送り直すと二重にできる）と、ほかの RPC（save_auto_allocations・確定・了承の回答。お知らせの作成〔save_notice の notice_id なし。T17〕も冪等の鍵がないのでこれ）：版などで保存されたかを読み直して確かめてから送り直す
