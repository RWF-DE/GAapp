# T01 リポジトリの雛形・CI・GitHub Pages
推奨：モデル sonnet ／ effort medium

目的：05_development.md の「リポジトリ構成と環境変数」「ブランチ・レビュー・CI」のとおりに、モノレポの雛形と、CI・公開の仕組みを作る。

前提：
- pnpm workspace、Next.js（App Router、`output: 'export'`、basePath はリポジトリ名）、TypeScript strict、Tailwind CSS、shadcn/ui、Vitest、Playwright、Supabase CLI。
- GitHub Pages には Actions で公開する。公開リポジトリなので保護ブランチが使える。

範囲：雛形と設定だけ。DB のスキーマ（T02）や画面（T09〜）は作らない。apps/web はログイン画面のプレースホルダーと、空のトップページだけ。

完了基準：
- `pnpm install`、`pnpm lint`、`pnpm typecheck`、`pnpm test`（空のテストが1つ通る）、`pnpm build`（out/ に静的ファイルが出る）がローカルで通る。
- ci.yml が PR で上の4つと `supabase test db`（テストが空でも可）を実行する。deploy.yml が main への push で Pages に公開する。migrate.yml は手動実行（workflow_dispatch）で `supabase db push` する。
- CLAUDE.md の「コマンド」を実際のコマンドに書き換えた。

出力：変更ファイル一覧、実行したコマンドと結果。手作業が要る設定（Pages の有効化、Actions の変数と secrets、保護ブランチ）の手順を README に書く。

---
終わったら：reviewer サブエージェントでレビューする（正しさと要件に関わる指摘だけ）。認証・RLS・RPC・入力処理に触れたら security-reviewer にも回す。指摘を直してから PR を作り、docs/requirements/05_development.md のチケット表の状態を更新する。
