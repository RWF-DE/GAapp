# T03 RLS・権限の関数・RPC
推奨：モデル opus ／ effort high ／ 計画モードで開始

目的：02_data.md の「権限とRLS」と、04_screens_api.md の DB 関数を実装し、pgTAP でロールごとの権限を確かめる。

前提：
- 権限の判定は `private.has_role(year_id, role)` と `private.is_group_member(group_id)`（SECURITY DEFINER、`search_path = ''`）で行う。
- RPC はすべて SECURITY DEFINER、`search_path = ''` にし、最初にロールを確かめる。理由は `set_config('app.reason', reason, true)` で、書き込みと同じトランザクションに置く。
- allocations は誰にも直接の書き込みを許さない。確定中は RPC がエラーを返す。
- save_auto_allocations は auto かつ未固定の行だけを消して入れ替え、保存後に在庫超過がないかを DB で確かめ、超過していれば全体を取り消す。
- set_consent は、了承なら該当の置き換え行を pinned にし、拒否なら pinned を外す。
- create_year_from は rules.params の団体 id を名前で付け替える。付け替えられないルールは無効にして memo に理由を書く。

範囲：supabase/migrations と supabase/tests。画面は作らない。

完了基準：
- 権限表のすべてのセル（ロール × テーブル × 読み・書き）を pgTAP で確かめ、`supabase test db` が通る。
- 招待されていないユーザーが自分の profiles 以外を読めないこと、団体代表が他の団体の requests を読めないことを確かめる。
- 各 RPC の正常系と、権限がない場合・状態が違う場合（確定中など）のエラーを確かめる。
- security-reviewer サブエージェントのレビューを受け、指摘を直した。

出力：変更ファイル一覧、テスト結果。仕様を補った点は 02_data.md と 04_screens_api.md にも反映する。

---
