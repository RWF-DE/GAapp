# T02 DDL・列挙型・ビュー・監査トリガー
推奨：モデル sonnet ／ effort medium

目的：02_data.md の列挙型とテーブル定義を、Supabase のマイグレーションにする。

前提：
- 02_data.md の DDL と「設計上の決めごと」に従う。
- 全テーブルに created_at・updated_at を付ける（updated_at はトリガーで更新）。
- v_remaining は security_invoker にし、使用不可の部屋を除く。
- audit_logs へのトリガーは stocks・requests・request_submissions・rules・allocations・substitution_consents・years・year_roles に付け、理由は `current_setting('app.reason', true)` で読む。
- 残すの整合（運び元＝団体の使用場所）は CHECK ではなくトリガーで確かめる。

範囲：supabase/migrations と supabase/seed.sql（品目9件と、テスト用の場所数件だけ。R8 の本データは T05）。RLS と RPC は T03。

完了基準：
- `supabase db reset` が通る。
- pgTAP（`supabase test db`）で次を確かめる：テーブル・列・制約があること、v_remaining が使用不可の部屋を除くこと、監査トリガーが行を書くこと、残すのトリガーが不正な行を拒否すること。
- `supabase gen types` の出力を packages/shared に置く。

出力：変更ファイル一覧、実行したコマンドと結果。DDL を仕様から変えた点があれば、理由を書いて 02_data.md も直す。

---
終わったら：reviewer サブエージェントでレビューする（正しさと要件に関わる指摘だけ）。認証・RLS・RPC・入力処理に触れたら security-reviewer にも回す。指摘を直してから PR を作り、docs/requirements/05_development.md のチケット表の状態を更新する。
