# T04 Google ログイン・ドメイン制限・招待
推奨：モデル opus ／ effort high ／ 計画モードで開始

目的：Supabase Auth の Google ログイン、学校のドメイン以外の拒否、招待からロールを付ける仕組み、CI 用のテストログイン、全画面で使う共通レイアウト（P-03）を作る。

前提：
- 02_data.md の「権限とRLS」の箇条書き（Before User Created フック、hd クレーム、auth.users への追加時のトリガー、invite RPC、メールは小文字で比べる）。
- 学校のドメインと、1〜3年生が外部アプリにログインできるかは未確定。notes/decisions.md を確認し、決まっていなければ質問する。ドメインはフック関数の中の定数にする。
- 静的書き出しなので、ログインはブラウザの PKCE フロー。リダイレクト先は GitHub Pages の URL（basePath 込み）とローカル。
- 04_screens_api.md の「共通レイアウト」「ログイン」。共通レイアウトは T10・T11 も使うので、T09 からこのチケットに移した（P-03）。

範囲：supabase/（フック・トリガー・テスト）、apps/web のログイン画面と「総務から招待されていません」の画面、ログイン状態の保持、共通レイアウト（ナビゲーション、ロールによる表示の切り替え、読み込み中・空・権限なしの3状態の部品）。業務の画面（T09〜）は作らない。

完了基準：
- ローカル Supabase で、フックは学校の Google ドメイン（Google のプロバイダー）のユーザーだけを作成でき、それ以外（ほかのドメイン、Google 以外のプロバイダー、テスト用ドメインのメールのサインアップ）は拒否される（フックのテスト）。テストユーザーは seed で auth.users・auth.identities に直接入れ、フックを通らずに作る（D-02）。
- 招待済みのメールで初めてログインすると year_roles と group_members が作られ、招待されていなければ何も読めない（pgTAP）。
- Playwright 用に、ローカルだけでメール＋パスワードのテストユーザー（管理者・部員・団体代表・未招待）でログインでき、それぞれナビゲーションの表示が違う。CI の e2e ジョブはローカルの Supabase を起動してから行う。
- 実際に起動して確認し、スクリーンショット（PC とスマホ幅）を notes/T04/ に残す。
- security-reviewer のレビューを受け、指摘を直した。

出力：変更ファイル一覧、テスト結果。本番で手作業が要る設定（Google Cloud の OAuth クライアント、Supabase のリダイレクト URL、フックの有効化、メールログインの無効化）を README に書く。
