# T14 履歴・通しの E2E・README
推奨：モデル sonnet ／ effort medium

目的：/history を作り、SPEC.md の「E2E の検証手順」を Playwright で通しにし、運用の README を書く。ホーム画面に追加できる PWA のマニフェストを入れる（K-20）。

前提：04_screens_api.md の「履歴」、SPEC.md の「E2E の検証手順」、00_overview.md の「性能と可用性」「保守と引き継ぎ」、05_development.md の「受け入れ基準」（とくに「画面の受け入れ（総務で確認）」）、画面の設計書の 3.12・7 章（7.3 通しの流れ、7.6 画面の受け入れ、7.7 4G の速さ）、D-17a（本番の Auth で必ず守る設定）・D-36（E2E のデータ）・D-38（PWA）。T09〜T13 がすべてマージされていること。
- 画面の設計書 notes/T09a-design/ui-design.md（1・2 章：構成とデータの読み書き、7 章：テスト）と、T09a の共通基盤（components/ui・components/common、lib/db・lib/rpc・lib/errors.ts・lib/data・lib/schemas/common.ts、e2e/support）を使う。共通の部品が足りなければ自分の画面のディレクトリ（components/<画面>/）に置き、common/ に移すのは2つ目の画面が要るときに後のチケットで行う。

範囲：app/(app)/history、components/history、lib/data/history.ts（diffAudit を含む）、e2e/serial/full-flow.spec.ts・e2e/full-flow/（データの事前の確かめの Vitest）・e2e/fixtures/full-flow-stall.csv（個人情報なし）・e2e/t14-*.spec.ts・e2e/basepath/・e2e/perf.spec.ts・e2e/manual/、e2e/shots/T14.shots.ts、scripts/build-e2e.mjs の引数（basePath・Supabase の URL）、playwright.config.ts の basepath・manual・perf のプロジェクト、PWA のマニフェストとアイコン（app/manifest.ts・app/icon.png・app/apple-icon.png。`display: "browser"`。Service Worker は入れない）、ci.yml の e2e ジョブ（basePath のビルドとスモーク、LibreOffice の取得、timeout-minutes 25）、README.md（docs/runbook.md に分けてもよい）、SPEC.md の「E2E の検証手順」、04 の「履歴」の節、05 の受け入れ基準のチェックボックス、notes/T14.md・notes/T14/。

完了基準：
- CI で通しの E2E（ログイン → 在庫 → 申請・取り込み → 締切 → 自動振り分け → 確定 → 出力〔LibreOffice で再計算して数式エラー・「在庫超過」「要確認」が0件〕→ 確定の解除 → 使用不可にして最小変更）が通る。数え直し・提出・取り込みは需要を増やさない（設計 7.3）。この入力で full と最小変更が解け、D-08 の判定が通ることを、E2E の前に Vitest（e2e/full-flow/）で確かめる。最小変更は `@gaapp/allocator/testing` の checkMinimalChange で判定し、画面の結果が同じ入力の allocate の結果と一致する。補えないつながりで変わった行の数を記録する。年度の作成と複製は T09 の serial のテストで確かめる。
- basePath（/GAapp）で書き出したもののスモーク（計算エンジンの読み込みで `/GAapp/highs.wasm` が 200、QR の URL、マニフェストとアイコンが 200）が CI で通る。
- 履歴の絞り込み（表・団体・期間・した人）と「さらに読み込む」（Playwright）、diffAudit の Vitest。
- README に「7月の再開と年度の始め方」「ルールの変え方」「年度末の書き出し（JSON・Excel、`supabase db dump`）」「障害時の対応」「オーナーの引き継ぎ」が書いてあり、7月の再開の手順に「本番の Auth で必ず守る設定（Google だけでログイン〔Email・Phone・匿名は無効〕、Confirm email と Secure email change は有効、Allow manual linking は無効。D-17a）が変わっていないことを確かめる」がある（設定の一覧は T04 の README の「必ず守る設定」。T04 を積み直したときに Allow manual linking が足されていることを確かめ、なければ足す）。
- 05 の「画面の受け入れ（総務で確認）」の4項目を、設計 7.6 の手順（総務の PC から LAN に配り、スマホで操作。データは合成データか R8）で確かめ、notes/T14.md の表（日付・端末・ビルド・データ・役割・計った区間・結果・詰まった所。名前は書かない）に記録した。部員の在庫入力は3部屋とも 60 秒以内、団体代表の提出は総務以外の2人以上が手を貸さずにでき、管理者の「使用不可 → 最小変更 → 出力」は、使用不可にする前に固定・手動の行を直す時間を含めて 5 分以内（了承で固定した行がその部屋にある状態でも1回計る）、見え方は pgTAP と e2e/foundation.spec.ts が通る。
- 00 の「画面はスマホの 4G でも 2 秒以内に開く」を、/stock・/request・/my で Fast 4G 相当と CPU 4 倍の条件で3回ずつ測り（`pnpm e2e:perf`）、中央値を notes/T14.md に記録した。最初に読む JS の量が T09a の記録の 1.5 倍以内で、ExcelJS と highs が3画面の最初の読み込みに入っていない。
- PWA：ホーム画面に追加したとき、ブラウザ（Safari・Chrome）で開いてログインのまま使える。standalone に変えるのは、iOS Safari と Android Chrome の実機で Google ログイン → /auth/callback/ → セッションが残ることを確かめたときだけ（確かめた端末を notes/T14.md に書く）。
- 05_development.md の受け入れ基準のチェックボックスを、確かめたものから埋めた（満たせなかったものは埋めず、出力に書く）。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。E2E はシナリオの年度（e2e/support の createScenario）で閉じる。seed の R8 の年度のロールと未招待のユーザーは変えない（seed のユーザーにはシナリオの年度にだけロールを付けてよい。ロール・招待を変えるテストは createUser のユーザーで。年度をまたぐ表は serial でだけ変える。D-36）。
- 実際に起動して確かめ、スクリーンショット（PC とスマホ、読み込み中・空・権限なし、主なダイアログ）を `pnpm e2e:shots --grep "<チケットID> "`（ID の後に空白を入れて絞る。ID だけだと、T09 が T09a のテストにも当たるように、ID で始まるほかのテストにも当たる） で notes/<チケットID>/ に残す。
