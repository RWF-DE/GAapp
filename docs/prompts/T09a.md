# T09a 画面の共通基盤
推奨：モデル opus ／ effort high ／ 計画モードで開始

目的：T09〜T13 の画面が同じ部品・同じデータの読み書き・同じテストの土台を使い、並行するブランチで同じファイルを作らないように、画面の共通基盤を先に入れる（D-32）。

前提：
- 画面の設計書 ui-design.md と差分案 spec-changes-ui.md（依頼と一緒に受け取る。設計書はこのチケットで notes/T09a-design/ui-design.md としてコミットする）の 1・2・4・7・8 章と、末尾の「改訂の記録」。04_screens_api.md の前書き・「共通レイアウト」・「ログイン」・「DB関数とブラウザ側の処理」、02_data.md の権限表と状態遷移、notes/decisions.md の D-17a・D-18・D-19・D-21・D-25・D-27〜D-29。
- T04・T05・T07・T08 がマージされていること（T09a は exporter の exportAllocationXlsx・allocationXlsxFileName・exportYearJson、importer の parseCsvLoose、shared の型と validate を使う。どれかがなければ始めない）。
- T04 の土台（AppShell、RequireAudience、components/states.tsx、lib/navigation.ts、lib/auth/）を使い、置き換えない（足すのは年度の切り替え〔useGuardedSetYear で未保存の入力を確かめる〕・canOpen・useGuardedRouter・ログアウトの scope と下書きの扱い・ログインのアプリ内ブラウザの案内と、立場の読み直しを裏で行う変更）。T04 の AuthProvider は reloadMembership で membership を 'loading' に戻し、AppShell がページ全体を読み込み中に置き換えて画面を外す（未保存の変更・フォーム・ダイアログの理由の入力が消える）ので、同じ利用者の読み直しでは前の membership を ready のまま出して isRefreshing だけを足し、AppShell が置き換えるのは初回と利用者が変わったときだけにする（設計 1.3）。T04 は T03 の今の先頭（bd6aef0。1日目の範囲・本人のメールの判定・Google の email_verified）の上に積み直したもの。
- 静的書き出し（動的セグメントなし、id はクエリ文字列）、basePath、publishable キーだけ。依存は exact で、公開から7日たった版。ui.shadcn.com はこの環境から届かないので、shadcn/ui（new-york v4）の部品は GitHub の raw からコミットを決めて手で置き、ファイルの先頭に元のコミットを書く。
- 業務の意味に関わる確認事項（設計書 9 章の Q1〜Q4）は、ユーザーの答えに従う（答えがなければ推奨案で作り、notes に書く）。

範囲：
- apps/web：components/ui（shadcn/ui）と components/common（DataTable・CountStepper〔min・max〕・ReasonDialog・ConfirmDialog・ErrorBanner・TokyoTime・YearStatusBadge・YearStatusActions〔入力の誤りがあれば確定できない〕・EntitySelect・UnsavedChangesGuard・AppLink・PageHeader・StaleBanner。書き込みのボタンは送信中は押せない）、app/layout.tsx（QueryClientProvider・Toaster）、ログアウトを `signOut({ scope: 'local' })` にし、手動のログアウトは未保存の入力を確かめてからキャッシュ・その人の下書き・選んだ年度を消し、401 などでの強制の signOut では下書きを残し、別の利用者のログインで他人の下書きを消す（設計 1.3 の (a)〜(c)）、立場の読み直しを裏で行う（isRefreshing）、年度の切り替え（D-31。sessionStorage。`current-year` の testid は保つ）と最新でない年度の帯・切り替えのボタン、全画面の雛形のページ（「この画面は準備中です（T10）」）とナビゲーションの ready・audiencesFor・canOpen・useGuardedRouter、ログインのアプリ内ブラウザの案内、lib/db（fetchAll・updateWithLock・deleteChecked）・lib/rpc・lib/errors.ts・lib/drafts.ts・lib/data（year・snapshot・year-data〔createContext で参照を確かめ、参照の切れたルールを problems に入れる〕・room-years〔setRoomUsable・fixedRowsFrom〕・validation・version-watch・swaps の swapRows・export の downloadAllocationXlsx）・lib/datetime.ts・labels・download・csv-file・query・lib/schemas/common.ts（optionalText を含む）。lib/errors.ts と lib/data/year-data.ts は E2E からも読むので、相対の import だけにする。
- T09〜T14 が使う依存をまとめて追加する（後のチケットは package.json・pnpm-lock.yaml を触らない）。ルートの devDependencies に @gaapp/shared・@gaapp/allocator（workspace。E2E の補助用）を足し、packages/allocator の exports に `./testing`（checkMinimalChange・getHighs など。ロジックは変えない）を足す。scripts/copy-highs-wasm.mjs と apps/web の predev・prebuild、.gitignore、ESLint の規則（highs は workers/ の外から import しない、@gaapp/exporter は動的 import、useRouter の直接の push・replace を使わない、no-console）、scripts/first-load-js.mjs（ページごとの最初に読む JS の量）。
- テストの土台：Vitest の jsdom（ファイルごとに指定）と e2e-support のプロジェクト、e2e/setup（年度をまたぐ表を1回だけ入れる db-setup と、storageState の auth-setup）、e2e/support（createScenario〔rules・extraGroups・prevYear・usable・grants・festivalStart〔latest は serial だけ〕・keep を含む〕・datasets・createUser・pinYear・shoot）、playwright.config.ts のプロジェクト（db-setup・auth-setup・chromium・serial・shots・manual・perf。shots・manual・perf は環境変数のときだけ）、scripts/e2e.mjs（chromium と serial を別に流す。`pnpm e2e`）、`pnpm e2e:shots`、scripts/local-supabase-env.mjs の DB_URL。db-setup は前の実行の残り物（E2E- の年度、serial のテスト用の行、e2e- のユーザー）を先に消す。
- 要件定義：04 の前書き・「共通レイアウト」・「DB関数とブラウザ側の処理」、05 の「リポジトリ構成」「CI」「チケット分割」（T09a の行と T09〜T14 の前提）、00 の画面一覧（Q1）、docs/prompts（README・T09〜T14）、CLAUDE.md の落とし穴、notes/decisions.md に D-31〜D-38（画面の設計書の差分案 spec-changes-ui.md のとおり）。
- DB（migrations・seed・pgTAP）は変えない。各画面の中身は作らない。

完了基準：
- 共通の純粋関数（toYearData〔'' と空白だけを null に、壊れたルール、参照の切れたルール → problems に ruleCode が入り validate が例外を投げない〕・toStoredRows・loadSnapshot の読む順・updateWithLock と deleteChecked の分け方・classifyError と文言の表の全行〔PGRST303・status 401・details のないものを含む〕・canOpen・drafts〔手動のログアウトで消える・強制の signOut では残る・別の利用者で他人の分が消える〕・datetime・swapRows・schemas/common）の Vitest が通る。AuthProvider と AppShell の Vitest：reloadMembership の間に子が外れない（子の状態が残る）、初回は読み込み中、読み直しの失敗で前の立場が残る。UnsavedChangesGuard の部品のテスト：未保存の入力があると手動のログアウトと年度の切り替えで確かめ、やめればそのまま。合成データ r8like を DB の行の形にした入力で、toYearData が shared/testing の toYearData と同じになる。createScenario の reference の行（is_keep を使用場所から決めたもの）を validate すると error 0。
- e2e/foundation.spec.ts：5人のナビ（全画面が ready）、立場の合わない画面を URL で直接開くと権限なし、シナリオの年度を作って切り替えると表示が変わり、同じタブの再読み込みでも残り、新しいタブでは最新の年度で開く、団体代表が API を直接呼んでもほかの団体の申請が 0 行で、未招待は何も読めない。e2e/errors.spec.ts：代表的な RPC の失敗を本物の DB で起こし、classifyError と文言が既定に落ちない。T04 の e2e/auth.spec.ts を新しいナビに合わせて通す（シナリオの年度ができていても `current-year` は変わらない。ログアウトのテストが storageState のセッションを壊さない）。
- `pnpm e2e` が chromium と serial を別に流し、片方が落ちてももう片方の結果が残る。
- `pnpm dev` と `pnpm build` の両方で apps/web/public/highs.wasm がコピーされ、out/ に入る。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。CI の check ジョブの時間の増え方と、ページごとの最初に読む JS の量（scripts/first-load-js.mjs）を notes/T09a.md に記録する。スクリーンショット（雛形・年度の切り替え・3状態・エラーの帯・下書きを戻す表示）を notes/T09a/ に残す。
- notes/T09a.md に、T09〜T13 が使う部品とデータの層の使い方（例つき）を書く。

出力：変更ファイル一覧、実行したコマンドと結果、スクリーンショット、T09〜T13 への申し送り。
