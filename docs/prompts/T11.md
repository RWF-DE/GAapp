# T11 画面：申請と申請一覧・CSV 取り込み
推奨：モデル sonnet ／ effort medium

目的：/request（スマホ、団体代表）と /requests（PC、総務）を作り、フォーム回答の取り込みを画面から使えるようにする。

前提：
- 04_screens_api.md の「申請」「申請一覧」「CSV取り込み」と、画面の設計書の 3.5・3.6・5 章。
- 画面の設計書 notes/T09a-design/ui-design.md（1・2 章：構成とデータの読み書き、7 章：テスト）と、T09a の共通基盤（components/ui・components/common、lib/db・lib/rpc・lib/errors.ts・lib/data・lib/schemas/common.ts、e2e/support）を使う。共通の部品が足りなければ自分の画面のディレクトリ（components/<画面>/）に置き、common/ に移すのは2つ目の画面が要るときに後のチケットで行う。
- 申請できる品目は items.requestable_categories で絞る。提出は submit_requests。締切前のセルの編集は直接（updated_at で楽観ロック）、締切後の修正は update_requests_after_deadline（理由が必須）。未提出に戻す操作は出さない（D-19）。
- 取り込みは importer（T05）の parseFormCsv と resolveResponses を呼ぶだけで、取り込みのロジックは変えない。保存は団体ごとに update_requests_after_deadline の p_submission に submittedAt（フォームのタイムスタンプ）を付ける（D-29。締切の前後によらない）。CSV にない品目は 0、申請できない品目は送らない。上書きの既定は確認事項 Q2 の答えに従う。

範囲：app/(app)/request・requests、components/requests（取り込みを含む）、lib/data/requests.ts・import.ts、lib/schemas/requests.ts、e2e/t11-*.spec.ts、e2e/shots/T11.shots.ts、notes/T11.md・notes/T11/、04 の「申請」「申請一覧」「CSV取り込み」の節。ほかの画面のディレクトリ、apps/web/package.json・pnpm-lock.yaml、lib/navigation.ts、app/layout.tsx、playwright.config.ts、e2e/support は触らない（T09a が持つ。足りなければ notes に書いて相談する）。

完了基準：
- 団体代表が申請を提出し、締切前なら修正でき、締切後は読み取り専用になる（Playwright。締切はシナリオの年度で SQL から過去にする）。
- 企業以外の団体には、長机(3人掛)の入力欄が出ない。DB に長机(3人掛)の申請が残っていれば、読み取り専用の行として出る。
- 提出が DB に締切後と判断されたとき（端末の時計のずれ）は、読み取り専用になり、同じ失敗を繰り返さない（Vitest）。
- 総務が締切後に理由つきで修正すると、audit_logs に理由が残る。
- 休憩所の代理入力で「前年の数を入れる」を押すと、前年度（createScenario の prevYear）の申請の数が入る。
- fixtures/importer-samples の CSV を取り込むと、対応できなかった行・古い回答・取り込まない行が一覧に出て、手で対応させた団体の requests と submitted_at（フォームのタイムスタンプ）が入る。画面のどこにもメールアドレスの文字列が出ない（Vitest）。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。E2E はシナリオの年度（e2e/support の createScenario）で閉じる。seed の R8 の年度のロールと未招待のユーザーは変えない（seed のユーザーにはシナリオの年度にだけロールを付けてよい。ロール・招待を変えるテストは createUser のユーザーで。年度をまたぐ表は serial でだけ変える。D-36）。
- 実際に起動して確かめ、スクリーンショット（PC とスマホ、読み込み中・空・権限なし、主なダイアログ）を `pnpm e2e:shots --grep <チケットID>` で notes/<チケットID>/ に残す。

出力：変更ファイル一覧、実行したコマンドと結果、スクリーンショット。

---
終わったら：reviewer サブエージェントでレビューする（正しさと要件に関わる指摘だけ）。認証・RLS・RPC・入力処理に触れたら security-reviewer にも回す。指摘を直してから PR を作る。05_development.md のチケット表の「状態」と notes/decisions.md は直さず、新しい決定は notes/<チケットID>.md に書く（並行するブランチで隣の行を変えて衝突するため。マージの後にまとめて直す。D-32）。
