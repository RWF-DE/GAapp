# 00 キックオフ：全体の計画と質問の洗い出し
推奨：モデル opus ／ effort high ／ 計画モードで開始。このセッションではコードを書かない。

目的：要件定義を読み、実装を始める前に、不明点・矛盾・リスクを洗い出し、T00〜T04 の実装計画を立てる。

前提：
- SPEC.md、CLAUDE.md、docs/requirements/00〜05 をすべて読む。特に 03_allocation.md（定式化）と 02_data.md（DDL・RLS）は細かく読む。
- チケットの一覧と依存関係は 05_development.md の「チケット分割」。
- 00_overview.md の「未決事項」（学校の Google アカウントでログインできるか、組織のオーナーなど）はまだ決まっていない。

範囲：読むだけ。作ってよいファイルは notes/ の下だけ。リポジトリの雛形作りや実装はしない。

完了基準：
- 仕様の不明点・矛盾・実装上のリスクが、優先度つきで一覧になっている（それぞれに根拠のファイル名と見出しがある）。
- T00〜T04 の実装計画（作るファイル、順番、検証方法）がある。
- 決めてほしいことを AskUserQuestion で質問し、答えを notes/decisions.md に記録した。

出力：notes/kickoff.md（不明点・リスク・計画）と notes/decisions.md（決定事項）。チャットには要点を10行以内で返す。
