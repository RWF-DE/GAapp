# T09 画面：マスタ設定とダッシュボード
推奨：モデル sonnet ／ effort medium ／ 計画モードで開始

目的：/settings（年度の作成と前年度からの複製・年度の変更・場所・品目・団体〔CSV を含む〕・距離・ユーザーの招待とロール・データの書き出し）と、/（総務のダッシュボード、団体代表・閲覧のみのホーム）を作る。

前提：
- 04_screens_api.md の「ダッシュボード」「マスタ設定」と、画面の設計書の 3.1・3.2・6 章。
- 画面の設計書 notes/T09a-design/ui-design.md（1・2 章：構成とデータの読み書き、7 章：テスト）と、T09a の共通基盤（components/ui・components/common、lib/db・lib/rpc・lib/errors.ts・lib/data・lib/schemas/common.ts、e2e/support）を使う。共通の部品が足りなければ自分の画面のディレクトリ（components/<画面>/）に置き、common/ に移すのは2つ目の画面が要るときに後のチケットで行う。
- 書き込みは RLS の範囲なら直接（場所・品目・団体・距離・場所の使用不可）、年度の作成・変更・状態の変更・招待・ロールは RPC（create_year_from、update_year、set_year_status、invite、set_role、remove_role、revoke_invitation、remove_group_member）。確定の流れは T09a の YearStatusActions を使う。
- 団体名は packages/shared の groupNameSchema と checkGroupNames（D-27）、場所の追加コストと距離は 0〜20（D-28）、1日目は 2000-01-01〜2200-12-31（D-18）。invite の applied が false のときの文言は D-17a に合わせる（アカウントがないとは言わない）。
- 年度データの書き出しは exporter の exportYearJson（動的 import）、振り分け表は T09a の downloadAllocationXlsx。

範囲：app/(app)/page.tsx（T04 のホームを置き換えるが、`data-testid="home-roles"`・`home-year` の要素と文字はダッシュボード・ホームの「立場の一覧」として残す。T04 の e2e/auth.spec.ts は T09a が持ち、ここでは触らない）・settings/page.tsx、components/dashboard・settings、lib/data/dashboard.ts・settings.ts（団体・場所を参照するルールを探す rulesReferencing を含む）・year-export.ts、lib/schemas/settings.ts、e2e/t09-*.spec.ts・e2e/serial/year-create.spec.ts、e2e/shots/T09.shots.ts、notes/T09.md・notes/T09/、04 の「ダッシュボード」「マスタ設定」の節。ほかの画面のディレクトリ、apps/web/package.json・pnpm-lock.yaml、lib/navigation.ts、app/layout.tsx、playwright.config.ts、e2e/support は触らない（T09a が持つ。足りなければ notes に書いて相談する）。

完了基準：
- 管理者・部員・団体代表・閲覧のみ・未招待のテストユーザーで、ダッシュボード・ホーム・マスタ設定の見えるものが権限表どおり（Playwright）。
- 状態の遷移（受付開始に締切が要る・締切・確定・確定の解除・終了）。2つの画面で開き、片方で在庫を変えてからもう片方で確定すると、検証のやり直しが出て、もう一度押すと確定する。
- 年度を作って前年度から複製すると、団体とルールが付け替わり、無効になったルールの数が出る。終了した年度からも新しい年度を作れる（e2e/serial。create_year_from は全年度の中で最新の年度からしか作れないので、`festivalStart: 'latest'` のシナリオの年度〔1日目は seed の R8 より後〕から、grants でロールを付けた createUser の管理者で作る。seed の R8 からは作らない）。年度名が空・1日目が複製元より前のときは、送る前に欄にエラーが出る。
- 招待（確かめたユーザーで applied: true、確かめていないユーザー・新しいメールで false）、ロールの変更と外す（最後の管理者は外せない、終了した年度でも外せる）、団体の CSV 取り込み（使えない団体名が止まる）、表示名・建物の空欄が null で保存される、権限や状態が変わって消えなかった削除で「削除しました」と出ない。団体・場所の削除の確認に、参照している有効なルールのコードが出て削除できない。ダッシュボード・ホームに home-roles・home-year が残り、e2e/auth.spec.ts が通る。
- summarizeDashboard・toYearExport（設定の壊れたルールもそのまま書き出す）・rulesReferencing・団体の CSV の読み取りの Vitest。部員のダッシュボードに、開けない画面へのリンクが出ない。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。E2E はシナリオの年度（e2e/support の createScenario）で閉じる。seed の R8 の年度のロールと未招待のユーザーは変えない（seed のユーザーにはシナリオの年度にだけロールを付けてよい。ロール・招待を変えるテストは createUser のユーザーで。年度をまたぐ表は serial でだけ変える。D-36）。
- 実際に起動して確かめ、スクリーンショット（PC とスマホ、読み込み中・空・権限なし、主なダイアログ）を `pnpm e2e:shots --grep <チケットID>` で notes/<チケットID>/ に残す。

出力：変更ファイル一覧、実行したコマンドと結果、スクリーンショット。
