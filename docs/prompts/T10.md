# T10 画面：在庫入力と在庫一覧
推奨：モデル sonnet ／ effort medium

目的：/stock?room=…（スマホ）と /stocks（PC）、部屋に貼る QR の印刷（/stocks/qr）を作る。

前提：
- 04_screens_api.md の「在庫入力」「在庫一覧」と、画面の設計書の 3.3・3.4・6 章。
- 画面の設計書 notes/T09a-design/ui-design.md（1・2 章：構成とデータの読み書き、7 章：テスト）と、T09a の共通基盤（components/ui・components/common、lib/db・lib/rpc・lib/errors.ts・lib/data・lib/schemas/common.ts、e2e/support）を使う。共通の部品が足りなければ自分の画面のディレクトリ（components/<画面>/）に置き、common/ に移すのは2つ目の画面が要るときに後のチケットで行う。
- 部員が書けるのは年度が preparing・requesting のときだけ（RLS）。管理者は振り分け中・確定中も書けるが、確定中は振り分けの合計より少なくできない（DB の確定中の守り）。保存は部屋の全品目を1回の upsert（counted_by・counted_at は DB が入れる）。前年の数は RPC previous_year_stocks。
- QR の URL は basePath を付けた `/stock/?room=<id>`（年度を入れない。D-31）。QR は uqr の SVG。

範囲：app/(app)/stock・stocks・stocks/qr、components/stock、lib/data/stocks.ts（stockUrl を含む）、lib/schemas/stock.ts、e2e/t10-*.spec.ts、e2e/shots/T10.shots.ts、notes/T10.md・notes/T10/、04 の「在庫入力」「在庫一覧」の節。ほかの画面のディレクトリ、apps/web/package.json・pnpm-lock.yaml、lib/navigation.ts、app/layout.tsx、playwright.config.ts、e2e/support は触らない（T09a が持つ。足りなければ notes に書いて相談する）。

完了基準：
- スマホの幅（390px）で＋－と数字の入力ができ、保存すると数えた人と日時が出て、counted_by と counted_at が更新される（Playwright）。
- 読み込んだ後にほかの人が保存していれば、上書きするか読み直すかを選べる。
- 前年度がある年度（createScenario の prevYear）では、在庫入力に前年の数、在庫一覧に前年との差が出る。
- 入力の途中で別の画面へ移って戻ると、下書きから戻せる。最新でない年度を開いているときは、保存の前に確かめる。
- allocating 以降は、部員には読み取り専用になる。管理者が確定中に振り分けの合計より少なくしようとすると、保存の前に止まる。
- 使用不可の部屋に「今年は使用不可」と表示される。
- QR のページのカードの数と URL（basePath ありとなしの stockUrl の Vitest）。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。E2E はシナリオの年度（e2e/support の createScenario）で閉じる。seed の R8 の年度のロールと未招待のユーザーは変えない（seed のユーザーにはシナリオの年度にだけロールを付けてよい。ロール・招待を変えるテストは createUser のユーザーで。年度をまたぐ表は serial でだけ変える。D-36）。
- 実際に起動して確かめ、スクリーンショット（PC とスマホ、読み込み中・空・権限なし、主なダイアログ）を `pnpm e2e:shots --grep "<チケットID> "`（ID の後に空白を入れて絞る。ID だけだと、T09 が T09a のテストにも当たるように、ID で始まるほかのテストにも当たる） で notes/<チケットID>/ に残す。

出力：変更ファイル一覧、実行したコマンドと結果、スクリーンショット。

---
終わったら：reviewer サブエージェントでレビューする（正しさと要件に関わる指摘だけ）。認証・RLS・RPC・入力処理に触れたら security-reviewer にも回す。指摘を直してから PR を作る。05_development.md のチケット表の「状態」と notes/decisions.md は直さず、新しい決定は notes/<チケットID>.md に書く（並行するブランチで隣の行を変えて衝突するため。マージの後にまとめて直す。D-32）。
