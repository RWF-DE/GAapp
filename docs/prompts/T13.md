# T13 画面：振り分け・キャスター机交換・自団体の振り分け
推奨：モデル opus ／ effort high ／ 計画モードで開始

目的：/allocation（中心の画面）、/swaps、/my を作り、自動振り分けから確定・出力までを画面で行えるようにする。

前提：
- 04_screens_api.md の「振り分け」「キャスター机交換」「自団体の振り分け」「DB関数とブラウザ側の処理」と、画面の設計書の 3.9〜3.11・4 章、ロジック設計（notes/T06-design/logic-design.md）の 4・13・14 章。
- 画面の設計書 notes/T09a-design/ui-design.md（1・2 章：構成とデータの読み書き、7 章：テスト）と、T09a の共通基盤（components/ui・components/common、lib/db・lib/rpc・lib/errors.ts・lib/data・lib/schemas/common.ts、e2e/support）を使う。共通の部品が足りなければ自分の画面のディレクトリ（components/<画面>/）に置き、common/ に移すのは2つ目の画面が要るときに後のチケットで行う。
- 読み込みは T09a の loadSnapshot（版を先に読む）と toYearData・toStoredRows。入力の組み立て（buildAllocateInput）は並べ替えをしない（allocate・validate・exporter が自分で並べる）。
- 計算は Web Worker で allocate() を呼ぶ（Worker は1つだけ作って使い回し、読み込みの失敗を覚えない。管理者が振り分け中に画面を開いたときだけ読み込む）。「中止」は計算と読み直しの段階だけで、保存を送った後は中止しない。保存は save_auto_allocations（版を渡す）、行の編集は未保存の変更として溜めて save_allocation_rows（理由が必須。楽観ロック。数は 1 以上。備考だけの変更も手動の行になる。応答が届かなかったときは版で確かめてから送り直す）、了承は set_consent（了承のときは「未依頼に戻す」を出さない）、確定は set_year_status（T09a の YearStatusActions）。部屋の見出しから使用不可にできる（T09a の setRoomUsable）。使用不可にする前に、その部屋からの固定・手動の行を一覧にして直して保存してもらい、その後で使用不可にする（save_allocation_rows は使用不可の部屋の行の update を、固定だけの変更でも E002 で拒否する。手動の行は固定を外しても再実行で動かない）。使用不可の部屋の行と precheck の E002 には、運び元の変更と削除だけを出す（「固定を外す」は出さない）。validate と Excel は主スレッド、exporter は動的 import。開けない画面（部員にとってのルール画面など）へのリンクは出さない（T09a の canOpen）。
- 見る人・確定前の Excel・団体代表の回答の変更は、確認事項 Q1・Q3・Q4 の答えに従う。

範囲：app/(app)/allocation・swaps・my、components/allocation・swaps・my、lib/allocation（engine・issue-target・pending・tabs・group-view）、lib/data/allocation.ts・my.ts、workers/allocate.worker.ts、e2e/t13-*.spec.ts、e2e/shots/T13.shots.ts、notes/T13.md・notes/T13/、04 の「振り分け」「キャスター机交換」「自団体の振り分け」の節（Q3 なら 03 の「Excel出力仕様」のファイル名も）。allocator と exporter のロジックは変えない（バグを見つけたら別のチケットにする）。ほかの画面のディレクトリ、apps/web/package.json・pnpm-lock.yaml、lib/navigation.ts、app/layout.tsx、playwright.config.ts、e2e/support は触らない（T09a が持つ。足りなければ notes に書いて相談する）。

完了基準：
- 合成データ fixtures/synthetic/r8like（またはそれを入れた seed）のシナリオの年度で、自動振り分け → 検証の error 0 件 → 確定 → Excel 出力ができる。計算時間（result.elapsedMs）が 2000 ms 未満（D-21。wasm の初回の読み込みは含めず、別に記録する）（Playwright）。R8 の元データは使わず、fixtures/r8 は作らない（D-40）。
- 計算中は画面がロックされ、解けない入力（S05 が原因のもの）では不足と原因（S05）が表示される。ok: false の reason ごとの表示の Vitest。
- 了承を「拒否」にして最小変更で再実行すると、その団体の置き換えが消える。
- 2つの画面で同じ行を変えると、後の保存で「他の人が変更しました」と出て読み直し、ぶつからない変更は当て直される。
- 使用不可の部屋の固定の行：画面に「固定を外す」が出ず、API で固定を外す update を送ると E002 で全体が拒否され、運び元の変更と削除は通る。部屋の見出しの「使用不可にする」は、その部屋からの固定・手動の行を先に直して保存するまで押せず、その順で使用不可にして最小変更で再実行すると precheck に E002 が出ない（Playwright）。allowedRowOps と、使用不可にする前の一覧の Vitest。
- 保存の応答だけを落とす（page.route で route.fetch の後に route.abort）と、送り直しの前に保存されていたことが分かり、行が二重にならない。計算中のロックは page.route で保存の応答を止めて確かめる。
- 団体代表の /my で、確定前は申請内容と交換の依頼、確定後は運び元と数が見える。
- pending（applyPending〔備考だけの変更で manual〕・toRpcChanges・rebasePending・reconcileAfterUnknown）・issueTarget（立場ごと）・highsWasmUrl（basePath ありとなし）・品目タブの並び（exporter と同じ）の Vitest。中止が計算の段階でだけ出ること（engine を偽物にして fake timers）。
- `pnpm lint`・`pnpm typecheck`・`pnpm test`・`pnpm build`・`pnpm e2e` が通る。E2E はシナリオの年度（e2e/support の createScenario）で閉じる。seed の R8 の年度のロールと未招待のユーザーは変えない（seed のユーザーにはシナリオの年度にだけロールを付けてよい。ロール・招待を変えるテストは createUser のユーザーで。年度をまたぐ表は serial でだけ変える。D-36）。
- 実際に起動して確かめ、スクリーンショット（PC とスマホ、読み込み中・空・権限なし、主なダイアログ）を `pnpm e2e:shots --grep <チケットID>` で notes/<チケットID>/ に残す。

出力：変更ファイル一覧、実行したコマンドと結果、スクリーンショット、計算時間と wasm の読み込みの時間。
