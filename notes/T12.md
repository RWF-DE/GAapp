## まとめ

- /rules を作った。一覧（コード・種別・内容の文・有効の Switch・メモ・編集）、種別ごとのフォーム（シート）での追加・編集、「R8 の初期ルールから追加」（まだないコードだけ）、有効・無効の切り替え。削除は出さない。
- 保存の前に ruleRowSchema（形）と checkRuleRefs（自分以外の有効なルール。参照と重なり）で確かめ、エラーを path（`params.rooms` など）ごとに欄の下に出す。団体・場所は名前で選んで id、品目はコードで保存。保存は rules への直接の insert と、updated_at で楽観ロックした update（updateWithLock）。
- 確定中（confirmed）と終了（closed）はメモだけ直せる（追加・有効の切り替え・params の欄は出さないか押せない）。振り分け中は「ルールを変えると、振り分け画面で再実行が要ります」の帯。
- `?code=S05` でその行を目立たせ、編集のシートを開く。有効なルールのうち参照の切れたもの（消した団体・場所を指す）・ほかと重なるもの・形の壊れたものに印（「参照が切れています（団体が見つかりません）」など）を出す。
- lib/data/rules.ts（describeRule・checkRuleForm・checkEnable・ruleProblems・ひな形・読み書き）と Vitest 18 件、E2E（e2e/t12-rules.spec.ts。6 件）、スクリーンショット 23 枚（notes/T12/）、04 の「ルール」の節（差分案 3-13）。

## 決めたこと

1. **フォームは react-hook-form を使わず、画面の状態と「path → 文言」の表で持った**（設計 1.6 はダイアログとフォームに react-hook-form＋zodResolver と書く）。種別ごとに欄の形が大きく違い、確かめは shared の ruleRowSchema（形）→ checkRuleRefs（参照と重なり）の2段で、エラーが params の path（`params.rooms.3`・`params.items.desk` など）で返るため、form の欄の名前に写すより、path の前方一致で欄の下に出す方が素直だった。確かめは checkRuleForm（純粋関数。Vitest で確かめる）1か所。
2. **保存する params の形**：代替の indoorOnly・needsConsent は偽なら書かない（03 の例・rules.json と同じ形。スキーマの既定と意味は同じ）。代替の区分は「チェックを付けた順」のまま（rules.json の S02 は `["rest_area","stall"]`。並べ替えると E2E の「同じ」が崩れる。順に意味はない）。運び元の制限の品目・場所と、残すの品目は、品目・場所の並び（sort_order → 名前 → id）にそろえる（同じ内容なら同じ params）。
3. **確かめの範囲**：コードの重複は無効のルールも含めて画面で見る（DB の unique は年度で全部。checkRuleRefs は有効なルールだけを見るので、足した）。insert の 23505 は「同じコードのルールがあります」をコードの欄に出して一覧を読み直す。**無効のまま保存するルールは重なりを見ない**（参照だけ見る。使わないので重なっても害がなく、重なる案を無効で置いておける）。有効にするとき（Switch）に checkRuleRefs で重なりを確かめ、だめなら理由の一覧と「編集する」のダイアログを出す。
4. **無効にするとき**は確認のダイアログでメモ（理由）を一緒に直せるようにした（設計の「使わなくなったルールは無効にし、理由をメモに書く」）。有効にするときは確かめが通れば確認なしで更新する。
5. **`?code=`**：一覧の行を目立たせ、その行の編集のシートを開く（「その行を開いて」を、編集のシートを開くことにした）。確定中・終了の年度ではメモだけのシート。見つからないコードは toast「ルール「X」は見つかりません」。code が変われば画面を作り直す（key に入れた）。
6. **一覧の印**：有効なルールに checkRuleRefs（自分以外の有効なルール・今の団体・場所・品目）を当て、団体・場所・品目が見つからないものは「参照が切れています（団体が見つかりません）」、重なり・E005 などは「要確認」、形の壊れたものは「設定が壊れています」の印と文言の一覧。件数を上の帯にも出す。無効のルールには印を出さない（振り分けに使わないため）。
7. **ひな形**：品目・区分・数・メモは合成データの rules.json と同じ（S06 は 241 台、S08 は机(木) 12・椅子(木) 4）。S05・S06・S08 の団体・場所は空にして選んでもらう（年度ごとに id が違い、名前で決め打ちしない）。残すは団体を選ぶと場所に団体の使用場所が入る。ひな形のまま（入力を変えていない）なら閉じるときに確かめない。
8. **確定中・終了**：追加のボタンとひな形のメニューを出さず、Switch は押せず、シートはメモだけ（コード・有効・params の欄は押せない）。保存は `{ memo }` だけの update。確定中は ReadOnlyNotice「確定中です。ルールは確定を解除してから変えてください（メモだけ直せます）」、終了は「終了した年度のルールは、メモだけ直せます」。
9. **最新でない年度の確認（useNotLatestYearConfirm）は使わない**：設計 1.3.1 で確かめるのは在庫入力・申請・了承の書き込む画面だけで、ルールは管理者の画面のため。
10. **通信の失敗の後**（2.6）：insert はコードで、update は id で読み直し、送った値と同じ（params は JSON のキーの順によらず比べる）で updated_at が進んでいれば「保存されていました」とする。読み直しもできなければ「保存できたか確かめられません。通信が戻ったら『読み直す』で確かめてから、もう一度保存してください」をシートに出して入力を残す。401 は useAuthErrorHandler で1回だけセッションを更新して送り直す。conflict・not_found は一覧を読み直して入力を残す（ErrorBanner）、forbidden・state は一覧と立場を読み直す。
11. **内容の文（describeRule）**：代替「模擬店の机(木)が足りなければ不可机で代える（重さ 0、屋内の団体だけ、了承が要る、同じ距離なら休憩所を先に）」、運び元の制限「設営の机(木)は 1-1・1-2・… からだけ出す」（設計の例どおり）、固定の申請「設営が未提出なら、机(木)を 241 台申請したものとする」（03 の「未提出のときだけ」）、残す「学科展示は第一多目的室の 机(木) 12・椅子(木) 4 を残す」。見つからない団体・場所は「（見つからない団体）」、知らない品目はコード、params が壊れていれば「設定が壊れています」。
12. 部員などは RequireAudience で「権限がありません」（lib/navigation.ts の /rules は admin だけ。E2E で確かめた。foundation.spec から /rules を外したので、その確かめを t12 の spec に移した）。

## レビューの指摘を直したもの（2026-10-29）

作業の最初に `git merge --no-edit feat/T09a-ui-foundation` で T09a の最新を取り込んだ（衝突なし）。どちらも先に E2E を足して落ちることを確かめてから直した。

1. **読み直しの失敗で、開いているシートと入力が消えた**（rules-screen.tsx。指摘 1・3。設計 1.3・2.5・2.6）：RulesScreen が data より先に `q.isError` を見ていたため、読んだ後の読み直し（シートの「読み直す」・ErrorBanner・conflict などの後の onReload・refetchOnReconnect）が失敗すると、TanStack Query v5 が前の data を残したまま isError にし、画面全体が ErrorState に置き換わって RuleFormSheetBody が外れていた（UnsavedChangesGuard の確認もなし）。ErrorState は **data がないとき（`q.isError && q.data === undefined`）だけ**にし、data があるときは RulesView を出したまま、一覧の上に帯（`data-testid="rules-reload-error"`。「ルールを読み直せませんでした。表示は前に読んだ内容のままです」と ErrorBanner の「もう一度」）を出し、失敗のたびに toast でも知らせる（シートはモーダルで帯が見えないため）。読み直しが通れば帯は消える。ErrorBanner の「読み直す」は network では出ない（effectOf の reload が none）ので、onRetry（「もう一度」）で読み直す。
   - E2E「シートを開いたまま読み直しが通信の失敗になっても、シートと入力が残る」：?code=S05 のシートでメモを入れ、`page.route('**/rest/v1/rules*')` を abort にして保存 → 「保存できたか確かめられません…」→「読み直す」→ 失敗の知らせ。シートとメモが残り、ErrorState（「もう一度読み込む」）が出ない。通信を戻して読み直すと帯が消え、メモはそのまま。直す前はシートが消えて落ちた。supabase-js の GET の再試行と React Query の再試行で、失敗が出るまで十数秒かかる（テストの時間を延ばした）。
2. **無効にするダイアログが conflict から戻れなかった**（rules-screen.tsx。指摘 2）：ダイアログは開いたときの行（updated_at・メモ）を持ち続け、ほかの人が先に変えると、押すたびに同じ古い行で送って conflict になっていた（メモも古いまま上書きしやすい）。onConfirm で **今の一覧の行（`data.rules.find(id) ?? disableTarget`）を送り**、**conflict・not_found ならダイアログを閉じる**（一覧は runWrite が読み直す。開き直すと今のメモが入る）。network などはダイアログを開いたまま（入力を残す）。
   - E2E「無効にするダイアログを開いている間にほかの人がルールを変えたら、ダイアログを閉じて読み直す」：ダイアログを開いた後に SQL で S04 のメモを変え、「無効にする」→ ダイアログが閉じ、一覧にほかの人のメモ・S04 は有効のまま。開き直すとメモの欄がほかの人のメモで、無効にできる。直す前はダイアログが開いたままで落ちた。

1. **編集のシートの楽観ロックが、開いたときの版を使っていなかった**（rule-form-sheet.tsx・rules-screen.tsx。設計 2.5・3.8）：シートは保存のたびに今の一覧（data）から行を引き直し、その updated_at で updateRule を送っていた。シートを開いた後に一覧が読み直される（staleTime 30 秒を過ぎたキャッシュの mount の読み直し・refetchOnReconnect・「読み直す」）と、フォームは開いたときの値のままなのに版だけ進み、ほかの人の変更（例：S05 の運び元の場所）を conflict なしで黙って戻していた（メモだけのシートも同じ）。
   - RuleSheetTarget の編集に **baseUpdatedAt**（initial を作った行の updated_at）を持たせ、openEdit と `?code=` の最初の state で入れる。保存は `{ ...今の行, updated_at: 版 }` で送る（「保存されていました」の確かめも同じ版と比べる）。
   - 版を進めるのは **conflict を見た後だけ**：conflict の後に読み直した行が来たら、その updated_at に進める（描画中に state を合わせる。effect の setState は react-hooks の lint が止める）。もう一度の保存は、エラーの帯を見た上での意図した上書きになる（2.5「読み直して入力を残す」）。版がずれたことを知らせる帯は足していない（指摘で任意。画面は変えていない）。
   - **無効にするダイアログも同じ形だった**（前回の指摘 2 の直しで、今の一覧の行を送るようにしていた）。メモの欄は開いたときのメモから作るので、開いたときの行（disableTarget）で送るように戻した。conflict・not_found ではダイアログを閉じる（前回の直し）ので、古い版で送り続けることはない。
   - E2E「シートを開いた後に一覧が読み直されても、開いたときの版で保存する」：`page.clock.install()` の後に `?code=S05` を開き、SQL で S05 の場所から 2-3 を外してメモを直す。時計を 31 秒進めて `setOffline(true→false)` で refetchOnReconnect を起こし、一覧の行にほかの人のメモが出るまで待つ。メモを直して保存すると「他の人が先に変更しました。読み直しました」で DB はほかの人のまま（場所 5 つ）、もう一度保存するとシートの内容（場所 6 つ）で上書きされる。直す前は1回目の保存がそのまま通って落ちた。
   - E2E「無効にするダイアログを開いた後に一覧が読み直されても、開いたときの版で送る」：同じ方法でダイアログの裏で読み直させ、「無効にする」→ ダイアログが閉じ、S04 は有効のままでほかの人のメモが残る。直す前は無効になり、メモが上書きされて落ちた。
