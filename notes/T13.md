### 2. 計算エンジン（設計 4 章、D-34）

| ファイル | 中身 |
| --- | --- |
| apps/web/workers/allocate.worker.ts | highs を1回だけ読み込んで使い回す。読み込みの失敗は覚えない（solver を null に戻す）。wasm の URL は highsWasmUrl。`self` は使う所だけの形で受ける（apps/web の tsconfig は DOM の型で、webworker の lib と同時に読めないため） |
| lib/allocation/protocol.ts | Worker との間のメッセージの型（warmup・allocate〔attempt つき〕／ready・load-error・progress・result・error） |
| lib/allocation/wasm-url.ts | `highsWasmUrl(origin, basePath, version, attempt)` → `${origin}${basePath}/highs.wasm?v=…`（attempt が 1 以上なら `&r=…`）。basePath は `/GAapp` の形にそろえる |
| lib/allocation/engine.ts | `createAllocatorEngine(makeWorker)`（テストは偽の Worker）と `getAllocatorEngine()`（アプリで1つ。`new Worker(new URL('../../workers/allocate.worker.ts', import.meta.url))` はここにだけ書く）、`useEngineState` |

- **Worker は1つだけ**：getAllocatorEngine はモジュールの変数に1つだけ engine を持ち、Worker は warmup・run を初めて呼んだときに作る。画面を離れて戻っても同じ Worker（読み込み済みならすぐ使える）。
- **読み込むのは管理者が振り分け中に画面を開いたときだけ**：画面は `isAdmin && status === 'allocating'` のときだけ getAllocatorEngine を呼んで warmup する。部員・閲覧のみと、振り分け中以外は Worker を作らない（E2E で highs.wasm の要求が 0 件のことを確かめた）。
- **読み込みの失敗を覚えない・URL に回数**：失敗した回数（attempt）は engine が数え、warmup・allocate のメッセージに入れて Worker に渡す。Worker は solver がないときだけ、その回数で URL を作って読み込む（engine.test.ts：失敗の後の要求で attempt が 1・2 と増え、同じ Worker の中で読み直す）。
- **load-error・例外は solver_error にそろえる**：読み込みの失敗は「計算エンジン（highs）を読み込めませんでした。通信を確かめて、もう一度実行してください。続くならページを再読み込みしてください」、allocate の例外は「計算中に予期しないエラーが起きました」、Worker の起動の失敗（onerror。チャンクの取得の失敗など）は「計算エンジンを起動できませんでした。ページを再読み込みしてください」で Worker を捨てる。詳しい中身は console.warn にだけ出す。
- **cancel（中止）**：Worker を terminate し、待っている run を EngineCancelledError で終える。次の run で Worker を作り直す（読み込みからやり直す）。
- **ログアウトで止める**：AuthProvider は T09a のファイルなので、getAllocatorEngine が Supabase の onAuthStateChange を聞き、SIGNED_OUT で dispose（terminate）する。
- **ビルドの確かめ**：`pnpm build` で Turbopack が Worker のチャンクを分ける（チャンクに `e.r(…)(Worker)`、`_next/static/media/highs.<hash>.wasm` も入る。設計 4.1 のとおり、ブラウザが取るのは `/highs.wasm?v=1.15.4` の1つだけ）。あわせて Worker の TS のソースがそのまま `_next/static/media/allocate.worker.<hash>.ts`（2 KB）として書き出される（`new URL(…, import.meta.url)` を資産としても扱うため。秘密は含まない。害はないが、気になるなら T14 で見る）。`next dev`（ポート 3271）でも Worker と wasm が動くことを、E2E をそのサーバーに向けて確かめた（開発のビルドは遅く、計算は 2089 ms だった。D-21 の判定は本番のビルドで行う）。

### 4. 画面 /allocation（設計 3.9、Q1・Q3）
- app/(app)/allocation/page.tsx：`<Suspense>` ＋ `<RequireAudience allow={['admin','staff','viewer']}>` ＋ AllocationScreen。**href ではなく allow にした**：確定前の閲覧のみに「振り分けは確定後に表示されます」を出すため（RequireAudience の href だと既定の権限なしの文になる）。出すのは ForbiddenState（題名は「権限がありません」のまま）なので、foundation.spec の「閲覧のみが R8 で開くと権限なし」は変わらない。
- components/allocation/：
  - allocation-screen.tsx：読み込み（useSnapshot〔admin・staff は full、viewer は public〕・useValidation・useVersionWatch〔計算中は止める〕・StaleBanner）、URL のクエリ（view・tab・row・group を zod で確かめ、合わない値は既定。移動は useGuardedRouter の forceReplace）、品目別・団体別の切り替え、`?row=` で開いたらその行のタブにして scrollIntoView・目立たせる、検証の一覧と precheck の項目から issueTarget で移動、上部のボタン（自動振り分け・最小変更で再実行〔自動の行が1行以上〕・Excel出力）、YearStatusActions（確定・確定を解除・終了。closeExtras に振り分け表の書き出し）、状態（受付中まで「締切の後に振り分けます」とホームへのリンク〔スナップショットも Worker も読まない〕・行がない「まだ自動振り分けをしていません」・部員の読み取りの帯・確定中の帯・終了の帯）。
  - auto-run.tsx：`useAutoAllocation(deps)`（段階 loading → preparing → solving → saving → reloading、中止、保存されたか分からないときの確かめ）と `AutoRunLock`（全面のオーバーレイ。段階と経過秒数。中止は loading・preparing・solving で 10 秒を過ぎたときだけ。saving は「（保存中…）」と「この段階では中止できません」）。計算中は useUnsavedChanges(true) で画面を離れるときに確かめる。
  - auto-result.tsx：FailurePanel（reason ごとの見出し。ルールのコードは AppLink で、開けない立場には文字だけ）と結果の表示（保存した件数・`data-testid="allocate-elapsed"`〔`data-elapsed-ms`・`data-load-ms`〕・除いた申請〔E006〕・保存の後の error・保存されていなかった・確かめられない〔「確かめる」〕・中止した）。
  - item-tab-view.tsx・group-view.tsx・issues-panel.tsx：品目タブの表（運び先・団体・品目〔2品目のタブと viewer〕・申請品目〔違うときだけ「…の代わり」〕・数・備考・自動／手動・固定）と余りの行（マイナスは赤で E001）、団体別の表（差の不足は E003、多いは W101）、検証の一覧（件数・コードで絞る・押すと移動・ルールは admin にリンク、staff にはコードと内容の文）。段 1 は行の操作を出さない（読み取りの表）。
- 自動振り分けの流れ：確認（「自動の行 N 件を置き換えます。固定・手動の行は残ります」・最小変更の文）→ ①読み込みが終わっていなければ warmup → ② loadSnapshot(yearId, 'full') で版から読み直し（React Query のキャッシュにも入れる）、buildAllocateInput、problems があれば止める → ③ engine.run → ok: false はパネル → ④ save_auto_allocations（`p_base_version` は②の版）→ ⑤ 読み直して検証 → toast「保存しました（追加 i・変更 u・削除 d、計算 0.28 秒）」。保存の前に validate を回さない（設計 3.9 の手順6）。`performance.measure('allocate', …)` に往復の時間と detail（elapsedMs・loadMs）を残す。
- **保存が拒まれたとき**：conflict・issue（E001・E002・E005）・not_found は スナップショットを読み直し、state・forbidden は年度の行と立場を読み直して ErrorBanner（`rpc: 'save_auto_allocations'` の文言、details の id は名前に）。自動でやり直さない。
- **保存の応答が届かないとき**（network・unknown。unexpected_response は除く）：版を読み直し、持っている版と同じなら「保存されていません。もう一度実行してください」、進んでいれば読み直して DB の自動の行（auto かつ未固定）を送った行と突き合わせ（autoRowsMatch）、同じなら「保存されていました」、違えば「ほかの人が変えました。もう一度実行してください」。版を読めなければ「保存できたか確かめられません。通信が戻ったら『確かめる』を押してください」で、確かめるまで自動振り分けを押せない。
- **中止の後**：版を読み直し、持っている版より進んでいればスナップショットを読み直す（読めなければ版の見張りに任せる）。
- **Excel 出力（Q3）**：admin・staff（part = full）。確定前は ConfirmDialog「確定前の振り分けです」（ファイル名の最後に「_確定前」を付けると説明）を出してから T09a の downloadAllocationXlsx（ファイル名は allocationExportFileName）。団体名が SUMIF に使えないときは ExportBlockedError の文言を toast。
- **計算時間（D-21）**：E2E（本番のビルド、ローカル）で result.elapsedMs は 297 ms と 625 ms（並行のテストの数で揺れる）。2000 ms 未満。wasm の読み込みは別に記録：`/highs.wasm?v=1.15.4` の応答まで 141〜157 ms、Worker の中の loadHighs（読み込みとコンパイル）177〜187 ms（localhost）。
- **最初に読む JS**（`pnpm build` → `node scripts/first-load-js.mjs`）：/allocation/ は 17 本・1152.4 KB・gzip 346.4 KB（validate を主スレッドで回すので allocator が入る。highs と ExcelJS は入っていない）。ほかのページは 14 本・gzip 268.7 KB（T09a の記録は 263.2 KB。T13 のコードはほかのページには入っていない）。

### 5. 決めたこと（新しい決定。notes/decisions.md は直さない。D-32）
- **T13-1 確定前の閲覧のみ**：RequireAudience を allow（admin・staff・viewer）で通し、画面が年度の状態で分けて「権限がありません」＋「振り分けは確定後に表示されます」を出す（設計 3.9 の状態の「確定後に表示されます」と、T09a の「確定前の viewer は権限なし」の両方を満たす）。
- **T13-2 確定中の帯の日時**：設計は「確定中（{日時}）」だが、年度の行に確定の日時の列がない（years は auto_allocated_at だけ。確定の時刻は audit_logs にあり、admin しか読めない）。段 1 は日時を出さず「確定中です。直すときは「確定を解除」してください。」にした。出すなら段 3 で audit_logs（admin）から引くか、DB に列を足す（T03 の領分）。
- **T13-3 自動振り分けの保存の応答が届かないときの突き合わせ**：設計は「版を読み直し、進んでいれば読み直して『保存されていました』か『ほかの人の変更』かを知らせる」まで。判定は DB の自動の行（origin = auto かつ未固定）と送った行の、運び元・団体・品目・申請品目・残すごとの数の合計が一致するか（save_auto_allocations は全部か何もないかで、自動の行を全部入れ替えるため）にした。
- **T13-4 部員の Excel 出力**：Q1 のとおり部員も出せる。確定前は管理者と同じ確認を出す。
- **T13-5 計算中の移動**：計算中・保存中は useUnsavedChanges(true) で、アプリの中の移動・年度の切り替え・ログアウトの前に確かめる（送った保存は止まらないため）。オーバーレイは全面で、ナビも押せない。
- **T13-6 品目タブ・団体別の切り替えは URL**（`?view=item&tab=desk`・`?view=group&group=…`）。移動は useGuardedRouter の forceReplace（同じ画面の中の切り替えなので確かめない。段 2 の未保存の変更は画面の状態に残る）。
