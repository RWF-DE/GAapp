## 目的とユーザーの決定（承認された計画）

1. 表示名：ロールは管理者（admin）・総務部門長（head）・総務副部門長（deputy_head）・総務部門員（staff）・閲覧のみ（viewer）。団体代表の立場は店長（manager）・副店長（deputy_manager）で、「{団体} の店長」「{団体} の副店長」と出す（「{団体} の団体代表」に代える）。
2. 段：LEAD（部門長以上）＝ admin・head・deputy_head、SOUMU（総務）＝ LEAD と staff。画面の判定はすべて新しい apps/web/lib/auth/roles.ts の一覧と関数から作り、画面ごとにロールの配列を書かない。
3. ナビ：/settings・/rules・/swaps・/history は LEAD、/stock・/stocks・/stocks/qr・/requests は SOUMU、/allocation は SOUMU と確定・終了の年度の viewer（finalOnly）。/request・/my は今のまま（rep）。/allocation のページも表から引く（href で守る）。
4. 業務の判定は admin → LEAD（振り分けの編集・実行・確定、申請一覧の締切後の編集など、在庫の振り分け中以降の数え直し、振り分け画面の部屋の使用不可）。マスタの判定は admin のまま（在庫一覧・部屋の選択のマスタへの案内、年度の作成、場所・品目・距離・団体の書き込み）。ルールの読み取り（場所の削除の前の確かめ）は SOUMU。
5. 年度の状態のボタン（YearStatusActions）は LEAD に出し、終了とその確認の書き出しは admin だけ。ホームは SOUMU にダッシュボード。
6. マスタ設定（LEAD）：admin はすべてのタブ。head・deputy_head は年度（受付期間だけ変えられる。年度名・1日目は読み取り、作成はない）・場所（今年の使用だけ）・ユーザー。ほかの `?tab=` は開けるタブの最初へ。ユーザーのタブは段で分ける（下の表）。04 の「メールアドレスを見られる人」を管理者・部門長・副部門長に直す。
7. 履歴：group_members の role は店長・副店長、year_roles の role は新しい表示名。
8. テスト：Vitest と E2E（seed に head@example.test、使い捨ての deputy_head、新しい e2e/t15b-roles.spec.ts）、スクリーンショット（e2e/shots/T15b.shots.ts → notes/T15b/）。

## 画面ごとの細部

### 共通：roles.ts・立場・ナビ・ページの守り・リンク

- **lib/auth/roles.ts（新しい）**：`APP_ROLES`（列挙の順。admin, head, deputy_head, staff, viewer）、`LEAD_ROLES`、`SOUMU_ROLES`、`GROUP_ROLES`（manager, deputy_manager）、`isAdmin(role)`・`isLead(role)`・`isSoumu(role)`（null は偽）、`manageableRoles(actor)`（admin → APP_ROLES、head・deputy_head → ['staff']、ほか → []）、`inviteKindsFor(actor)`（manageableRoles に、LEAD なら GROUP_ROLES を足したもの）。型と相対の import だけにする（lib/labels.ts・lib/errors.ts は E2E〔Node〕からも読むので `@/` を使わない。membership.ts と同じ）。
- **membership.ts**：ROLE_LABELS を 管理者・総務部門長・総務副部門長・総務部門員・閲覧のみ に。`GroupRole` 型と `GROUP_ROLE_LABELS`（店長・副店長）。`GroupSummary` に `role: GroupRole`。`groupPositionLabel(g)`（「{団体名} の店長」）。ROLE_ORDER（lib/data/settings.ts）は APP_ROLES の順から作る。lib/labels.ts は GROUP_ROLE_LABELS も出し直し、FIELD_LABELS に `group_role: '店長・副店長'`。
- **load-membership.ts**：group_members を `group_id, role, groups (id, name, year_id)` で読み、`{ ...groups, role }` にする（T14 の先送りは URL ごとに覚えるので、select が変わっても古い記録は当たらないだけ）。GroupSummary の role は必須にし、テストの立場の団体には manager を書く。
- **lib/navigation.ts**：audiences を roles.ts から作る（ALL＝[...APP_ROLES, 'rep']、LEAD、SOUMU、/allocation は [...SOUMU, 'viewer'] で finalOnly ['viewer']）。マスタ設定のタブ `SETTINGS_TABS`・`SettingsTab`・`settingsTabsFor(role)`（admin → 7つ、head・deputy_head → years・rooms・users、ほか → []）をここに置き（canOpen が使うので、データの層〔lib/data/settings.ts〕から import しない。lib/data/settings.ts は出し直す）、`canOpen` は `/settings?tab=X` なら立場のどれかの settingsTabsFor に X があるときだけ真（tab のない /settings は今までどおり）。
- **RequireAudience**：今のまま href で表から引く。立場が finalOnly だけで外れたとき（確定前の閲覧のみ）は、ForbiddenState に「振り分けは確定後に表示されます。」を添える（T13-1 の文言。題名は「権限がありません」のまま）。app/(app)/allocation/page.tsx は `allow={['admin','staff','viewer']}` をやめて `href="/allocation"` にする。allocation-screen.tsx の中の確かめ（SOUMU でなく viewer なら確定前は同じ文言）は二重の守りとして残す。
- ヘッダー（app-shell の roleSummary）とホームの立場（role-summary の home-roles）：ロールの表示名と、団体ごとの groupPositionLabel。home-roles はほかの文字を入れない約束のまま（E2E が toHaveText で見る）。

### マスタ設定

- settings-screen.tsx：`tabs = settingsTabsFor(m.role)` を出し、`?tab=` は tabs にあればそれ、なければ tabs[0]（URL は書き換えない。今の parseSettingsTab と同じ扱い）。終了した年度の帯は、管理者「終了した年度のため、読み取り専用です（ロールを外す・店長・副店長を外す・招待の取り消し・新しい年度の作成はできます）」、部門長・副部門長「終了した年度のため、読み取り専用です（総務部門員のロールを外す・店長・副店長を外す・招待の取り消しはできます）」。
- 年度のタブ（years-tab.tsx）：年度名・1日目の欄は `isAdmin(membership.role)` のときだけ書ける（ほかは readOnly）。yearPatch は変えたキーだけを送るので、部門長・副部門長の patch は受付期間だけになる（DB の update_year も、admin でない人のほかのキーを forbidden にする）。説明の文は、部門長・副部門長には「申請の受付期間を変えます（年度名と1日目は管理者が変えます）。受付開始の前に締切を入れてください（受付中は締切を空にできません）」。作成の欄は今の canCreate（その年度の admin で最新の年度）のまま、ほかの人には今の「新しい年度は、最新の年度（…）を開いて、その年度の管理者が作れます。」を出す。
- 場所のタブ（rooms-tab.tsx）：変えない見込み。今年の使用の「変える」は yearWritable（終了していない）、追加・編集・削除は globalWritable（開いている年度のどれかの admin。D-01）で、部門長・副部門長だけの人には一覧を読み取りで出す（GlobalReadOnlyNote の「開いている年度の管理者でないため、場所は編集できません。」も今のまま）。振り分け中の今年の使用の守り（固定・手動の行があれば振り分け画面へ）も今のまま（振り分け画面は LEAD が開ける）。
- ユーザーのタブ（users-tab.tsx）：
  - 招待のフォーム：立場の選択肢は `inviteKindsFor(role)`（表示は ROLE_LABELS と GROUP_ROLE_LABELS）。店長・副店長を選んだら団体を選ぶ（今の rep と同じ欄）。送るのは `p_role`、または `p_group_id` と `p_group_role`。INVITE_KINDS は `[...APP_ROLES, ...GROUP_ROLES]`（'rep' をやめる）、inviteFormSchema は選べる立場を受け取る形（`inviteFormSchema(kinds)`）にし、出力は `{ email, role, group_id, group_role }`。既定の立場は staff（どちらの段にもある）。送った後は同じ立場と団体を残す。

## 判断したこと（承認された計画にないもの）

1. **マスタ設定のタブへのリンクも段で出し分ける**（D-50）：canOpen が `/settings?tab=X` の X を settingsTabsFor で見る。部門長・副部門長に、開くと年度のタブに戻る「マスタ設定の団体へ」などのリンクを出さないため（04「画面の中のリンクは、行き先の画面を開ける立場のときだけリンクにする」）。tab のない /settings と、ページの守り（RequireAudience）は今までどおりパスだけを見る。
