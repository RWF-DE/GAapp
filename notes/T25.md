## 判断したこと（DB）

1. path は bucket room-photos の中の `{year_id}/{room_id}/{photo_id}.webp`（JPEG は .jpg）。計画の「room-photos/{year_id}/…」の room-photos は bucket の名前として読み、名前の先頭には付けない（documents の bucket の `{year_id}/…` と同じ形。1つ目のフォルダが年度なので、Storage のポリシーが split_part で年度を取れる）。
2. 写真の行の id は予約の id（photo_id）と同じ。add_room_photo の送り直しは、その id の行があればそれを返す（メモは変えない）。行がもうなければ（消した後）invalid_state（used）。
3. select のポリシーは D-47 の形（行の列を判定関数に渡さない）にするため、集合の関数 `private.room_photo_year_ids()`（can_see_room_photos が真の年度と、その prev_year_id の年度）を足した。013 の「storage.objects のポリシーは、行の列を判定関数に渡さない」の決まりにも合う。計画の「can_see_room_photos を select のポリシーで使う」は、この集合の関数の中で同じ条件を使う形にした。can_see_room_photos と can_write_room_photos は RPC の中からだけ呼ぶので、誰にも execute を与えない。
4. 前の年度は select のポリシーでも読める（1つ前だけ）。Storage の署名つき URL を作るのに Storage の select のポリシーが前の年度の物を許す必要があり、表の select もそれとそろえた。room_photos_with_previous は、今の年度で見られる人にだけ2年度分を返す（見られなければ 0 行。エラーにしない）。
5. room_photos.room_id は restrict（場所への参照の決まり。写真のある場所は消せない）。予約の表の room_id は cascade（品目の画像の予約と同じ）。year_id はどちらも cascade。
6. 6 枚の上限は BEFORE INSERT のトリガー（年度と場所ごとの勧告的ロック）。reserve_room_photo も先に数えて too_many_photos を返す（6 枚あるのに上げさせない）。add_room_photo は送り直しを先に見て、新しい行だけがトリガーで止まる。
7. 終了の年度は、ロールの確かめの後に invalid_state（detail は status。提出物の lock_document_year と同じ形）。年度の行は for share でロックしてから見る。update・delete で写真がないときは、どの年度の総務でもなければ forbidden、そうでなければ not_found（有無を漏らさない）。
8. memo は `not null default ''`、50 字まで、制御文字（改行を含む）なし（CHECK と RPC の invalid_input〔field: memo〕）。前後の空白は画面が除く。update_room_photo の null の引数は変えない。sort_order は 0〜1000。
9. 監査は room_photos だけ（tg_audit('id')）。予約の表は監査しない（T23 と同じ）。year_id・room_id・object_path は check_immutable。振り分けの版・確定中の守りは付けない。
