### 3. 画面（apps/web/components/settings/、app/(app)/settings/page.tsx）
- page.tsx は `<Suspense>`＋`<RequireAudience href="/settings">`＋SettingsScreen だけ。
- settings-screen.tsx：タブは `?tab=years|rooms|items|groups|distance|users|export`（合わない値は years）。切り替えは useGuardedRouter の replace（未保存の入力を確かめる）。選んだタブだけを描く。closed の年度は ReadOnlyNotice。
- shared.tsx：SettingsContext（year・membership・yearWritable〔closed でない〕・globalWritable〔adminOfOpenYear〕）、useWriteErrorHandler（2.5・2.6 の扱い：toast、forbidden・state・network・unknown は年度の行と立場を読み直す、conflict・not_found は渡したキーを読み直す、auth は useAuthErrorHandler）、Field（ラベル・説明・エラー）、FormSheet（追加・編集のシート）、TabHeading、settingsKeys（クエリのキー）。
- years-tab.tsx：今の年度の変更（update_year。変えたキーだけ、理由は任意。invalid_input の festival_start・request_close_at・reason と conflict の label は欄に出す）。新しい年度の作成（開いている年度が最新で自分がその年度の admin のときだけ。closed でも出す。複製される・されないものを書く。invalid_input の details なしは年度名と1日目の両方の欄に 2.5 の文言。作ったら toast に無効になったルールの件数とコード、立場を読み直して新しい年度に切り替える）。
- rooms-tab.tsx：表（名前・別名・種類・建物・階・保管場所・追加コスト・並び順・今年の使用）。追加・編集・削除は globalWritable のときだけ（「すべての年度に効きます」）。今年の使用（room_years）は yearWritable のときの「変える」から。振り分け中で固定・手動の行がある部屋、確定中で振り分けの行がある部屋は、使用不可にする保存を押せなくし、振り分け画面へ案内（確定中は解除を案内）。削除の確認は DeleteWithRefsDialog。
- items-tab.tsx：追加・編集（コードは作った後は読み取り専用、送らない）。削除は出さない。
- groups-tab.tsx：表（代表者の数つき）、追加・編集（保存の前に年度の全団体〔編集後〕で checkGroupNames）、削除（DeleteWithRefsDialog。確定中は削除のボタンを出さず、区分・使用場所は読み取り専用）、CSV の取り込み（groups-csv-dialog.tsx：UTF-8 → Shift_JIS で読み、プレビュー〔追加・変更・変わらない・エラーの件数、行ごとの扱いと変わる項目〕、エラーか名前の誤りがあれば保存を押せない）。
- distance-tab.tsx：距離の上書きの表と追加・編集（建物は場所の建物の datalist から、自由入力も）・削除。23505 は「その組はすでにあります」を欄に。場所ごとの追加コストは一覧だけ（場所のタブへのリンク）。
- users-tab.tsx：招待（closed では出さない。applied で文言を分け、偽でも「アカウントがない」とは言わない。D-17a）、メンバー（表示名・ロール・代表する団体。ロールを変える〔closed では出さない〕・ロールを外す・代表を外す〔closed でも〕。理由は任意）、招待の一覧（未使用は取り消せる。closed でも）。自分のロールを変えたときのため、操作の後に立場を裏で読み直す。

### 5. 決めたこと（新しい決定。notes/decisions.md は直さない。D-32）
- **クエリのキー**：マスタ設定のキーは最後に `'settings'` を付ける（`['rooms','settings']`、`['year', id, 'settings', 'groups']` など。shared.tsx の settingsKeys）。並行するチケットが同じキー（`queryKeys.rooms()` など）に別の形のデータを置いてもぶつからないため。書いた後は前の部分（`queryKeys.rooms()`・`queryKeys.year(id)`）で invalidate し、ほかの画面のキャッシュも読み直させる。場所・品目・距離の変更は `['year']` 全体も invalidate する（全年度のスナップショットに効くため）。
- **列挙の選択はネイティブの select**（Input と同じ見た目の class）。団体・場所の選択は EntitySelect。
- **追加・編集のシートは閉じたら外す**（FormSheet）。閉じる動きの途中に次のシートを開くと、前のシートがフォーカスを戻して新しいシートが閉じた（E2E で再現）。
- **react-hook-form で読み取り専用にする欄は disabled にしない**（値が送られなくなるため）。年度の欄は readOnly、確定中の団体の区分は登録しない読み取り専用の Input。
- **無効になったルールの数**：create_year_from は年度の行だけを返すので、作った後に複製元と新しい年度のルールを読み、複製元で有効・新しい年度で無効のコードを数える。
- **団体の CSV**：既存の団体とは団体名が完全に同じときだけ同じ団体とみなす（大文字・小文字などだけが違う名前は checkGroupNames の誤りとして止める）。使用場所の列が空なら「校内に分散」（null）で上書きする（見出しの決まりのとおり）。upsert は楽観ロックを使わない（全部か何もしないかの1回）。
- **今年の使用の守り**：振り分け中は固定・手動の行、確定中は振り分けの行（DB の確定中の守りと同じ条件）がその部屋からあれば、マスタ設定では使用不可にする保存を押せない。
- **団体の削除**：確定中は削除のボタンを出さない（DB が invalid_state で止める）。
- **年度の作成の後の切り替え**：作成のフォームを reset してから、描画で「未保存の入力」の印が消えるのを待って（setTimeout 0）useGuardedSetYear で切り替える（待たないと切り替えの確かめが出る）。
