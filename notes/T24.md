## 承認した計画の要点（2026-11-10。D-62）

- 提出物（documents）に `submit_url` を足す。任意。https だけ、500 字まで。部門長以上が提出物の登録・編集で入れる（共有ドライブのフォルダ、Google フォーム）。
- /document：「提出先を開く」のリンク（新しいタブ、rel=noopener noreferrer）と「提出した」。ファイルを上げる欄は出さない。
- /documents：承認・差し戻し・代理の提出は今のまま。ファイル欄（上げる欄）は出さない。
- やめるもの：新しいファイルの予約（reserve_document_file）は invalid_state `uploads_disabled`。requires_file はすべて false にして画面から外す（列は残す。トリガーで true にできないようにする）。
- 残すもの：すでに上がったファイルは見る・消すことができる。年度のファイルの削除と片付けも残す。
- 容量：02 の容量の表を「提出物 0（ドライブ）・品目の画像 100 MiB・部屋の写真 800 MiB」にする。
- 誰が出せるか・見られるかは、ドライブの権限（学校の Workspace の共有の設定）で決まる。04 にそう書く。

## 判断したこと

1. requires_file のトリガー（keep_requires_file_off）は、true を 23514 で拒まずに false に直す。理由：古い画面（キャッシュの残った PWA）や SQL Editor から true が来ても書き込みを止めない。「true にできない」は直した後の値で確かめる（033）。
2. submit_url の CHECK は「`https://` で始まり、その後に1字以上、空白・制御文字（`[[:space:][:cntrl:]]`）を含まない、500 字まで」。https の形だけを見て、ドメインは見ない（学校のドライブ以外のフォームも使えるように。中を見られるかはドライブ側で決まる）。画面は前後の空白を除き、空なら null にしてから同じ形を確かめる。
3. v_document_status は `create or replace view` で最後に submit_url を足す（店長・副店長の /document は documents でなくこのビューを読む）。ほかの列・where・security_invoker は変えない。
4. reserve_document_file は、今の lock_document_year（ロール → 年度の行 → 終了なら invalid_state）の後で、いつも invalid_state（detail: `{"reason": "uploads_disabled"}`）。入力の形・送り直しを見る前に止める（同じ file_id の送り直しも止まる）。引数・戻り値・権限は変えない（型と RPC の一覧を変えない）。
5. copy_previous_documents は submit_url も写す（requires_file は写すが、トリガーで false になる）。previous_year_documents の返り値（requires_file を含む）は変えない（返り値の型を変えると drop と作り直しが要る。画面は requires_file を使っていない）。
6. Storage の守り（documents_objects_guard・ポリシー）は変えない。T24 の前の、届いていない予約の path にはまだ上げられるが、増えない（予約は止めた）。画面は「もう一度」を出さないので、届いていないものは外すだけ。
7. document_storage_usage は変えない（上限 900 MiB の値を返すが、ダッシュボードの使った量の表示はそのまま。T24 の前のファイルの数・大きさと、片付けていない物の数を出すため）。
8. pgTAP の 026・027 は、予約を前提にしていた所を直した（T19 の確かめを T24 の形に合わせる）：026 の ① の予約の行は uploads_disabled（呼べる人は IS）、② の予約の細部（入力の順・path・送り直し・5 つ・too_many_orphans・900 MiB）と ⑨ の予約の例外の直しは消した（止めたことは 033）。後の節が使う T24 の前のファイルの行は、予約の代わりに `tests.add_file` で postgres が直接入れる（0016 の予約と同じ行）。no_file の確かめは消し、① の「ファイルなしの提出」の行は ok にした。027 の ⑤ の流れの予約は、rep の予約の行を postgres が入れる形にした（上げる・届いた・外す・消すは今までどおり）。
