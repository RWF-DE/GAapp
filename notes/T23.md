## 承認した計画の要点（2026-11-10。D-61）

- 物を画像で選べるようにする。一覧にない物は「その他」で写真を撮って登録する。
- 画像を出す所：備品（数えるだけ）、机椅子の 9 品目（在庫入力）、団体の申請画面（/request）。
- 写真つきで新しい物を登録できる人：在庫を数えられる人全員（add_count_item と同じ段）。
- 画像はなくてもよい。名前だけで登録でき、画像は後から足せる。画像のない物は名前だけのカードで出す。

## DB の形（0022）

- 列：items.image_path・count_items.image_path（null なら画像なし。CHECK でその行の id のフォルダの形に固定）。
- 予約：item_image_uploads（id は画面が作る。item_id か count_item_id のどちらか1つ。object_path は DB が作る。content_type は image/webp か image/jpeg。created_by・expires_at〔1 時間〕・used_at・replaced_path）。RLS：select は自分の予約だけ。書き込みの権限なし（RPC だけ）。
- Storage：非公開の bucket item-images（1 MiB・WebP・JPEG）。storage.objects のポリシー item_images_objects_select（has_any_access）・_insert（自分の生きた予約の path）・_delete（どの行にも使われていない物）。update のポリシーなし。トリガー item_images_objects_guard（RLS を通らない書き込みも予約で止め、上書き・移動を止める）。
- RPC：reserve_item_image(kind, target_id, image_id, content_type)・set_item_image(kind, target_id, image_id)。
- トリガー check_image_path（items・count_items）：RPC の外から image_path を変えさせない。
- 版の増分の関数を置き換え、set_item_image の items の画像だけの変更では版を上げない。

## 判断したこと

1. reserve_item_image は計画の3つの引数に content_type を足した4つ（`reserve_item_image(kind, target_id, image_id, content_type)`）。bucket は WebP と JPEG を許し、WebP を作れない端末は JPEG で上げるので、path の拡張子（.webp・.jpg）と予約の形を DB でそろえ、トリガーが metadata の mimetype と予約の形の違いを止める（reason: type）。
2. 予約は表 item_image_uploads（public・RLS 有効・select は自分の予約だけ・書き込みの権限なし）。対象は item_id か count_item_id の外部キー（cascade）で持ち、kind と target_id の組にしない（行を消したときに予約も消え、別の表の id を取り違えない）。object_path の形は CHECK で固定する（document_files と同じ）。
3. 段は年度を選ばずに見る：count_item は新しい `private.can_write_stocks_any()`（can_write_stocks と同じ条件を、終了でない年度のどれかで）、item は `private.is_admin_of_open_year()`。どちらでもない人は kind の確かめより先に forbidden（「最初にロールを確認」）。予約・画像にする・外すのどれも同じ段（計画の「count_item なら作った段の人が外せる」は、名前を足せる段と読んだ）。
4. 予約の送り直し：同じ id・同じ中身（kind・対象・形・予約した人）ならその行を返し、期限が切れていてまだ上げておらず使っていなければ期限を 1 時間延ばす（「期限切れにして再予約できる形」）。中身が違えば invalid_input（image_id・in_use）。
5. 上限：1人の上げていない生きた予約は 10 個まで（too_many_reservations）。bucket の合計（届いた物の size ＋ 届いていない生きた予約 × 1 MiB ＋ 今回 1 MiB）は 100 MiB まで（storage_full）。documents の 900 MiB と合わせて 1000 MiB で、無料プランの 1 GB を超えない。勧告的ロック `gaapp.item_images` で予約どうしを順にする。
6. set_item_image の送り直し：予約に used_at と replaced_path を残し、使った予約で行の画像がその物のままなら同じ前の path を返す（画面が前の物を消し損ねない）。行の画像がもう別の物なら invalid_state（used）。外す（image_id が null）でもう画像がなければ行を変えずに null を返す（監査に空の変更を残さない）。
7. image_path の守り：トリガー check_image_path（BEFORE INSERT OR UPDATE OF image_path。SECURITY DEFINER。private.fail を呼ぶため）が、ログインしている人の書き込みで transaction-local の `app.item_image` が立っていなければ invalid_input（column: image_path、reason: immutable）で止める（app.keep_submitted_at と同じ形）。seed・SQL Editor では入れた値のまま。
8. 版：0022 で private.tg_bump_allocation_version を置き換え、`app.item_image` が立った items の書き込みでは版を上げない（ほかの枝は 0002 のまま）。名前など画像以外の items の変更は今までどおり上げる（032 で両方を確かめる）。
9. Storage の delete：どの行にも使われていない物で、フォルダの段（items は管理者、count-items は在庫を書ける人）がある物。ほかの人の生きた予約で上げた物（set の前）は消せない（上げた直後に他人が消して set が not_uploaded になるのを防ぐ）。自分の物は消せる（あきらめた写真の片付け）。
10. トリガー item_images_objects_guard は、予約の行を for share でロックしてから、予約・期限・使ったか・予約した人の段・形を見る（documents_objects_guard と同じ考え方で、予約した人〔created_by〕の段で見る）。update は bucket item-images の物の名前・bucket・版・metadata の変更をいつでも止める。
11. 共有の fixture に、staff の期限の切れた予約 IU_STAFF を1つ足した（011 の権限表の select のセルに中身を持たせるため。032 の上限・合計には数えない）。Storage の物は置かない（027 の見える物の一覧を変えない）。013 の⑤（Storage の比べ方）は、013 の中で bucket item-images の予約と物を足して比べる。
