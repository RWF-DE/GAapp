## 承認した計画の要点（2026-11-09。D-60）

- ゴミ箱・延長コード・扇風機・オレンジ椅子の4つは、在庫入力のすべての場所に最初から行を出す。
- ほかは「その他」から選ぶ。選択肢になければ名前を自由に書け、書いた名前は次から（ほかの部屋・翌年も）選択肢に出る。
- どれも数えるだけ。申請・振り分け・Excel・検証・ダッシュボードには入れない。
- 数は在庫入力と在庫一覧（/stocks）に出し、前年の数も出す。

## DB の形（0021）

- count_items（年度をまたぐ名前の一覧）：id・name（1〜50 字。前後の空白なし。lending_items と同じ 25 文字の式）・always_shown・sort_order・created_by（トリガー set_actor）・作成と更新の日時。NFKC・小文字の名前に一意の索引 count_items_name_key。マイグレーションで always_shown の4つ（並び 1〜4）を入れる。
- count_stocks（年度×保管場所×物）：year_id・room_id・count_item_id・count（0〜10000）・counted_by・counted_at（トリガー set_counted。stocks と同じ形）。主キーは3つの組。場所と物へは restrict、年度へは cascade。
- RLS：count_items の select は has_any_access、insert・update・delete は is_admin_of_open_year（items と同じ）。count_stocks の select は stocks と同じ（D-47 の形。総務）、insert・update・delete は can_write_stocks。
- RPC：add_count_item(year_id, name)（can_write_stocks を最初に確かめる。同じ名前ならその id）、previous_year_count_stocks(year_id)（previous_year_stocks と同じ形）。
- 付けないもの：版の増分（bump_version_*）、確定中の守り（guard_confirmed）。年度の作成・年度データの JSON・スナップショットにも入れない。

## 判断したこと

1. add_count_item の拒否は forbidden だけにする（終了の年度・振り分け中の部員も）。can_write_stocks が段と年度の状態をまとめて答え、在庫の直接の書き込みの拒否（RLS）とそろうため。invalid_state に分けると、書けない理由を段ごとに読み分ける分の処理が増え、画面の出し分け（読み取り専用）でもともと呼ばない。
2. 名前の誤り（null・空・前後の空白・51 字以上）は invalid_input（detail は field: name）。DB は除かずに拒む（画面は zod の trim を通してから送る。lending_items と同じ）。
3. count_items の履歴：年度を持たないので、そのままでは誰も読めない（audit_logs_select は年度のない行を rooms・items・distance_overrides だけに許す）。品目と同じ扱いにするため、0021 で audit_logs_select を作り直し、年度のない行の一覧に count_items を足す（ほかの枝は 0013 のまま）。
4. count_stocks の check_immutable は year_id・room_id・count_item_id（鍵の列は全部変えない。lending の子の表と同じ）。count_items は年度がないので付けない。
5. count_stocks の delete も在庫と同じく can_write_stocks で許す（画面は使わないが、在庫と同じ権限の形にする）。
