## 実装で決めたこと（設計の gap check で残った low）

- **requests.csv の意味**：fixtures/r8 と r8like の両方で「DB の requests に入る申請（取り込みの後・代替の前）」とする。取り込みは企業以外の長机(3人掛)を読み替えて保存するが、DB に長机(3人掛)のまま残っていてもよい（D-05）ので、どちらの形も許す。r8like は前処理の読み替えを通すため、模擬店06 の長机(3人掛) 2 を読み替えの前のまま置く（T00 のまま）。テストの需要の期待値は、どちらの形でも読み替えを明示的に当てて作るので同じ値になる。fixtures/synthetic/r8like/README.md に書いた。
- **scripts の依存**：ルートの package.json の devDependencies に `@gaapp/shared`・`@gaapp/allocator`（workspace:*）、`highs` 1.15.4、`tsx` 4.23.15 を足した（pnpm の厳密な解決で scripts/ から見つかるように）。highs の版は allocator の devDependencies とルートの2か所（apps/web は T13 で足す）。shared の index.test.ts が HIGHS_VERSION と全部の package.json の版の一致を確かめる。
- **時間のかかるテスト**：Vitest の既定（5 秒）を超えるものだけに個別のタイムアウトを付けた。最小変更の 90 通り（約 32 秒、上限 300 秒）、シード 100〜129 の不変条件（約 2 秒、上限 120 秒）、総当たり（約 0.5 秒、上限 120 秒）、20 通りの並べ替え（約 2 秒、上限 60 秒）、段ごとの検算（約 0.6 秒、上限 60 秒）。`pnpm test` 全体は手元で約 35 秒（CI の check ジョブの上限 10 分に十分収まる）。
- **入力の細部**（allocate の前処理0。どれもテストあり）：
  - stocks に同じ場所・品目の行が2つ → invalid_input（DB の主キーと同じ。足すと二重に数えうる）。requests の同じ団体・品目の行は足す（設計 5 章 P1）。consents の同じ (団体, from, to) → invalid_input。
  - mode が full で previousRows が空でない → invalid_input（呼ぶ側の誤り）。
  - fixedRows に origin = auto かつ pinned = false の行 → invalid_input（固定行は pinned か manual だけ）。
  - distance_overrides に同じ建物どうし・同じ組が2つ → invalid_input。
  - rules.json の `enabled: false` のルールは toYearData で YearData に入れない（DB から組み立てる入力と同じく有効なルールだけ）。
  - allocate の型は `allocate(input: AllocateInput, solver, opts?)`。実行時にも zod で確かめる（Worker の境界のため）。
- **makeInfeasibleS05 の「減らした分を足す場所」**：S05 以外で机(木)のある最初の場所（sort_order の順）。T00 の実装（在庫の配列の順）とは場所が違うが、T07 の診断の期待値（設営・机(木)・241・235）には影響しない。
- **W107 の判定の返り値**：findW107 は T00 の定義で見つかった組をすべて返し、`swappable`（D-20 の定義に当たるか）を付ける。T07 は swappable のものだけを Issue にする。
