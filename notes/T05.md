## 判断したこと

- **列の対応表（FORM_COLUMN_MAP）は仮**。本物のフォームの見出しを見ていない。タイムスタンプは「タイムスタンプ」、団体名は「団体名」「部門名」で始まる列（模擬店は複数列のうち空でない方）、備考は「備考」で始まる列、品目は見出しに items.aliases（NFKC・空白除去・長い方を優先）を含む列。合わなければ、必要な列がないという失敗（中身を含まないメッセージ）か ignoredColumns に出る。本物のフォームの CSV を取り込むときに見出しを突き合わせる（D-40）。直すのは parse.ts の対応表だけ。
- ParsedForm.rejected の reason に `invalid_timestamp` を足した（設計 3.7 は misaligned・invalid_number・empty）。タイムスタンプが読めない行を、静かに捨てずに行番号つきで返すため。
- 数の列にメールがある行は `misaligned`（列がずれた行）にする。団体名・備考の中のメールは、その部分だけ取り除く。ほかの列（対応表にない列）は読まない。見出しがメールのパターンなら `(列N)` にする。
- 全角の数字・「3台」のような単位つきは読む。負数・小数・MAX_COUNT 超えは invalid_number。
- resolveResponses：名前・別名が 2 つの団体に当たる表記は対応させず unmatched にする。手で選んだ団体 id（manual）は名前より優先し、存在しない id は unmatched。申請できない品目で読み替え先もないもの（E006 候補）はそのまま残す。0 の行は持たない。出力は団体の入力順 → 品目の sort_order。
- CSV のパーサは importer に自前（ブラウザで動くため shared/testing は使えない）。行番号はレコード番号（セル内の改行は数えない）。
- 共通基盤（shared・shared/testing）は変えていない。scripts は importer を相対パス（`../../packages/importer/src/index`）で読み、ルートの devDependencies を増やさない（T07・T08 と package.json が衝突しないように）。
- build の入力の形（R8_SOURCE_DIR）は設計書にないので決めた（上の README の表）。元データの実際の形に合わせて直す。company.csv は行ごとに団体を選ぶ必要があるので company_map.csv（row,group）を別に置く。
- build の失敗：フォームの取り込めない行・対応しない行は既定で失敗（`--allow-rejected` で飛ばして続行）。想定外の例外は種類の名前だけを出す。ただしフォーム・CSV の形が読めない失敗（見出しが合わない・引用符が閉じていない）は、importer の `ImportFormatError`（メッセージに元データの値を入れない）で投げ、build が `forms/<種類>.csv: …` の BuildError にして表示する。
- reference の「残す」の行（S08）：運び元の部屋が rooms.csv で usable = false なら除く。使える部屋なら、manual/groups.csv で location がその部屋の団体の行にする（当たる団体がない・複数あるときは行番号つきで失敗）。計・合計・余り・使用不可と reference_skip.csv の使用用途は除く。団体別集計（allocation_totals）の「残す」の行は団体ではないので除く。
- 分ける団体（剣道部）は manual/settings.json の `splitGroups`（元の名前 → 並び順の団体名の配列）で指定する。申請より多い分は配列の最後の団体に付ける。分けた後の品目ごとの合計は、表の行の合計と一致するかを確かめる。集計シートの値と違うときは、2 団体とも group_totals.csv から除く。
- group_totals.csv は、集計シートにない団体は 0 として比べ、一致した団体を全部載せる（T08 の「載っている団体の数 = 団体数 − 除いた数」を成り立たせるため）。
- 備考は「キャスター机に交換」だけを許す（settings.json の allowedNotes で足せる）。それ以外は文言を出さず失敗。
- メールの検出（sanitize.ts）は、@ ごとに左右へ伸ばす方式（正規表現で local 部を先に探すと、@ のない長い列で時間が二乗になるため）。@ の前後の空白（8 字まで）と、ドメインの区切りの「。」を許す。local 部は長さを切らず全体を取り除く（5 万字のセルが 100ms 未満）。「。」を区切りに許すため、直後に日本語が続くと（`…。com。以上`）その続きの文字も取り除く（取りこぼすより多く取り除く側に倒した）。
- 読む列（団体名・数・備考・タイムスタンプ）のいちばん右の位置まで届かない短い行は `misaligned`（足りない列を 0 として取り込まない）。
- build：完全に空の行（reason が `empty`）は失敗にせず、件数だけを report（`空の行（取り込まない）`）に出す。anonymize.csv の source_name が manual/ の名前の欄（groups.csv の name・aliases・display_name、reference_skip.csv の use、settings.json の splitGroups のキー）に入っているときは、値を出さず anonymize.csv の行番号とファイル名・欄だけで失敗する（元の名前が fixtures に出るのを防ぐ）。reference_skip の use は匿名化の後の名前で当てる。

## マージの後の直し（2026-10-30）

マージ前の最終レビューの軽い指摘（PR #5）：同じ団体の新しい回答が parseFormCsv で取り込まない行（misaligned・invalid_number・invalid_timestamp）になると、その行は resolveResponses に渡らないので、古い回答が「一番新しい回答」として使われ、superseded にも出なかった（04「同じ団体の回答が複数あるときは、タイムスタンプが一番新しいものを使う」と違う結果が、取り込まない行の一覧の陰で起こりうる）。

選んだ形：**rejected にタイムスタンプと団体名を残し、resolveResponses が、使う回答より新しい取り込まない行のある団体を requests・submissions から外して `newerRejected` で返す。**
- `ParsedForm['rejected']` の要素（`RejectedRow`）に `submittedAt: string | null` と `groupName: string | null` を足した。列のずれ・数が読めない行は、読む列の位置の値で読み、読めればそれを入れる。日時が読めない行・空の行は両方 null、日時が読めなければ団体名も null、企業フォームの団体名は常に null。団体名は回答の groupName と同じ読み方（団体名の列のうち空でない方からメールを除いたもの）。タイムスタンプは個人情報ではなく、団体名は回答の行にもともと持っている値なので、3.7 の「中身は持たない」（数・備考は持たない）の趣旨は保つ。画面には rejected の団体名を出さない（団体はマスタの名前で出す）。
- `resolveResponses`：取り込まない行のうち、日時と団体名が読めて、団体名（別名を含む）がちょうど1つの団体に当たるものを団体ごとに集め、使う回答（読めた回答のうち一番新しい。同時刻なら後の行）より新しい（タイムスタンプが新しい、同時刻なら後の行）ものがあれば、その団体を `requests`・`submissions`・`superseded` に入れず、`newerRejected: { groupId, keptRow, droppedRows, rejectedRows: { rowNumber, reason, submittedAt }[], submission, requests }[]` に入れる。`submission`・`requests` は keptRow で取り込むときの値で、呼ぶ側が人に確かめてから使う（自動では取り込まない）。
  - 理由：外すのを既定にしたのは、newerRejected を見ない呼び出し（build-r8-fixtures など）が古い回答を黙って使わないようにするため。値を添えたのは、画面で管理者が「それでも読めた回答で上書きする」を選べるようにするため（04 の Q2 の「団体ごとに選び直せる」に合わせ、既定で上書きしない）。もう1つの案（画面で取り込まない行があるだけで保存を止める）は、関係のない団体まで止めるので採らなかった。
  - 団体名が2つ以上の団体に当たる・どの団体にも当たらない取り込まない行、日時か団体名が読めない行は、今までどおり取り込まない行に出すだけ（どの団体も止めない）。手で選ぶ対応（manual）は回答の行にしかないので、取り込まない行には使わない。使う回答がない団体（回答が全部取り込まない行）も、今までどおり（取り込むものがない）。
- `scripts/r8/build.ts`：回答と同じく、取り込まない行の団体名も anonymize してから resolveResponses に渡す（仮名の団体に当てるため）。build は取り込まない行を既定で失敗にするので fixtures は変わらない。`--allow-rejected` のときは newerRejected の団体は取り込まれず、report の「回答のない団体」に出る。
- テスト（importer.test.ts）：rejected の日時と団体名（サンプル・途中で切れた行・メール）、新しい取り込まない行（数が読めない・同時刻の後の列のずれ）で団体を外すこと、古い取り込まない行・日時の読めない行は関係しないこと、外した団体の古い回答は droppedRows に出ること、2つの団体に当たる名前・未登録の名前は止めないこと、回答のない団体は今までどおりのこと。直す前に落ちることを確かめた。
- 設計書（notes/T06-design/logic-design.md の 3.7）の型と、04 の取り込みの節（同じ団体の回答の項・流れ・上書きの既定）を合わせた。画面は T11（notes/T11.md）。

### build が newerRejected を見ていなかった（2026-10-30、マージ前レビューの軽い指摘）

- 問題：上の直しで resolveResponses が newerRejected を返すようにしたが、`scripts/r8/build.ts` はそれを見ていなかった。`--allow-rejected` で fixtures を作ると、その団体は理由の分からないまま「フォームの回答がなかった団体」になった（--allow-rejected でなければ、newerRejected の元の取り込まない行が先に失敗にしていたので、fixtures は変わっていなかった）。
- 直し：newerRejected の団体を取り込まない行と同じ扱いにした。`--allow-rejected` でなければ `forms/<種類>.csv:<行>: 同じ団体の新しい回答が取り込めない行です（<理由>）…` で止める（行番号・フォームの名前・理由だけで、値は出さない。今は取り込まない行の失敗が先に起きるので、守りとして置いている）。`--allow-rejected` なら report の `formNewerRejected`（フォーム・匿名化した団体名・行番号と理由）に残し、出力に「新しい回答が取り込めない団体（取り込まず、submitted_at は空）: 研究室A(department・4行目 invalid_number)」の形で出す。その団体は「フォームの回答がなかった団体」には入れない（理由のある行に出すため）。取り込まない扱い（submitted_at は空、申請は adjustments だけ）は変えていない。
- テスト（scripts/build-r8-fixtures.test.ts）：匿名化する団体（研究室ゼータ → 研究室A）の新しい回答の机を数でなくした行を足し、(1) --allow-rejected でなければ `forms/department.csv:4` で失敗し、値・元の名前・メールを出さない、(2) --allow-rejected なら研究室A の submitted_at は空、report の行に匿名化した団体名・フォーム・行番号・理由が出て、「フォームの回答がなかった団体」には出ず、元の名前・値・メールを出さない。(2) は直す前に落ちることを確かめた（(1) は直す前から通る。取り込まない行の失敗が先に起きるため）。
