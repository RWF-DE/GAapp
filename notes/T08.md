# T08 exporter（Excel と年度データ）

設計：notes/T06-design/logic-design.md の 13.2。仕様：docs/requirements/03_allocation.md「Excel出力仕様」。

## できたもの（packages/exporter）
- `exportAllocationXlsx`：R8 様式の振り分け表（8 シート）。数式と計算済みの値を両方書き、`fullCalcOnLoad` を設定。
- `exportSwapsXlsx`：キャスター机交換依頼一覧（団体・企画名・場所・台数・了承状況、末尾に「交換」列と合計）。
- `exportYearJson`：年度データ。項目の許可リストで書き、自由記述に混じったメール形式の文字列は「(メールアドレス削除)」にする。
- `buildAllocationSheets` / `buildSwapsSheet`：ExcelJS に依存しないセル（値・数式・計算済みの値）の組み立て。xlsx への書き込みは `xlsx.ts`。
- ファイル名の関数（`allocationXlsxFileName` など）。allocator は import しない（ESLint でも禁止）。

## 決めたこと（仕様に書いていない細部）
- 運び先：keep 行は「残す」、それ以外は団体の使用場所の名前。使用場所のない団体（校内に分散など）は運び先を空にして最後に並べる（例外にしない）。
- 場所ブロックの行の並び：残す → 運び先の sort_order → 団体の並び（K-27）。
- 1列のシートは「運び元・運び先・団体・備考」が同じ行を足す（備考が違う行は分ける）。2列のシートは備考を「、」でつないで 1 行にする。
- 在庫が無く振り分けも無い場所は出さない。使用不可の部屋で不可机の在庫が 0 のときは E 列を空にする。使用不可の部屋から行が出ていれば、在庫の全数との差で「在庫超過」になる（検出される）。
- 2列のシートの在庫の見出しは「在庫(R8数え)」「{不可品目名}在庫(R8数え)」。
- 交換依頼一覧の了承状況：未依頼／依頼済み（返事待ち）／了承／了承なし（辞退）。了承済みで count より今の台数が多いとき「了承（N台。今はM台。依頼し直し）」（W102 と同じ見方）。
- 団体名が SUMIF に使えないとき（shared の checkGroupNames）は、団体名つきの例外でファイルを作らない。

## 再計算の確認（K-18）
- `tools/recalc.py`：soffice を headless + UNO で起動し、`calculateAll()` を明示的に呼んでから全セルの値とエラーコードを JSON に書く。
- `src/testing/recalc.ts`：Node から呼ぶ（Node 専用のテスト用）。`src/reference.test.ts`：
  - 合成データ r8like の reference/allocations.csv から出力 → 再計算 → 数式エラー 0・「在庫超過」「要確認」0・書いた計算済みの値が全セルで再計算の値と一致・団体別集計が reference/group_totals.csv と一致・末尾 4 行（使用数 計・在庫・使用不可・余り）が在庫から計算した値と一致。
  - 書いた値を壊しても LibreOffice が正しい値に直す（再計算が効いている証拠）。
  - 使用不可の部屋・自動の備考を含む小さな入力でエラー 0、在庫超過は 1 件検出。
- soffice と python3-uno がなければ飛ばす。`REQUIRE_LIBREOFFICE=1` のときは失敗にする。メインの check ジョブでは `SKIP_LIBREOFFICE=1`（二重に動かさない）。
- ci.yml に `recalc` ジョブを追加（apt で libreoffice-calc python3-uno）。PR で exporter・shared・合成データ・lock・ci.yml に変更があるときだけ動かす（main への push では常に）。ローカルで約 20 秒（soffice の起動 2 回）。
