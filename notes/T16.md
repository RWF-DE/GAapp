## 目的とユーザーの決定（承認された計画。2026-10-31）

アプリを「電波祭 総務」（総務アプリ）にする。総務部門の仕事を機能として1つのアプリにまとめ、今の机椅子は「机椅子」の機能になる。後に足す機能はお知らせ（T17）・予定と締切（T18）・提出物（T19）・シフト・作業分担（T20）・テント等の貸し出し（T21）。トップはダッシュボードで、機能ごとのカード・要対応の一覧・締切と予定を出す（T17 で総務内のお知らせを足す）。

1. **要件**：00〜05・CLAUDE.md・SPEC.md・README・runbook を総務アプリの形にそろえ、机椅子のルールは全部そのまま残す（この docs のコミット）。D-51（総務アプリにしてトップをダッシュボードにする）・D-52（機能の登録とダッシュボードのデータの形）。
2. **機能の登録**（データだけ。ページは本物のファイル）：lib/modules/registry.ts、lib/modules/portal.ts（型）、lib/modules/furniture/portal.ts（総務には軽い読み取りだけ。純粋関数 furniturePortal）。数え方を summarizeDashboard から出して両方で使う。
3. **ナビゲーション**：RouteDef.section と NAV_SECTIONS（ホーム／机椅子／共通）、/furniture、マスタ設定と履歴は共通へ。navItemsFor（平ら）は残し navSectionsFor を足す。AppNav は見出しごとに出し、`<li>` はリンクだけ。
4. **/furniture**：今のダッシュボードを「机椅子の状況」として出す（testid は変えない。ファイルは components/dashboard のまま）。振り分け画面の「ホームのダッシュボードから」は /furniture へのリンク「机椅子の状況から」に。
5. **ダッシュボード（/）**：立場の一覧が最初。総務は要対応の一覧・締切と予定・機能ごとのカード（店長・副店長も務めれば代表する団体も）、閲覧のみはカード（読み取り）と締切と予定、団体代表は締切と予定と代表する団体（と要対応）。h1 は総務に「ダッシュボード」、ほかに「ホーム」。欄ごとに別々に読み、読み込み中・失敗ともう一度・エラーの境界を持つ。団体代表・閲覧のみの / はスナップショットと検証を読まず、import もしない。
6. **名前**：「電波祭 総務」（manifest の short_name「総務」）、Excel の作成者「電波祭 総務アプリ」、アイコンは文字のない総務の絵。QR のカードと /stock?room= は変えない。
7. **速さの表**：/furniture は版を先に読む（許可リストに足すものはない）。テストの SNAPSHOT_PATHS に /furniture。/ は T16 では許可リストに入れない（リードの決定 4 で改めた：/ を許可リストと先読みに入れる。「取り込みと決めたことの直し」の 2）。
8. **テスト**：Vitest・E2E（t16-portal ほか）・perf の home・スクリーンショット（notes/T16/）。テストの名前は「T16 」で始める。

### 3. 機能の登録とダッシュボードの型（lib/modules）

**registry.ts**（データだけ。実行時の import をしない。lib/navigation.ts が読むので、ナビの JS を増やさない）

```ts
export const MODULES = [
  { id: 'furniture', label: '机椅子', homeHref: '/furniture' },
] as const;
export type ModuleId = (typeof MODULES)[number]['id'];
export interface ModuleDef { id: ModuleId; label: string; homeHref: string }
```

約束：id は英字の小文字（01 の用語集の英語名）、label はナビの見出しとカードの名前、homeHref は ROUTES にあり section がその id のルート（Vitest で確かめる）。並びは見出しとカードの並び。機能のチケットは最後に1行足す（D-52）。

**portal.ts**（型と小さな純粋関数だけ。React・Supabase・lib/data を import しない）

```ts

export interface TodoItem {

  moduleId: ModuleId;
  title: string;          // 画面に出す文。数を含む（「未提出 3 団体」）
  count?: number;         // 文の中の数（テスト・読み上げ用）
  severity: TodoSeverity;
  due?: string;           // 期日（timestamptz の ISO 文字列）。「締切 M/D HH:mm」と出す

export interface DatedItem {
  id: string;             // 機能の中で一意。種類（kind）によらず同じ項目は同じ id・同じ中身
  moduleId: ModuleId;
  title: string;
  at: string;             // ISO 8601。時刻のあるものは timestamptz の文字列、日付だけのものは YYYY-MM-DD（Asia/Tokyo の日付）
  kind: 'deadline' | 'event'; // 締切・予定
  href?: string;          // 開けるときだけ
}

export interface ModuleCardModel {
  moduleId: ModuleId;
  title: string;          // 機能の名前（MODULES の label）
  lines: string[];        // 要約（1〜4 行）
  href: string | null;    // 入口（開けなければ null）
  linkLabel: string;      // リンクの文字
}

/** 1つの機能が1つの種類に出すもの */
export interface PortalSection { card: ModuleCardModel | null; todos: TodoItem[]; dated: DatedItem[] }

export interface PortalContext {
  kind: PortalKind;
  year: YearRow;                    // 開いている年度の行（立場と一緒に読んでキャッシュにあるもの。useYearRow）

/** ['year', yearId, 'portal', moduleId, kind, ...extra]（queryKeys.yearPart と同じ形。年度の invalidate で一緒に消える） */
export function portalQueryKey(yearId: string, moduleId: ModuleId, kind: PortalKind, ...extra: string[]): readonly unknown[];

export type PortalWidgetId = 'todos' | 'dated' | 'cards'; // 欄（2026-10-31 の決定 7 で lib/modules/portal.ts に移した）

/** 機能の読み取り（決定 7：読み取りの結果を使う欄を宣言する。ほかの欄は fromYear だけを出し、この読み込み中・失敗を出さない） */
export interface PortalQuery {
  widgets: readonly PortalWidgetId[];

   * 読む分。TanStack の queryOptions（queryKey は portalQueryKey(...)、queryFn は生の行、select で PortalSection）。

  options: (ctx: PortalContext) => PortalQueryOptions | null;

export interface PortalProvider {

  kinds: readonly PortalKind[];

export function portalKindsOf(m: Pick<Membership, 'role' | 'groups'>): PortalKind[];
export function sortTodos(todos: readonly TodoItem[]): TodoItem[];
export function upcomingDated(items: readonly DatedItem[], now: number, limit?: number): { items: DatedItem[]; more: number };

```

- `PortalQueryOptions` の型の書き方は実装で決める（useQueries に並べて渡せること。data は PortalSection）。
- `sortTodos`：急ぎ → ふつう → 参考、同じなら期日の早い順（期日のないものは後）、MODULES の順、元の順（安定）。
- `upcomingDated`：時刻つきは `at` が now より後（04 の「今より後」。締切ちょうどは「締切を過ぎた」側）、日付だけは日付が今日（Asia/Tokyo。tokyoToday(now)）以降のものを、早い順（日付だけは tokyoStartOfDay で比べる。同じ時刻は MODULES の順、元の順）に `limit`（既定 8）件まで。残りの数を more に返す。
- `mergePortalSections`：todos と dated は id で重ねず（最初の1件）、カードは機能ごとに種類の順（soumu → viewer → rep）で最初の null でないもの。
- 欄が使う結果は「query があり data（select の後）があればそれ、なければ fromYear(ctx)、どちらもなければ空」。query の結果は fromYear の分を含む約束なので、両方を足し合わせない。

**providers.ts**（ダッシュボードに出す機能の一覧。各機能の portal.ts を import するのはここだけ。components/portal が読む）


### 5. 欄の読み込み・失敗・エラーの境界

- 年度の行：`useYearRow(yearId)`（立場と一緒に読んだキャッシュがある。D-45）。data がない間は、どの欄も `portal-loading`。年度の行の読み込みが失敗したら、欄ごとに失敗ともう一度（年度の行の refetch）。
- ctx：種類ごとに PortalContext を作る。now は画面を開いた時刻（`useState(() => Date.now())`。RepHome と同じ）。
- 読む：PORTAL_PROVIDERS × 種類（provider.kinds に入るもの）のうち、その欄が query.widgets に入り、query.options(ctx) が null でないものを、欄ごとに useQueries に並べる（portalWidgetQuery。欄ごとに自分の要るものだけ。要対応：soumu・rep、締切と予定：全部、カード：soumu・viewer）。同じキーは TanStack が1回だけ読むので、欄が3つでもリクエストは機能・種類ごとに1回。机椅子の読み取りは要対応とカードの欄にだけ並べ、締切と予定の欄には並べない（決定 7。2026-10-31 に「締切と予定は全部の種類の query を並べる」から直した）。
- 欄の出し方：
  - query の data があればそれ、なければ fromYear の分を出す。
  - query の読み込み中は、fromYear の項目を出したうえで、その機能の分の小さな Skeleton（`portal-loading`）を足す（fromYear の項目もなければ Skeleton だけ）。
  - query の失敗（data なし）は、その欄の中に `portal-module-error`（「{機能の名前}：{messageFor(classifyError(error))}」と「もう一度」＝その query の refetch）。ほかの機能・ほかの欄・fromYear の項目は出したまま。data があって読み直しだけが失敗したときは data を出し続ける（QueryState と同じ考え）。
  - 認証の失敗（401・PGRST301〜303）は今の画面と同じ扱い（lib/errors の分類と、セッションの更新・ログインへ）。
- エラーの境界：欄ごとに React のエラーの境界（components/portal/widget-boundary.tsx）で包む。描画の例外は `portal-widget-error`（「この欄を表示できませんでした。」と「もう一度」＝境界を戻し、その欄の query を refetch）。ほかの欄は出したまま。
- 読み直し：既定の staleTime（30 秒）のまま。/furniture で状態を変えると YearStatusActions が `queryKeys.year(yearId)` を invalidate するので、ダッシュボードに戻れば読み直す。最後に読み込んだ日時と「読み直す」は出さない（どちらも portal.test.tsx で確かめる。アプリの QueryClient の既定値のまま、29 秒後に戻れば読み直さず 31 秒後なら読み直す。レビューの T16-R2）。

2. **機能の見出しを MODULES から作る**：機能のチケットが registry.ts に1行足すだけで、ナビの見出しとカードの並びがそろう（navigation.ts の見出しの一覧を各チケットが直さない）。

5. **DatedItem の at の日付だけの形**：1日目は date の列なので、時刻を作らず YYYY-MM-DD のままにする。並べるときは Asia/Tokyo の 0 時として比べ、出すときは日付だけにする（タイムゾーンを通さない。lib/datetime.ts の formatDate・tokyoStartOfDay と同じ考え）。
6. **query の結果は fromYear の分を含む**：furniturePortal(raw | null, ctx) の1つの関数から両方を作るので、欄は「data があればそれ、なければ fromYear」を出すだけで、足し合わせや重なりの扱いが要らない。
