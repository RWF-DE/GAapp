- **messageFor の引数**：設計の `messageFor(kind, ctx)` ではなく `messageFor(classified, ctx)` にした（details が要るため）。ctx は `{ rpc, names: { room, item, group }, reloadedStatus, prevFestivalStart, groupId }`。details のないエラー（set_consent の invalid_state、create_year_from の invalid_input、revoke_invitation の forbidden）は `rpc` で文言を分ける。

```ts
const draft = loadDraft<Counts>(key);            // あれば「保存していない入力があります（formatTime(draft.savedAt)）」
const writer = useMemo(() => createDraftWriter<Counts>(key), [userId, yearId, roomId]);
writer.write(counts);                            // 500 ms まとめて書く
writer.clear();                                  // 保存に成功したら
useEffect(() => () => writer.flush(), [writer]); // 外れるとき（移動・年度の切り替え）に書いていない分を書く
```
- 年度を切り替えると AppShell が画面を作り直す（key が年度の id）。画面は外れるときに writer.flush() で前の年度の下書きに書き切り、作り直された画面は新しい年度の下書きから DraftNotice で戻す（年度の id を key に入れるので、前の年度の入力を新しい年度に持ち込まない）。

## E2E の書き方（T09〜T14）

### 決まり
- ファイルはチケットごと（`e2e/t10-stock.spec.ts` など。設計 7.2 の表）。ほかのチケットのファイルを触らない。
- **テストの名前はチケット ID で始める**（`test('T10 在庫入力（390px）', …)`）。`pnpm e2e:shots --grep T10` と `pnpm e2e -- --grep T10` はテストの名前で絞る。
- ログインは storageState（`test.use({ storageState: storageStateFor('admin') })`）。**ログアウトを試すテストは storageState を使わない**（`loginAs` で画面からログインし直すか createUser のユーザー）。
- **年度はテストごとにシナリオの年度を作る**（seed の R8 に書かない）。`try { … } finally { await s.cleanup(); }`。
- 年度をまたぐ表（rooms・items・distance_overrides）は chromium のテストで書かない。書くテストは e2e/serial/ に置き、`SERIAL_NAMES` の名前の行だけを作って変え、`afterEach` で pg で消す（設計 7.2）。テスト用の場所を作った後に createScenario を呼ばない。
- 場所の数など年度をまたぐ表の全体の数は書き込まず、`readGlobalRooms()` かデータセットから期待値を作る。在庫入力の場所の一覧には、データセットにない場所も「使用不可」の印つきで出るので、データセットの名前で絞って確かめる。
- 読み込み中・ロックの表示は `page.route('**/rest/v1/rpc/save_auto_allocations', …)` で応答を止めてから見る（速すぎて消えるため）。立場の読み込みなどを `route.abort()` すると supabase-js が GET を読み直し（4 回・約 7.5 秒）、エラーの表示が遅れるので、エラーを見るときは `route.fulfill({ status: 500, … })` を使う。
- 1つだけ流す：`E2E_PORT=3210 pnpm exec playwright test --project=chromium e2e/t10-stock.spec.ts`（setup は依存で走る）。DB に触れるのでロックを取る（このコンテナでは db-lock.sh）。
