### 設計どおりでないところ・決めたこと
- **messageFor の引数**：設計の `messageFor(kind, ctx)` ではなく `messageFor(classified, ctx)` にした（details が要るため）。ctx は `{ rpc, names: { room, item, group }, reloadedStatus, prevFestivalStart, groupId }`。details のないエラー（set_consent の invalid_state、create_year_from の invalid_input、revoke_invitation の forbidden）は `rpc` で文言を分ける。
- **P0001 以外の details は持たない**（23505 の details は「Key (email)=(…)」のように DB の値を含むため）。
- **画面の層が作るエラー**は `appError(kind, reason, details)`。reason の印：`lock_missing`（0 行・行がない）・`lock_conflict`（updated_at が違う）・`lock_unchanged`（RLS で拒否）・`client_validation`（送る前の zod）・`year_missing`・`unexpected_response`（jsonb の返り値が zod に合わない。kind は unknown で、effectOf は読み直し）。
- **送る前の確かめ**：`callRpc` は RPC_ARGS の zod で引数を確かめ、確かめた値（前後の空白を除いた理由・小文字にしたメールなど）を送る。理由が空なら kind reason、それ以外は kind input（field は p_ を除いた引数名。`入力の形が違います（年度）` など）。
- **上限の定数**：設計 1.6 は「名前 100 字・自由記述 2000 字・別名は shared の定数」と書いたが、shared にあるのは MAX_COUNT・MAX_DISTANCE_COST・MAX_SUBSTITUTE_COST だけだった。packages を変えないため、NAME_MAX・NOTE_MAX・BUILDING_MAX・ALIASES_MAX_* も schemas/common.ts に DB の CHECK の出所つきで置いた（後で shared に移すなら、そのときに）。
- **toYearData の参照の確かめ**：createContext の inputErrors に ruleCode があれば、そのコードのルールをすべて外して problems（`ルール {code}：{message}（ルール画面で直すか無効にしてください）`、path は createContext のまま）に入れ、もう一度確かめる。ruleCode のない誤りは最後の回のものだけを problems に入れて validatable を偽にする。ルールどうしの重なりは両方のルールを外す。設定の壊れたルール（ruleSchema に合わない）の problem にも ruleCode を付けた（ルール画面へのリンクのため）。
- **toStoredRows** は zod で確かめず写すだけ（DB の CHECK で形が決まっている。例外を投げない）。
- **swapRows の対象**：有効で needsConsent の代替ルールの組の置き換え（current ≥ 1）と、了承の行すべて（ルールを無効にした後に残った行も出す）。注意（attention）は、依頼した台数（count）が null の了承では W102 にしない（validate の W102 と同じ）。

## 段 C・D への申し送り（段 B から）

### 段 C
- **QueryClientProvider**：`createQueryClient()`（lib/query.ts）で1つ作る。手動のログアウト・強制の signOut・利用者の切り替えで `queryClient.clear()`。
- **ログアウトと下書き**：手動のログアウトは UnsavedChangesGuard で確かめた後に `draftsOnSignOut('manual', userId)`、強制の signOut（401・ほかのタブの SIGNED_OUT）は `draftsOnSignOut('forced', userId)`（何も消さない。呼ばなくてもよいが、呼べば意図が読める）、user_id が決まったら `draftsOnSignIn(userId)`。選んだ年度（sessionStorage の `gaapp:year:<user_id>`）は drafts の関数では消さないので、AuthProvider が消す。
- **401 の扱い**：`effectOf(classified).reauth` が真なら、`supabase.auth.refreshSession()` を1回試し、成功したら同じ要求を1回だけ送り直す。だめなら `signOut({ scope: 'local' })` してから `/login?next=…`（下書きは消さない）。この流れ（useMutation・useQuery の onError から呼ぶ共通の関数）は段 C の AuthProvider の近くに置く。
- **ErrorBanner**：`messageFor(classifyError(e), ctx)` と `effectOf` の reload（`data` → 画面のクエリを refetch、`year` → `queryKeys.year(yearId)` を invalidate して reloadMembership）。kind issue のときは `issueMessages` を一覧で出す。
- **TokyoTime**：`formatDateTime`（表示）と `formatDateTimeSeconds`（title）。
- **YearStatusActions**（設計 8.1 の 5 に入っているが部品なので段 C）：確定は `callRpc('set_year_status', { p_year_id, p_to: 'confirmed', p_reason, p_base_version: snapshot.version })`。押せる条件は `useValidation` の `status === 'ok'`・error 0・`yearData.problems.length === 0`・`version === snapshot.version`・`useVersionWatch().stale` が偽。conflict は `messageFor(e, { rpc: 'set_year_status' })`。
- **年度の切り替えの ESLint**（段 A の申し送りのまま）。
