- 名前と題名：notices_title_check・events_title_check と同じ 25 文字（JavaScript の String.prototype.trim が除く文字）。書き込みは画面からの直接なので DB では除かず、前後に空白のある値と空白だけの値を CHECK で拒む（23514）。画面は zod の trim を通してから送る。
- 場所・説明・作業の説明：任意。空なら画面が null にする（D-33。DB は空文字を止めない。events.note と同じ）。字数は length（コードポイント）。
- 時間枠：`starts_at < ends_at`、長さは 24 時間まで（同じ 24 時間はよい）、開始・終わりの Asia/Tokyo の日付は 2000-01-01〜2200-12-31（D-18・D-54 と同じ。infinity と JavaScript の Date で扱えない日時を入れさせない）。CHECK は名前の順に確かめられる（date_range → length → order）ので、infinity は引き算の前に date_range で 23514 になる（無限の timestamptz の引き算は、PostgreSQL 16 までは 22008、17〔ローカルの supabase/config.toml の版〕では無限の interval になる。どちらの版でも、length の CHECK の前に date_range で止める）。日は starts_at の Asia/Tokyo の日付（0 時をまたぐ枠は開始の日）。
- 作業の締切：任意。日付の範囲の CHECK だけ（時刻の決まりはない。画面の既定は 17:00）。外部キーは MATCH SIMPLE なので、担当者が null なら確かめない。
- 外部キーの on delete：年度へは cascade。ますは時間枠・持ち場が消えると消え（cascade）、割り当てはますが消えると消える（cascade）。割り当ての year_roles への参照は cascade（ロールを外すと消える）、作業の担当者は set null（担当者の列だけを空にする。PostgreSQL 15 からの書き方。year_id は残す）。書いた人・直した人は set null（02 の決まり）。
- 索引：一覧とポリシーの `year_id in (…)` 用に year_id から始める。外部キーの連鎖で引く (year_id, user_id)・(year_id, assignee_id)・(slot_id, duty_id) を持つ。shift_needs は主キー (slot_id, duty_id) だけ（年度に 250 行ほどの見込みで、持ち場の削除の連鎖〔duty_id で引く〕も年度で絞った読みも小さい）。

```sql
-- 時間枠の重なり（[開始, 終わり) が重なる2つを同じ年度に置かない。隣り合う 9:00〜10:00 と 10:00〜11:00 はよい）
create function private.tg_shift_slots_no_overlap()
returns trigger language plpgsql security definer set search_path = '' as $$
declare v_other uuid;
begin
  if private.rls_applies() and not private.can_lead(new.year_id) then
    return new;            -- 書けない人：ロックを取らずに拒否を RLS に任せる（0004 の約束）
  end if;
  if not (new.starts_at < new.ends_at) then
    return new;            -- 時刻の順が違う値は CHECK（shift_slots_order_check）に任せる
  end if;
  perform pg_advisory_xact_lock(hashtext('gaapp.shift_slots'), hashtext(new.year_id::text));
  -- ロックを取る文と確かめる文を分ける（READ COMMITTED：待っている間に確定した時間枠も次の文で見える。0013 と同じ）
  select s.id into v_other from public.shift_slots s
  where s.year_id = new.year_id and s.id <> new.id
    and s.starts_at < new.ends_at and new.starts_at < s.ends_at
  order by s.starts_at, s.id
  limit 1;
  if v_other is not null then
    perform private.fail('invalid_input', jsonb_build_object('field', 'starts_at', 'reason', 'overlap', 'slot_id', v_other));
  end if;
  return new;
end $$;
create trigger no_overlap before insert or update of starts_at, ends_at on public.shift_slots
  for each row execute function private.tg_shift_slots_no_overlap();

-- その年度の総務か（任意の人について答えるので、誰にも execute を与えない。VOLATILE：for share で行をロックし、待った後の値を読む）
create function private.year_member_is_soumu(p_year_id uuid, p_user_id uuid)
returns boolean language plpgsql security definer set search_path = '' as $$
declare v_role public.app_role;
begin
  select yr.role into v_role from public.year_roles yr
  where yr.year_id = p_year_id and yr.user_id = p_user_id
  for share;
  return coalesce(v_role in ('admin', 'head', 'deputy_head', 'staff'), false);
end $$;

-- 割り当てる人・作業の担当者は、その年度の総務だけ（tg_argv[0] は列の名前）
create function private.tg_soumu_member_check()
returns trigger language plpgsql security definer set search_path = '' as $$
declare
  v_col constant text := tg_argv[0];
  v_user uuid := (to_jsonb(new) ->> v_col)::uuid;
begin
  if v_user is null then
    return new;            -- 担当者なし（作業）
  end if;
  if tg_op = 'UPDATE' and v_user is not distinct from (to_jsonb(old) ->> v_col)::uuid then
    return new;            -- 値が変わらない更新では year_roles を読まない（ロックを取らない）
  end if;
  if private.rls_applies() and not private.can_lead(new.year_id) then
    return new;            -- 書けない人：拒否を RLS に任せる（ロックを取らず、相手のロールの有無も漏らさない）
  end if;
  if not private.year_member_is_soumu(new.year_id, v_user) then
    perform private.fail('invalid_input', jsonb_build_object('field', v_col, 'reason', 'not_soumu'));
  end if;
  return new;
end $$;
create trigger member_check before insert or update of user_id on public.shift_assignments
  for each row execute function private.tg_soumu_member_check('user_id');
create trigger member_check before insert or update of assignee_id on public.tasks
  for each row execute function private.tg_soumu_member_check('assignee_id');
```

- no_overlap と member_check は private.fail を呼ぶので DEFINER（authenticated では private.fail を実行できず 42501 になるため。0004 の tg_immutable_columns と同じ）。set_actor は auth.uid() を読むだけなので INVOKER のまま（tg_events_set_actor と同じ）。
- 書けない人（anon・authenticated で can_lead でない人）は、BEFORE ROW のトリガーがポリシーの with check より先に動いても、ロックを取らずに new を返し、拒否は RLS（insert は 42501、update・delete は 0 行）に任せる。SQL Editor（postgres）と RPC の中（role は authenticated のまま。add_shift_slots を呼べるのは部門長以上）は確かめる。

### RPC

**`set_task_status(p_task_id uuid, p_status public.task_status, p_base_updated_at timestamptz) returns public.tasks`**（総務で、その作業の担当者か部門長以上）

```sql
create function public.set_task_status(p_task_id uuid, p_status public.task_status, p_base_updated_at timestamptz)
returns public.tasks language plpgsql security definer set search_path = '' as $$
declare
  v_year_id uuid := (select t.year_id from public.tasks t where t.id = p_task_id);
  v_old public.tasks;
  v public.tasks;
begin
  perform private.lock_year(v_year_id, '{preparing,requesting,allocating,confirmed}', '{admin,head,deputy_head,staff}');
  if p_status is null then
    perform private.fail('invalid_input', jsonb_build_object('field', 'status'));
  end if;
  if p_base_updated_at is null then
    perform private.fail('invalid_input', jsonb_build_object('field', 'base_updated_at'));
  end if;
  select * into v_old from public.tasks t where t.id = p_task_id for update;
  if not found then
    perform private.fail('not_found');
  end if;
  if v_old.assignee_id is distinct from auth.uid() and not private.has_any_role(v_year_id, '{admin,head,deputy_head}') then
    perform private.fail('forbidden');
  end if;
  if date_trunc('milliseconds', v_old.updated_at) is distinct from date_trunc('milliseconds', p_base_updated_at) then
    perform private.fail('conflict', jsonb_build_object('id', v_old.id));
  end if;
  perform private.set_reason('作業の状態');
  update public.tasks set status = p_status where id = v_old.id returning * into v;
  return v;
end $$;
```

エラーの順（pgTAP の 028 はこの順で確かめる）：

1. lock_year：作業がない・その作業の年度の総務でない → forbidden（作業の有無を漏らさない。delete_notice と同じ）。年度が終了 → invalid_state（detail は status）。
2. p_status が null → invalid_input（field: status）。p_base_updated_at が null → invalid_input（field: base_updated_at）。
3. 年度の行のロックを待つ間に作業が消えた → not_found（呼んだ人はその年度の総務で、その作業を読めた。delete_notice と同じ。計画の 5 段に足した。「判断したこと」の 4）。
4. 担当者でも部門長以上でもない → forbidden（担当者なしの作業は部門長以上だけ）。
5. updated_at が p_base_updated_at と違う（ミリ秒までで比べる）→ conflict（detail は `{id}`）。
6. 理由「作業の状態」を置き、status だけを書く（同じ状態でも書き、updated_at・updated_by が進む）。返り値は作業の行（画面は返った updated_at を次に使う）。

- どの状態からどの状態へも変えられる（完了から戻すのもよい）。担当者が set_role で閲覧のみに変わった作業は、本人は lock_year の forbidden で変えられない（部門長以上は変えられる）。
- 確定中も書ける。終了の年度は invalid_state。

**`add_shift_slots(p_year_id uuid, p_slots jsonb, p_needs jsonb default '[]'::jsonb) returns setof public.shift_slots`**（部門長以上。「1日分をまとめて作る」）

- p_slots：`[{"starts_at": "2027-10-15T09:00:00+09:00", "ends_at": "2027-10-15T10:00:00+09:00"}, …]`（1〜96 個。日時はオフセットつきの ISO 8601 の文字列）。
- p_needs：`[{"duty_id": "<uuid>", "required_count": 1}, …]`（0〜100 個。作った時間枠のすべてに、同じ持ち場のますを同じ必要人数で作る。空なら時間枠だけ〔ますは「—」〕）。
- 返り値：作った時間枠（開始の早い順）。
- 冪等の鍵はない（応答が届かなかったら、その日の時間枠を読み直して確かめてから送り直す。04 の (B2)）。

エラーの順（detail の ord は送った配列の中の番号。1 から。save_auto_allocations の ord と同じ数え方）：

1. `private.lock_year(p_year_id, '{preparing,requesting,allocating,confirmed}', '{admin,head,deputy_head}')`：年度がない・その年度の部門長以上でない → forbidden。終了 → invalid_state。
2. p_slots が null・配列でない・空 → invalid_input `{field: slots, reason: required}`。97 個以上 → `{field: slots, reason: too_many}`。
3. 時間枠ごと（送った順）：object でない・starts_at か ends_at が文字列でない・オフセットつきの日時として読めない → `{field: slots, reason: invalid, ord}`。開始が終わりより前でない → `{field: slots, reason: order, ord}`。24 時間より長い → `{field: slots, reason: too_long, ord}`。開始・終わりの Asia/Tokyo の日付が 2000-01-01〜2200-12-31 の外 → `{field: slots, reason: out_of_range, ord}`。
4. 送った時間枠どうしが重なる（開始の順に並べ、前の枠の終わりより前に始まる）→ `{field: slots, reason: overlap, ord}`（ord は重なる2つのうち送った順で後のもの）。
5. p_needs（null は空と同じ）：配列でない → `{field: needs, reason: invalid}`。101 個以上 → `{field: needs, reason: too_many}`。要素ごと：object でない・duty_id が uuid の文字列でない・required_count が 0〜100 の整数（JSON の数）でない → `{field: needs, reason: invalid, ord}`。同じ持ち場が2回 → `{field: needs, reason: duplicate, ord}`（後のもの）。その年度の持ち場でない → `{field: needs, reason: not_in_year, ord}`。
6. 理由「シフトの時間枠」を置き、時間枠を開始の早い順に1つずつ insert する（今ある時間枠と重なれば、no_overlap のトリガーが `{field: starts_at, reason: overlap, slot_id}`。slot_id は今ある時間枠）。作った時間枠ごとに、p_needs の並びでますを insert する。
7. 確かめた後に持ち場が消えた（23503。管理者・部門長の削除と重なった）→ `{field: needs, reason: not_in_year}`。CHECK の違反（23514）と形の誤り（22xxx）→ `{field: slots, reason: invalid}`（確かめの後なので、ふつうは起きない）。どのエラーでも何も残らない（1つのトランザクション）。

### ロックと同時実行

| 書き込み | 取るロック（順に） |
| --- | --- |
| 時間枠の insert・時刻の update（直接） | 年度ごとの勧告的ロック（no_overlap。書ける人だけ）→ 行 →（外部キーの確かめ：years の for key share） |
| add_shift_slots | years の行（lock_year の for no key update）→ 勧告的ロック（no_overlap）→ 時間枠とますの行 |
| 割り当ての insert（直接） | year_roles の行（member_check の for share。書ける人だけ）→ 行 →（外部キー：shift_needs・year_roles の for key share） |
| 作業の insert・担当者を変える update（直接） | update は作業の行（BEFORE ROW のトリガーの前に行をロックする）→ 新しい担当者の year_roles の行（for share） |
| set_task_status | years の行（lock_year）→ 作業の行（for update） |
| remove_role（変えない） | 招待の行 → year_roles の行（delete）→ 連鎖で割り当ての行（delete）・作業の行（担当者を null に update） |

- 同時に同じ時刻の時間枠を足す2人は、勧告的ロックで順になり、後の人が overlap になる。勧告的ロックは年度ごとで、ほかの年度・ほかの表の書き込みを待たせない。lock_year（for no key update）と外部キーの for key share はぶつからないので、時間枠の直接の書き込みは振り分けの保存や状態の遷移を待たない（add_shift_slots・set_task_status は年度の行で順になる。delete_notice と同じ）。
- ロールの変更・外すことと、割り当て・担当者の書き込みは year_roles の行で順になる：割り当てる側が先に for share を取れば、remove_role はそれを待ってから消し、連鎖は新しいスナップショットで引くので、入ったばかりの割り当ても消す。remove_role・set_role が先なら、割り当てる側は待った後の行（なくなった・閲覧のみになった）を読んで not_soumu になる。
- 作業の update は「作業の行 → 新しい担当者の year_roles の行」の順に取り、remove_role は「year_roles の行 → 確定した担当者がその人の作業の行」の順に取る。トリガーが year_roles を読むのは担当者が変わるときの新しい担当者の行だけで、連鎖が待つのは確定した担当者が外す人の作業の行だけなので、1人の作業の書き込みと1つの remove_role の間では待ち合いの輪はできない（同じ作業の担当者を A→B に変えながら A を外す、などは片方が待つだけ）。担当者の入れ替えと remove_role が何組も同時に重なる、まれな組み合わせでは 40P01 になりうる（DB が検出して1つを止める。画面は今の 40P01 の文言「ほかの人の保存と重なりました。もう一度保存してください」）。
- 読み取りはロックを取らない。

### ロールを外したとき・年度の状態・複製

| 起きること | 割り当て | 作業 |
| --- | --- | --- |
| remove_role（year_roles の行が消える。終了した年度でも） | 外部キーの cascade で、その年度のその人の割り当てが消える（ますの人数が減り、足りない枠に出る） | 担当者が空になる（set null。状態はそのまま。担当者なしに出る） |
| set_role で閲覧のみにした（行は残る。管理者だけの操作） | 残る。部門長以上の表で「総務でない人」と出し、人数に数えない（部門長以上が外す） | 残る。部門長以上の一覧で「担当者が総務でない」と出す（本人は set_task_status で変えられない） |
| アカウントの削除 | year_roles の連鎖で消える | 担当者が空になる。作った人・直した人も空になる |
| 年度の削除 | 年度の連鎖で5表とも消える | 同じ |

- 連鎖で消えた行・変わった行は監査に残る（理由は remove_role の理由、した人は外した人。連鎖の update でも set_actor が updated_by を外した人にする）。
- 準備中〜確定は書ける（確定中も書ける。当日に直すため）。終了は読むだけ（can_lead と RPC の invalid_state）。SQL Editor（postgres）からは終了の年度でも書ける（トリガーの守りはない。予定と締切と同じ）。
- 年度の複製（create_year_from）は5表を写さない（日時と人が年ごとに違う。持ち場は数行なので毎年入れ直す）。create_year_from は変えない。pgTAP の 020 で、複製元に行があり、複製した年度に 0 件であることを確かめる。

### 8. zod（lib/schemas/shifts.ts・lib/schemas/tasks.ts）

- 持ち場：名前は zod の trim（25 文字）の後に 1〜50 字、場所は trim して空なら null・100 字まで、説明は空なら null・1000 字まで（字数はコードポイント）、並び順は整数（±1,000,000。マスタ設定の並び順と同じ）。
- 時間枠：日付（2000-01-01〜2200-12-31）・始まり・終わり（`HH:mm`）。終わりが始まり以前なら翌日。送る値は `YYYY-MM-DDTHH:mm:00+09:00`。
- 1日分：日付・始まり・終わり（終わりは 24:00 まで。始まりより後）・区切り（15・30・60・90・120）・持ち場ごとの「置く」と必要人数（0〜100）。並ぶ時間枠は 1〜96。
- 作業：題名は trim の後に 1〜100 字、説明は空なら null・2000 字まで、担当者は uuid か null、締切は日付が空なら null（時刻だけは誤り）、日付があれば時刻の既定 17:00、`YYYY-MM-DDTHH:mm:00+09:00` で送る。

## 判断したこと（計画の読み方）

1. **pgTAP の新しいファイルは 028**：計画は 026_rpc_shifts。並行の T19 が 026・027（026_rpc_documents・027_storage_documents）を使い、T21 は 029（029_rpc_lending。T20 の 026 と重ならないように付けた。notes/T21.md）にしたので、マイグレーションの並び（T19 0016・T20 0017・T21 0018）に合わせて 028 にした（ファイルの名前は違うのでどの番号でも git の衝突はしないが、読む人が迷わないように。マージでほかとぶつかったらリードが付け直す）。
2. **時間枠の CHECK の名前の順**：infinity を引き算の前に止めるため、日付の範囲の CHECK の名前が先に来るようにした（date_range → length → order。PostgreSQL は CHECK を名前の順に確かめる）。計画の範囲は変えない。
3. **重なりのトリガーは時刻の順が違う値を確かめない**：開始が終わりより前でない値は CHECK に任せる（overlap と取り違えた文言を出さない）。
4. **set_task_status にロックの後の not_found を足した**：計画の確かめの順の 1 と 3 の間に、年度の行のロックを待つ間に作業が消えたときの not_found を足した（delete_notice と同じ。消えた作業の update が 0 行で黙って成功しないように）。
5. **同じ状態でも書く**：set_task_status は同じ状態を頼まれても書き、updated_at を進める（save_notice の「何も変わらなくても書く」と同じ。画面は今の状態のボタンを押せなくするので、ふつうは起きない）。
6. **総務かの確かめは、書ける人だけ・値が変わるときだけ**：計画の「値が変わるときだけ」に、書けない人（can_lead でない人）では確かめずに RLS に任せることを足した（0004 の守りのトリガーと同じ。ロックを取らせないことと、総務部門員が自分の読めない year_roles のロールを not_soumu と 42501 の違いで知らないようにするため）。
7. **ロックの順の説明を直した**：計画は「year_roles の行 → 割り当て・作業の行」と1つの向きに書いたが、作業の update は BEFORE ROW のトリガーの前に作業の行をロックするので「作業の行 → 新しい担当者の year_roles の行」になる。1人の書き込みと1つの remove_role の間で輪ができないことと、まれに 40P01 になりうることを「ロックと同時実行」に書いた（画面の扱いは今の 40P01 の文言）。
8. **add_shift_slots の入力の約束**：計画の「重なり・その年度にない持ち場・範囲外は invalid_input（field・reason）」を、field（slots・needs・starts_at）と reason（required・too_many・invalid・order・too_long・out_of_range・overlap・duplicate・not_in_year）と ord（1 から）に分けた。日時はオフセットつきだけを受け付ける（オフセットのない日時をセッションのタイムゾーン〔UTC〕で読んで9時間ずれないように。update_requests_after_deadline の submittedAt と同じ）。needs は 100 まで（持ち場の数の上限の見込み）。
9. **シフト表の読み取りは2本＋表示名（＋ロール）**：計画は「2〜3本」。持ち場は時間枠に埋め込めない（外部キーがない）ので、時間枠（ますと割り当てを埋め込む）と持ち場の2本に、表示名と、部門長以上はロールの一覧を並行に足して3〜4本にした（PC の画面で、先読みにも入れない）。
10. **表示名は id で絞らずに読む**：/shift と /tasks を 2 秒以内に開くため、表示名（profiles）を自分の割り当て・作業と並行に読む。id が届く前に送るので、RLS が返すもの全部（自分が総務である年度のメンバー。年度に 100 人ほど）を読む。
11. **部門員の表では「総務でない人」を分けない**：部門員はほかの人のロールを読めない（year_roles は自分の行だけ）ので、閲覧のみに変わった人の割り当ても数に入れる。部門長以上の表とダッシュボードは分ける（外すのは部門長以上）。
12. **カードの文の足りない場合**：計画の例にない「今日の分は終わりました」「あなたのこれからのシフトはありません」「これからの時間枠はありません」「作業はまだありません」を足した（過去にだけ枠がある・時間枠が全部過去・作業がない、のとき「まだありません」と誤って言わないように）。

18. **要件の共有の文は書き換えず、自分の段落・項・行を足す**：計画の「04「共通レイアウト」と D-45 も直す」などを、並行の T19・T21 とぶつからない形で書いた。02 の共有の文（マイグレーションの一覧の段落、監査の表の一覧、変えられない列、楽観ロック、段の一覧、can_lead の説明）と、04 の共有の文（画面の分け方、共通レイアウトの読み込み・ナビ・印刷、ダッシュボードの欄の締切と予定・読み込みと失敗・読むもの、直接の書き込みの一覧、(A)・(B1)・(B2)）は書き換えず、02 には 0017 の段落・設計上の決めごとの「シフト・作業」の項（監査・楽観ロックを含む）・段の一覧の「シフト・作業」の項を、04 には共通レイアウトの「シフト・作業の読み込み」「シフト・作業のナビ」の項・ダッシュボードの「シフト・作業」の項・(A)〜(B2) の「シフト・作業」の項を足した（T19・T21 と同じ足し方。マージでぶつかったら両方を残す。D-52）。共有の文にまとめるかは、3つのマージの後にリードが決める。00 の画面の数の文（「…15画面」）と A-1 も同じ理由で直していない。

#### 2.3 二重の割り当てと「総務だけ」

- 時間枠は重ならないので、同じ人が同じ時刻に2か所にいるのは「同じ時間枠に2行」のときだけになる。これは主キー (slot_id, user_id) の 23505 で DB が止める（トリガーも勧告的ロックも要らない）。
- 時間枠の重なりは、shift_slots のトリガー（before insert、update of starts_at・ends_at）で止める。
  - 年度ごとの勧告的ロックを取ってから、[開始, 終了) の重なりを確かめる。重なれば `invalid_input {field: starts_at, reason: overlap, slot_id}`。
  - 隣り合う枠（9:00〜10:00 と 10:00〜11:00）はよい。
  - 書けない人（can_lead でない）ではロックを取らずに RLS に任せる（02 の約束）。
- 総務だけ：shift_assignments（user_id）と tasks（assignee_id）のトリガー（before insert・update。値が変わるときだけ）で確かめる。
  - その年度の year_roles の行を for share で読み、admin・head・deputy_head・staff でなければ `invalid_input {field, reason: not_soumu}`。
  - DEFINER・`search_path = ''`。閲覧のみ・店長・副店長・ロールのない人は入らない。
  - for share で読むので、閲覧のみへのロールの変更と同時に入ることも止まる。
- 画面：人を選ぶ一覧で、その時間枠に入っている人は「受付に入っています」と出して押せなくする。移すときは duty_id の更新1回で行う（消してから足さない）。

| 名前 | 呼べる人 | 動作 |
| --- | --- | --- |
| set_task_status(task_id, status, base_updated_at) → tasks | 総務で、その作業の担当者か部門長以上 | 状態だけを変える（RLS は列を分けられないので RPC にする）。完了から戻すのもよい。確かめの順は下 |
| add_shift_slots(year_id, slots, needs) → setof shift_slots | 部門長以上 | 「1日分をまとめて作る」。時間枠（`[{starts_at, ends_at}]`、1回に 96 まで）と、その全部に同じ必要人数（`[{duty_id, required_count}]`）を1回で作る（2つの表をまとめて変えるので RPC）。重なり・その年度にない持ち場・範囲外は invalid_input（field・reason）。理由は「シフトの時間枠」 |

set_task_status の確かめの順：
1. lock_year：作業がない・その年度の総務でない → forbidden（有無を漏らさない）。年度が終了 → invalid_state。
2. status か base_updated_at が null → invalid_input。
3. 担当者でも部門長以上でもない → forbidden。
4. updated_at が違う（ミリ秒まで比べる）→ conflict（detail は id）。
5. 理由「作業の状態」を置いて書く。

#### 2.7 ロールを外したとき

| 起きること | 割り当て | 作業 |
| --- | --- | --- |
| remove_role（year_roles の行が消える。終了した年度でも） | 外部キーで、その年度のその人の割り当てが消える（ますの人数が減り「足りない枠」に出る） | 担当者が空になる（状態はそのまま。「担当者のいない作業」に出る） |
| set_role で閲覧のみにした（行は残る。管理者だけの操作） | 残す。表で「総務でない人」と出し、人数に数えない（部門長以上が外す） | 残す。「担当者が総務でない」と出す（本人は RPC で変えられない） |
| アカウントの削除 | year_roles の連鎖で消える | 空になる |

- 消えた行は監査に残る。理由は remove_role に入れた理由、した人は外した人になる。
- year_roles・remove_role・set_role は変えない。T20 の表に外部キーを足すだけで済む。
- ロックの順は「year_roles の行 → 割り当て・作業の行」。remove_role の連鎖も T20 のトリガーも同じ向きで取る。トリガーは値が変わるときだけ year_roles を読むので、担当者を変えずに作業を直す書き込みとはデッドロックしない。

#### 2.8 年度の状態・複製

- 準備中〜確定は書ける。確定中も書ける（当日に直すため）。終了は読むだけ（can_lead と RPC の invalid_state で守る）。
- create_year_from は T20 の表を写さない（日時と人が年ごとに違う）。create_year_from は変えず、pgTAP の 020 で写らないことを確かめる。

#### 2.9 書き込みの道（04「DB関数とブラウザ側の処理」の分け方）

| 書き込み | 道 | 応答が届かなかったとき |
| --- | --- | --- |
| 持ち場・時間枠を足す | insert（画面が id を作る） | (B1) |
| 持ち場・時間枠を直す・消す | updateWithLock・deleteChecked（updated_at の文字列のまま） | (B1) |
| 必要人数 | upsert（数の絶対値） | (A) |
| 割り当てる・外す・移す | insert（主キー (slot_id, user_id)）・delete・update（変わった行を受け取る） | (B1) |
| 作業を足す・直す・消す | insert（id）・updateWithLock・deleteChecked | (B1) |
| 作業の状態 | RPC set_task_status | (B1)（楽観ロック） |
| 1日分をまとめて作る | RPC add_shift_slots | (B2)（その日の時間枠を読み直して確かめてから） |

### 3. 画面

#### 3.1 機能の登録とナビ

- MODULES に `{ id: 'shifts', label: 'シフト・作業', homeHref: '/shifts' }` を、PORTAL_PROVIDERS に shiftsPortalProvider を、どちらも最後に1行足す。
- ナビの見出し「シフト・作業」に、自分のシフト（/shift）・シフト表（/shifts）・作業一覧（/tasks）を置く。
  - 印刷（/shifts/print）は nav: false。
  - どれも総務（SOUMU）が開ける。閲覧のみ・店長・副店長には見出しごと出ず、URL で開くと権限なしになる。
- パスは /stock・/stocks と同じ並べ方にする（単数は自分のスマホの画面、複数は一覧）。id と表示の切り替えはクエリ（`?day=`・`?task=`・`?filter=`）で渡す。

#### 3.2 立場ごとの見え方

| 画面 | 部門長以上 | 総務部門員 | 端末 |
| --- | --- | --- | --- |
| 自分のシフト /shift | 自分の枠（部門長以上も割り当てられる） | 自分の枠 | スマホ |
| シフト表 /shifts | 作る・直す（時間枠・持ち場・必要人数・割り当て） | 読むだけ（自分の名前を目立たせる） | PC（狭い幅では時間枠ごとの縦並び） |
| 印刷 /shifts/print | 日ごとの表・人ごと | 同じ | PC |
| 作業一覧 /tasks | 足す・直す・消す・担当を決める・状態を変える | 自分が担当の作業の状態を変える。ほかは読む | PC・スマホ |

終了した年度では、どの画面も読むだけにし、総務に「終了した年度のため、シフトと作業は読むだけです」の帯を出す。最新でない年度は今までの帯を出す。

#### 3.3 シフト表 /shifts

- 日のタブ（`?day=YYYY-MM-DD`）：時間枠のある日を並べる。1日目から数えた日なら「前日（10/15）」、ほかは「10/18（土）」と出す。既定は今日か、次に時間枠のある日。
- 表：
  - 行は時間枠（早い順）、列は持ち場（sort_order → 名前 → id）。
  - ますには名前と「2/3」を出す。足りなければ「あと1人」（注意の色と文字）、多ければ「+1」。ますのない所は「—」。
  - 行の終わりと列の下に合計を出す。
- 部門長以上の操作：
  - 「1日分をまとめて作る」：日付・始まり・終わり・区切り（30・60 分など）・持ち場ごとの必要人数を入れ、並ぶ時間枠を見てから作る（add_shift_slots）。
  - 時間枠の追加・時刻の変更・削除、持ち場（名前・場所・説明・並び）の追加・変更・削除。割り当てがあるときは、人数を出して確かめる。
  - ますを押すと、必要人数（CountStepper）と人を選ぶ一覧を出す。一覧にはその年度の総務を、表示名・ロール・その日の枠の数つきで並べる。その時間枠に入っている人は押せない。ここから割り当てる・外す・ほかの持ち場へ移す。
- `?filter=short`：足りないますだけを目立たせる（ダッシュボードから来るとき）。
- 最後に読み込んだ日時と「読み直す」を出す。画面に戻ったときと 60 秒ごとに読み直す（Realtime は CI で起動しないので使わない）。
- 表は見出しつきの table にする（読み上げは「9:00〜10:00 受付 2/3 人」）。足りない・多いは色だけで表さない。

#### 3.4 自分のシフト /shift（スマホ）

- 自分の割り当てを日ごとに並べる。今日を先頭にし、終わった日は畳む。
- 1件に出すもの：時刻・持ち場・場所・説明・同じますの人の名前。「今」「次」の印。
- 空のときは「あなたのシフトはまだありません」。下に「シフト表を見る」を置く。
- 読み取りは2本（7. 速さ）。表の編集の部品は読み込まない。

#### 3.5 作業一覧 /tasks

- 絞り込み（`?filter=`）：自分の作業（部門員の既定）・すべて（部門長以上の既定）・未完了・締切を過ぎた・締切が近い・担当者なし。`?task=` でその作業を目立たせる（ダッシュボードから来るとき）。
- 上に進み具合を出す：「完了 12／20（作業中 5・未着手 3・締切を過ぎた 2）」。
- 1件に出すもの：題名・状態・担当者・締切（過ぎていれば注意の色）・説明・直した人と日時。
- 状態のボタン（未着手・作業中・完了）：担当者と部門長以上に出す（set_task_status）。conflict なら読み直して知らせる。
- 部門長以上：
  - 「作業を足す」と編集のダイアログ：題名・説明・担当者（その年度の総務）・締切の日付と時刻（時刻の既定は 17:00）。入力は下書きに置く（お知らせと同じ）。
  - 削除（確かめのダイアログつき）。
- 広い PC では表、狭い幅ではカードの縦並びにする（お知らせ一覧と同じ）。

#### 3.6 印刷 /shifts/print（nav: false）

- `?day=` と `?view=table|people` で切り替える。ヘッダーとナビは隠す（QR の印刷と同じ）。`useSearchParams` は Suspense に包む。
- 日ごとの表：A4 横。持ち場が多い日は列を分ける。足りないますは「あと1人」と文字で出す。
- 人ごと：1人1枚のカード。紙で配るときと、当日に通信が切れたときのため。

#### 3.7 エラー（lib/errors.ts に足す）

| 起きたこと | 文言 |
| --- | --- |
| 23505（割り当て） | この人は同じ時間枠に、ほかの持ち場で入っています |
| invalid_input（reason: overlap） | ほかの時間枠と時間が重なっています（9:00〜10:00） |
| invalid_input（reason: not_soumu） | 総務（管理者・総務部門長・総務副部門長・総務部門員）だけを割り当てられます |
| 23503（ます・時間枠が先に消えた） | 時間枠か持ち場がほかの人に消されました。読み直しました |
| 23505（持ち場の名前） | 同じ名前の持ち場があります |
| 更新・削除が 0 行 | 読み直して not_found・conflict・forbidden に分ける（(B1)） |

### 4. ダッシュボード

**プロバイダ `shifts`**
- kinds は総務だけ。閲覧のみ・店長・副店長には何も出さない。
- 読み取りの結果を使う欄は、要対応・締切と予定・カードの3つ。読み込み中と失敗は、この3つの欄にシフト・作業の分だけ出る。fromYear はない。
- 読む分は軽いモジュール lib/modules/shifts/portal-read.ts に置く（/ の先読みも同じものを使う）。

- 自分の user_id は、queryFn の中でセッションから取る（PortalContext を変えない）。components/portal と portal.ts の型も変えない（専用の欄を作らない。Q9）。

**カード「シフト・作業」**

| /tasks（部門員・スマホ） | 2本（その年度の作業／表示名。部門長以上は＋ロールの一覧） | 同じく足す | 2 秒以内 |

- JS：部門員が開く /shift と /tasks には、表の編集やダイアログを入れない（部門長以上の部品は動的 import）。最初に読む JS は /my と同じくらい（約 320 KB）に収め、`node scripts/first-load-js.mjs` で確かめる。
- DB：索引は year_id から始め、select は D-47 の形にする。1年の量の見込み（時間枠 50・必要人数 250・割り当て 800・作業 200）なら、どれも数ミリ秒で済む。
- 2 秒を超えたら、部門員の / の先読みからシフトを外す（記録・先送りだけにする）か、読む列を減らす。

### 9. ユーザーに確かめたいこと

| # | 確かめたいこと | 推奨（既定） | 理由 |
| --- | --- | --- | --- |
| 1 | 時間枠は日ごとに重ならない共通の区切りにし、すべての持ち場が同じ時間枠を使う | はい | 決定1の「固定の時間枠」のとおりで、表が素直になり、二重の割り当てを主キーで止められる。持ち場ごとに時刻を変えるなら、重なりをトリガーで確かめる形にする（+S） |
| 2 | 二重の割り当ては DB で止める（警告で済ませない） | 止める | 当日に1人が2か所にいる誤りを作らない。わざと兼ねるなら「本部・見回り」のような1つの持ち場にする |
| 3 | 部門員もシフト表の全体（ほかの人・足りない枠）を見られる | 見られる（スマホの既定は自分のシフト） | 同じ枠の人や交代の相手が分かる。総務の中では名前をもう見られる。自分の分だけにするなら、RLS を「自分の行だけ」にする |
| 4 | 部門員は全員の作業を読める（状態を変えられるのは自分が担当の作業だけ） | 読める | 進み具合を総務で共有できる。個人情報は増えない |
| 5 | 作業の担当者は1人（空でもよい） | 1人 | 決定3の「担当の部門員が状態を変える」に合う。何人かでやる作業は分けて作る |
| 6 | 作業の締切は日時で入れる（時刻の既定 17:00）。画面の言葉は「締切」 | はい | ダッシュボードの「締切 10/5 17:00」と同じ形・言葉になる。日付だけにすると終日の扱いが要る |
| 7 | ロールを外したら、その年度の割り当てを消し、作業の担当者を空にする（終了した年度でも。記録は履歴に残る） | はい | 総務でない人が枠を埋めているように見えない。外し忘れもない。year_roles と remove_role を変えず、外部キーだけでできる |
| 8 | 締切と予定に出すのは、自分が担当の作業の締切と、自分のシフトのある日だけ | はい | 欄の 8 件をほかの機能と分け合う。部門長以上は全体を要対応とカードで見る |
| 9 | 今日のシフトは要対応とカードに出す（ダッシュボードに専用の欄を作らない） | はい | 共有の部品と型を変えずに済み、T18 の後半とぶつからない。専用の欄にするなら、D-52 と 04「ダッシュボード」を先に直す（+S） |
| 10 | 閲覧のみ・店長・副店長には、シフトも作業も見せない | 見せない | 総務の中の割り当てで、学生の名前が入るため |
| 11 | 下書き・公開の区別は持たない（できたら「お知らせ」で知らせる） | 持たない | 作るのは部門長以上だけ。区別を持つと RLS と画面が増える |
| 12 | 書き出しは印刷だけにする（CSV・年度データの JSON は後で）。年度の複製で持ち場も写さない | はい | 印刷で当日の通信の切れに備えられる。持ち場は数行なので毎年入れ直せる（create_year_from を変えない） |
| 13 | DB と画面を1つの PR で出す（T17 と同じ） | 1つ | CLAUDE.md の 1チケット＝1PR。本番はまだ使っていないので、マージから migrate.yml までの読み込みの失敗の表示は受け入れる。レビューは前半・後半の2回に分ける |
| 14 | 機能は1つにする（ナビの見出し「シフト・作業」に3項目） | 1つ | ナビとカードを増やしすぎない |
