### 1. 目的とユーザーの決定

**目的**：団体が出す書類（出店計画・食品の届けなど）をアプリの中で受け取ります。総務が中身を確かめて承認か差し戻しをし、締切と状況を1か所で追えるようにします。紙・メール・LINE での受け渡しと、未提出を確かめる往復をなくします。

ユーザーの決定（2026-10-31）は上の表のとおり。

- **機能**：id は `documents`、名前は「提出物」。
  - 画面は /documents（総務：提出状況）と /document（店長・副店長：自団体の提出物）の2つ。/requests と /request と同じ並べ方。
- **v1 で作らないもの**：メール・プッシュの通知、既読、ファイルの中身の検査、まとめてのダウンロード（zip）、様式（ひな形）のファイル、団体ごとの免除。
- **01 の用語集に足す言葉**：
  - 提出物 document（表 documents）、提出 document submission、提出の状態 document_status、提出物のファイル document file
  - 承認・差し戻し、代理の提出、どの提出にも属さないファイル（orphan）
  - コードの変数名は `doc` にする（ブラウザの `document` とぶつけない）。

### 2. DB（0016_documents.sql）

#### 2.1 列挙・表・ビュー

- 列挙 `document_status`：not_submitted 未提出 / submitted 提出済み / returned 差し戻し / approved 承認

| 表 | 主な列 | 書き込み | 監査 |
| --- | --- | --- | --- |
| documents（提出物） | id・year_id（cascade）・title・description（2000 字）・deadline・target_categories・food_only（Q8）・requires_file（Q7）・files_deleted_at・created_by／updated_by・unique (year_id, title)・unique (id, year_id) | 部門長以上が画面から直接書く（下の注） | する |
| document_submissions（提出。団体×提出物で1行。最初の操作で作る） | 主キー (document_id, group_id)・year_id・status・submitted_at／by・proxy（代理）・reviewed_at／by・review_note（差し戻しの理由・承認のメモ。1000 字） | RPC だけ | する（理由つき） |
| document_files（ファイル） | id（画面が作る）・year_id・document_id・group_id・object_path（unique）・content_type（3 種）・size（申告。1 B〜10 MiB）・created_by | RPC だけ | する（元のファイル名は持たない。Q16） |

表の注：
- documents の列：
  - title は 1〜100 字。notices・events と同じ「25 文字の空白」の CHECK を付ける。
  - deadline は timestamptz で必須。2000〜2200 年の CHECK を付ける。
  - target_categories は group_category[] で 1〜4 個。トリガーで重なりを除いて並べる。
  - requires_file の既定は true。created_by／updated_by は set_actor が入れる。
- documents の書き込み：RLS の can_lead で守る。終了の年度は読むだけ。
  - 登録は、画面が id を作って insert する。変更・削除は updated_at を条件にする（(B1)。T18 と同じ）。
- document_submissions の year_id：複合外部キーで、提出物・団体と同じ年度に縛る（cascade）。
- document_files の外部キーと path：
  - 提出の行へ cascade する。
  - object_path は、列から作った `{year_id}/{group_id}/{document_id}/{id}.{pdf|jpg|png}` と一致する CHECK を付ける。

ビュー（どちらも `with (security_invoker = true)`）：
- `v_document_status`：提出物 × 対象の団体（区分・飲食）× 提出の行。行がなければ未提出として出す。
- `v_document_files`：ファイルの行に、Storage に届いたかと実際の大きさを足す（storage.objects を読む）。

トリガー：
- set_timestamps（3表）
- set_actor（documents）
- 対象の区分の並べ直し（documents）
- check_immutable：3表の year_id、提出の document_id・group_id、ファイルの鍵と path
- tg_audit（3表）

そのほか：
- 振り分けの入力ではないので、版（allocation_version）を増やさず、確定中の守りもない。
- 年度の複製（create_year_from）では写さない（D-54 と同じ）。写すのは「前年度から写す」。

| --- | --- | --- | --- | --- | --- |
| documents | その年度の全部 | 全部 | 自団体が対象のもの（注） | 何も（Q5） | 何も |
| document_submissions | 全部 | 全部 | 自団体の行 | 何も | 何も |

注：店長・副店長の判定には、新しい集合の関数 `private.my_group_document_ids()` を使います。

#### 2.3 RPC

どの RPC も SECURITY DEFINER・`search_path = ''` で、最初にロールを確かめます。その後、年度の行を for share でロックしてから状態を見ます。終了の操作とは順に処理され、提出どうしは並行に進みます。

| RPC | 呼べる人 | すること |
| --- | --- | --- |
| reserve_document_file(document_id, group_id, file_id, content_type, size) | 店長・副店長（未提出・差し戻しのとき）、部門長以上（承認でなければ。代理） | ファイルの行を予約して path を返す（下の注） |
| discard_document_file(file_id) | 同上（届く前の予約は状態によらない） | ファイルの行を消す。Storage の物は「どの提出にも属さないファイル」になり、画面が消す |
| submit_document(document_id, group_id, base_updated_at) | 店長・副店長、部門長以上（代理） | 未提出・差し戻し → 提出済み。ファイルが要る提出物は1つ以上必要で、予約が全部 Storage に届いていること |
| withdraw_document(document_id, group_id, base_updated_at) | 同上 | 提出済み → 未提出（Q13） |
| approve_document(document_id, group_id, note, base_updated_at) | 部門長以上 | 提出済み → 承認。未提出・差し戻しから承認するときはメモが必須（紙で受け取ったとき。Q9） |
| return_document(document_id, group_id, note, base_updated_at) | 部門長以上 | 提出済み・承認・差し戻し → 差し戻し。理由（1〜1000 字）が必須 |
| previous_year_documents(year_id)・copy_previous_documents(year_id, document_ids) | 部門長以上 | 複製元（prev_year_id）の提出物を見せ、選んだものを写す（下の注） |
| delete_year_document_files(year_id, reason) | 管理者（終了の年度だけ） | その年度のファイルの行を全部消し、files_deleted_at を入れる（Q3） |
| document_orphan_paths(year_id) | 部門長以上、店長・副店長 | 自分が消せる「どの提出にも属さないファイル」の path を返す（画面の片付け用） |
| document_storage_usage(year_id) | 部門長以上 | bucket の合計と上限、その年度のファイルの数と大きさ、片付けていないファイルの数を返す（カードと要対応に使う） |

RPC の注：
- reserve_document_file：
  - 提出の行がなければ作る。
  - 数（Q2）、形と大きさ（Q1）、bucket 全体の容量（900 MiB）を確かめる。
  - 同じ file_id で送り直したら、同じ行を返す。
- copy_previous_documents：締切は1日目の差の日数だけずらす（時刻は同じ）。同じ名前のものは飛ばす（Q10）。

約束：
- **楽観ロック**：base_updated_at はミリ秒まで比べる（02 の RPC の決まり）。違えば conflict。
- **エラーの順**：
  1. forbidden
  2. invalid_state（終了）
  3. invalid_input
  4. not_found
  5. forbidden（段）
  6. invalid_state（状態。detail に status と reason〔not_editable・not_uploaded・storage_full など〕）
  7. conflict

  detail には、メールもファイルの中身も入れない。
- **監査の理由**：「提出物の提出」「提出物の代理の提出」「提出の取り消し」「提出物の承認」「提出物の差し戻し」「提出物のファイルの削除」

#### 2.4 状態と移り方

| 今 | 操作 | する人 | 次 |
| --- | --- | --- | --- |
| 未提出・差し戻し | ファイルを足す・外す | 店長・副店長／部門長以上（代理） | そのまま |
| 未提出・差し戻し | 「提出した」 | 同上 | 提出済み（締切の後なら「締切の後」の印。Q6） |
| 提出済み | 「提出を取り消す」 | 同上 | 未提出 |
| 提出済み | 承認 | 部門長以上 | 承認 |
| 提出済み・承認・差し戻し | 差し戻し（理由） | 部門長以上 | 差し戻し（承認の取り消しと、理由の書き直しも兼ねる） |
| 未提出・差し戻し | 紙などで受け取って承認（メモ） | 部門長以上 | 承認（Q9） |
| どれでも | — | — | 終了の年度では変えられない（例外は管理者のファイルの削除だけ） |

### 3. Storage（ファイルの置き場）

#### 3.1 bucket と path

- **bucket `documents`**：
  - 非公開で、1ファイル 10 MiB まで。形は `application/pdf`・`image/jpeg`・`image/png`（Q1）。
  - 0016 の中で `insert into storage.buckets … on conflict (id) do update` として作る。
  - config.toml の `[storage.buckets]` は使わない。ローカル・CI・本番を同じマイグレーションでそろえるため。
- **path**：`{year_id}/{group_id}/{document_id}/{file_id}.{pdf|jpg|png}`
  - DB が作り、CHECK で形を固定する。
  - 日本語や個人名を入れない。Storage のキーは使える文字が限られ、日本語の名前は Invalid key になることがある。

#### 3.2 storage.objects のポリシー

- bucket が documents のものだけに効かせる。
- 集合の関数で、問い合わせごとに1回だけ判定する（D-47）。
- anon 向けのポリシーは作らない。storage の表の権限（Supabase の既定）は変えず、ポリシーで守る。

| 操作（Storage API） | 許す条件 |
| --- | --- |
| select（ダウンロード・署名つき URL。消すときにも要る） | 1つ目のフォルダが「自分が部門長以上の年度」、または2つ目が自分の団体 |
| insert（アップロード） | name が「自分が予約した、まだ届いていない、今書ける提出の path」。update のポリシーは作らない |
| delete（削除） | name が「自分の範囲で、どの提出にも属さないファイル」。DB の行がある物は消せない |

ポリシーの注：
- select は `private.my_role_year_ids('{admin,head,deputy_head}')` と `private.my_group_ids()` で判定する。Q4 で部門員にも見せるなら、ここに足す。
- insert は新しい `private.my_document_upload_paths()` で判定する。update のポリシーがないので、上書き・移動・upsert はできない。
- delete は新しい `private.my_document_orphan_paths()` で判定する。範囲は select と同じ。DB の行がある物は消せないので、承認したファイルは Storage からも消せない。

（注：insert の「まだ届いていない」は、SQL にするときに外した。送り直しを 409〔もう届いていた〕で分けるため。「判断したこと」の 3）

#### 3.3 流れ

- **上げる**：
  1. 画面で形と大きさを確かめる。PDF・JPEG・PNG の先頭のバイトも見る。
  2. JPEG は作り直す。長い辺を 2500px までにし、位置情報などの EXIF を消す（Q1）。
  3. reserve を呼ぶ。
  4. `upload(path, blob, { contentType, upsert: false })` で上げる。
  5. 一覧を読み直す。届いたかは v_document_files で分かる。

  通信が切れたら、同じ path へ送り直す。409 が返れば、もう届いていた。
- **開く・保存**：
  - 押したときに `createSignedUrl(path, 60)` を作る。
  - 保存のときは、`download` に「{提出物}_{団体}_{n}.pdf」を渡す（個人名を入れない）。
  - URL はキャッシュ・下書き・ログに残さない。
  - ポップアップで止められないよう、押したときに先にタブを開き、後から URL を入れる。
- **差し替え（出し直し）**：未提出・差し戻しの間に、古いファイルを外す（discard の後、すぐ Storage から remove）。新しいものを上げて「提出した」を押す。
- **提出物・団体を消したとき**：
  - DB は cascade で行を消す。Storage の物は SQL では消せない（`storage.protect_delete`）。
  - 行がなくなった物は「どの提出にも属さないファイル」になる。部門長以上が /documents を開いたとき、画面が remove する。店長・副店長は、外した直後に画面が remove する。
  - それでも残っていれば、要対応で知らせる。
- **年度の終了**：
  - 終了の年度でも、ファイルは読める・開ける。
  - 管理者が「この年度のファイルをすべて削除」を押すと、行を消し、画面が Storage から消す。
  - 状態・日時・理由は残す（Q3）。
- **容量の守り**：予約のときに止める。1提出 5 つまで、1つ 10 MiB まで、bucket 全体で 900 MiB まで（無料プランの 1 GB の手前）。

#### 3.4 ローカル・CI・本番

| 場所 | 直すこと |
| --- | --- |
| CI の e2e ジョブ | `supabase start -x …` の除外から storage-api を外す。imgproxy は除外のまま（画像の変換は使わない）。取得と起動で +30 秒ほど |
| CI の db ジョブ | `supabase db start` のまま（下の注） |

### 5. 画面

#### 5.1 ナビ・登録・立場

- 登録に `{ id: 'documents', label: '提出物', homeHref: '/documents' }` を足す（T18 の行の後）。
- ナビの見出し「提出物」に、2つの項目を置く。
  - 「提出状況」（/documents。総務）
  - 「自団体の提出物」（/document。店長・副店長）

| 画面 | 管理者 | 部門長・副部門長 | 部門員 | 閲覧のみ | 店長・副店長 |
| --- | --- | --- | --- | --- | --- |
| /documents 提出状況（PC） | 全部（下の注） | 管理者と同じ（ファイルの削除だけはできない） | 状況だけ（ファイルは出さない） | —（Q5） | — |
| /document 自団体の提出物（スマホ） | 兼ねていれば | — | — | 兼ねていれば | 上げる・外す・「提出した」・取り消す、差し戻しの理由を見る |

注：管理者の「全部」は、開く・保存・承認・差し戻し・代理・設定・前年度から写す・終了の年度のファイルの削除です。

#### 5.2 /document（店長・副店長。スマホ）

- **団体の切り替え**：`?group=` で切り替える（/request と同じ）。
- **カード**：対象の提出物を、締切の早い順にカードで出す。
  - 名前、締切（過ぎたら「締切を過ぎました」）、状態の印、説明
  - 差し戻しの理由（目立つ枠で）、承認の日時、「総務が代わりに提出しました」
- **ファイル**：
  - 「ファイル 1（PDF・1.2 MB・10/5 17:00）」のように出し、「開く」と「外す」を置く。外せるのは未提出・差し戻しのときだけ。
  - 届かなかったものは「アップロードできませんでした」と出し、「もう一度」「外す」を置く。
- **ファイルを追加**：`accept="application/pdf,image/jpeg,image/png"` で、複数を選べる。上げている間は「アップロード中…」と出し、その間に離れるときは確かめる。
- **提出した**：「提出すると、総務が確かめるまでファイルを変えられません」と確かめてから送る。提出済みには「提出を取り消す」を出す。
- **書く前の確かめと読み直し**：
  - 最新でない年度に書く前に確かめる（D-31）。終了の年度は読むだけ。
  - 店長と副店長が同時に操作して conflict になったら、読み直して、もう一度押してもらう（(B1)）。
  - （注：レビューの F1 で分かったこと。提出・取り消し・承認で同じ操作が重なったときと、成功した後の送り直しは、conflict でなく invalid_state〔not_editable と今の status〕になる。画面は読み直して今の状態を出す。conflict は、読んだ後にほかの人がファイルを足す・外すなどで版が進んだとき。「SQL の約束」の RPC の共通の決まり）

#### 5.3 /documents（総務。PC）

- **タブと URL**：
  - タブは「提出状況」と「提出物の設定」の2つ。設定は部門長以上だけに出す。
  - URL のパラメータは `?tab=`・`?status=`・`?document=`・`?group=`。status は 未提出・承認待ち・差し戻し・承認・締切を過ぎた のどれか。
- **提出状況**：
  - 団体を行、提出物を列にした表。団体は sort_order → 名前 → id の順、提出物は締切 → 名前 → id の順に並べる。
  - セルに状態の印を出す（締切の後の提出・代理の印も）。
  - 狭い幅では、提出物ごとの一覧にする。
  - 最後に読み込んだ日時と「読み直す」を出す。部門長以上には「CSV で保存」も出す。
- **セルのシート**：セルを押すと、横にシートを開く。
  - 状態・日時・した人（表示名）・前の差し戻しの理由
  - ファイル（開く・保存）
  - 操作：承認、差し戻し（理由は必須）、代理（ファイルを足す・提出済みにする）、紙で受け取ったとして承認
- **提出物の設定**：
  - 一覧：名前・締切・対象・ファイルが要るか・承認の数
  - 追加・編集：題名・説明・締切（Asia/Tokyo）・対象の区分・飲食だけか・ファイルが要るか
  - 削除：「提出 N 件とファイル M 件も消えます」と確かめる。
  - 「前年度から写す」：複製元の提出物を、ずらした締切と一緒に並べて選ぶ。
- **片付けと終了の年度**：
  - 開いたときに「どの提出にも属さないファイル」があれば、裏で消す。
  - 終了の年度は読むだけ。管理者には「この年度のファイルをすべて削除（N 件・X MB）」を出し、先に要るものを保存するよう書く。

#### 5.4 書き込みの決まり

04 の「通信が切れたとき」の分け方に当てはめます。(B2) になる書き込みはありません。

| 書き込み | 決まり |
| --- | --- |
| 提出物の登録・変更・削除（直接） | (B1)：画面が作る id と、updated_at の条件 |
| 予約・上げる | (B1)：file_id と path が鍵（送り直しても二重にならない） |
| 提出・取り消し・承認・差し戻し | (B1)：base_updated_at。conflict なら読み直して、入力を残す |
| 前年度から写す・年度のファイルの削除・片付け | 何度しても同じ結果になる |

### 6. ダッシュボード

プロバイダは lib/modules/documents/portal.ts に置きます（D-52）。

- **読むもの**（軽く読む。版と振り分けは読まない）：
  - 総務：v_document_status の (document_id, group_id, status, submitted_at) と、提出物の (id, title, deadline)
  - 部門長以上：上に加えて document_storage_usage
  - 店長・副店長：自団体の行（名前・締切・状態・理由）
  - 閲覧のみ：何も読まない
- **結果を使う欄**：要対応・締切と予定・カードの3つ。

（注：v_document_status に提出物の題名・締切などを入れたので、総務の読み取りもビューの1回にできる。「判断したこと」の 17）

#### 要対応

| 立場 | 出すとき | 文 | 度合い | 行き先 |
| --- | --- | --- | --- | --- |
| 部門長以上 | 提出済みがある | 承認待ち N 件 | ふつう | /documents?status=submitted |
| 総務 | 締切を過ぎた未提出・差し戻しがある | 締切を過ぎた未提出 N 件（差し戻しを含む） | 部門長以上はふつう、部門員は参考 | /documents?status=overdue |
| 部門長以上 | どの提出にも属さないファイルがある | 片付けていないファイル N 件（提出状況を開くと消します） | 参考 | /documents |

#### E2E（e2e/t19-documents.spec.ts。CI で storage-api を起動する）

- **通しの流れ**：
  1. 部門長以上が提出物を登録する。
  2. 店長（スマホの幅）が、テストの中で作った小さな PDF を上げて「提出した」を押す。
  3. 部門長以上が開く（新しいタブで PDF）・保存する（名前と中身を確かめる）。
  4. 部門長以上が差し戻す。店長のホームの要対応に理由が出る。
  5. 店長が差し替えて出し直し、部門長以上が承認する。
  6. ダッシュボードの要対応・締切と予定・カードを確かめる。
- **守りの確かめ**：
  - 部門員にはファイルを出さない。閲覧のみにはナビがない。
  - ほかの団体の path は Storage が拒む。10 MiB を超えるもの・許さない形は Storage が拒む（REST で直接送る）。
  - 店長と副店長が同時に提出すると、後の方は invalid_state（not_editable）になり、読み直すと提出済みが出る（レビューの F1 で直した。計画では conflict と書いていた）。conflict は、片方がファイルを足した後に、もう片方が足す前に読んだ古い版で提出する場合で確かめる。通信を落とした後に送り直せる。
- **serial**：前年度から写す（prev_year_id のある年度で）。終了の年度でファイルを削除し、storage.objects が空になることを確かめる。
- 今の E2E の、ナビと / の読み取りの期待値も直す。

### 列挙型と表

```sql
create type public.document_status as enum ('not_submitted', 'submitted', 'returned', 'approved');
-- 表示名：未提出 / 提出済み / 差し戻し / 承認（画面の絞り込みでは submitted を「承認待ち」と呼ぶ）

-- 提出物（年度ごとの書類の種類と締切）。部門長以上が画面から直接書く（RLS の can_lead）
create table public.documents (
  id uuid primary key default gen_random_uuid(),   -- 画面は自分で作った id で insert する（(B1)）
  year_id uuid not null references public.years on delete cascade,
  title text not null,
  description text,                                -- 任意。空なら画面が null にする（D-33）
  deadline timestamptz not null,
  target_categories public.group_category[] not null,
  food_only boolean not null default false,        -- 飲食の団体だけ（Q8）
  requires_file boolean not null default true,     -- ファイルが要る（Q7）
  files_deleted_at timestamptz,                    -- 年度のファイルを削除した日時（delete_year_document_files だけが入れる。Q3）
  created_by uuid references auth.users on delete set null,
  updated_by uuid references auth.users on delete set null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint documents_title_check check (title <> ''
    and title = btrim(title, E'\t\n\u000b\f\r \u00a0\u1680\u2000\u2001\u2002\u2003\u2004\u2005\u2006\u2007\u2008\u2009\u200a\u2028\u2029\u202f\u205f\u3000\ufeff')
    and length(title) <= 100),
  constraint documents_description_check check (length(description) <= 2000),
  constraint documents_deadline_check check (
    (deadline at time zone 'Asia/Tokyo')::date between date '2000-01-01' and date '2200-12-31'),
  constraint documents_target_categories_check check (
    cardinality(target_categories) between 1 and 4 and array_position(target_categories, null) is null),
  constraint documents_year_id_title_key unique (year_id, title),
  constraint documents_id_year_id_key unique (id, year_id)          -- 提出の複合外部キーの参照先
);
create index documents_year_id_idx on public.documents (year_id, deadline);

-- 提出（団体×提出物で1行。最初の操作で作る。行がなければ未提出）。RPC だけで書く
create table public.document_submissions (
  document_id uuid not null,
  group_id uuid not null,
  year_id uuid not null,
  status public.document_status not null default 'not_submitted',
  submitted_at timestamptz,                        -- 最後に「提出した」を押した日時（未提出と、紙での承認では null）
  submitted_by uuid references auth.users on delete set null,
  proxy boolean not null default false,            -- 部門長以上が代わりに提出した（Q9）
  reviewed_at timestamptz,                         -- 承認・差し戻しの日時（最後のもの）
  reviewed_by uuid references auth.users on delete set null,
  review_note text,                                -- 差し戻しの理由・承認のメモ（最後のもの）
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (document_id, group_id),
  unique (document_id, group_id, year_id),         -- ファイルの複合外部キーの参照先
  constraint document_submissions_document_fkey foreign key (document_id, year_id)
    references public.documents (id, year_id) on delete cascade,
  constraint document_submissions_group_fkey foreign key (group_id, year_id)
    references public.groups (id, year_id) on delete cascade,
  constraint document_submissions_review_note_check check (review_note is null or (review_note <> ''
    and review_note = btrim(review_note, E'\t\n\u000b\f\r \u00a0\u1680\u2000\u2001\u2002\u2003\u2004\u2005\u2006\u2007\u2008\u2009\u200a\u2028\u2029\u202f\u205f\u3000\ufeff')
    and length(review_note) <= 1000)),
  constraint document_submissions_status_check check (
    case status
      when 'not_submitted' then submitted_at is null and not proxy
      when 'submitted' then submitted_at is not null
      when 'returned' then reviewed_at is not null and review_note is not null
      when 'approved' then reviewed_at is not null
    end
    and (not proxy or submitted_at is not null))
);
create index document_submissions_group_id_idx on public.document_submissions (group_id);
create index document_submissions_year_id_idx on public.document_submissions (year_id, status);

-- 提出物のファイル（Storage の物と1対1。行は足すか消すだけ）。RPC だけで書く
create table public.document_files (
  id uuid primary key,                             -- 画面が作る（reserve_document_file の p_file_id。既定値なし）
  year_id uuid not null,
  document_id uuid not null,
  group_id uuid not null,
  object_path text not null,
  content_type text not null,
  size integer not null,                           -- 申告の大きさ（バイト）
  created_by uuid references auth.users on delete set null, -- 予約した人（Storage に上げられるのはこの人だけ）
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint document_files_submission_fkey foreign key (document_id, group_id, year_id)
    references public.document_submissions (document_id, group_id, year_id) on delete cascade,
  constraint document_files_object_path_key unique (object_path),
  constraint document_files_content_type_check check (content_type in ('application/pdf', 'image/jpeg', 'image/png')),
  constraint document_files_size_check check (size between 1 and 10485760),       -- 1 B〜10 MiB
  constraint document_files_object_path_check check (object_path = year_id::text || '/' || group_id::text || '/'
    || document_id::text || '/' || id::text || '.'
    || case content_type when 'application/pdf' then 'pdf' when 'image/jpeg' then 'jpg' when 'image/png' then 'png' end)
);
create index document_files_submission_idx on public.document_files (document_id, group_id);
create index document_files_year_id_idx on public.document_files (year_id);
```

- 外部キーの on delete は 02 の決まりのとおり：年度・団体・提出物・提出へは cascade、記録のためのユーザー（created_by・updated_by・submitted_by・reviewed_by）は set null。提出・ファイルは複合外部キーで、提出物・団体と同じ年度に縛る（allocations・notice_groups と同じ）。

- path の uuid は `uuid::text`（小文字の 36 字）。拡張子は形から決める（pdf・jpg・png）。

### 書き込み（documents は直接、提出とファイルは RPC）

**documents（直接。RLS。T18 の events と同じ）**

- 書けない人の insert は 42501、update・delete は 0 行（画面は読み直して not_found・conflict・権限や状態の変化を分ける）。題名の重なりは 23505（documents_year_id_title_key）、送り直しの主キーの重なりも 23505（documents_pkey。画面は制約の名前で分ける）、CHECK の違反は 23514。
- 消すと提出とファイルの行も cascade で消える（監査に残る。理由は null）。Storage の物は残り、どの提出にも属さないファイルになる。

**RPC の共通の決まり**

- どれも SECURITY DEFINER・`search_path = ''`、execute は authenticated だけ。引数名は `p_` を付ける（下では省く）。
- 書き込みの RPC の始め（plan の 2.3）：
  1. ロール（forbidden）：対象の年度（団体の年度・ファイルの年度・p_year_id）がない、または呼んだ人が「呼べる人」でない。店長・副店長かは `private.is_group_member(group_id)`、部門長以上かは `private.has_any_role(year_id, '{admin,head,deputy_head}')`。
  2. 年度の行を `for share` でロックし、ロールをもう一度確かめ（待つ間に外されたとき。forbidden）、終了なら invalid_state（detail `{status: 'closed'}`）。delete_year_document_files だけは逆で、終了でなければ invalid_state（`{status, reason: 'not_closed'}`）。
  3. 入力（invalid_input。detail `{field, reason?}`）
  4. not_found（その年度にない提出物、団体が対象でない提出物。detail なし）
  5. 段の forbidden：使わない（どの RPC も 1 で決まる。計画のエラーの順の 5 は空き）
  6. 状態（invalid_state。detail `{status, reason}`。reason は not_editable・no_file・not_uploaded・too_many_files・too_many_orphans・storage_full）。提出・取り消し・承認で同じ操作が重なったとき（店長と副店長が同時に「提出した」を押した）と、成功した後の送り直しは、ロックを待った後の状態で invalid_state（not_editable と今の status）になる（7 の conflict より先。画面は読み直して今の状態を出す。差し戻しは差し戻しからもできるので、重なると conflict。レビューの F1。04 の「提出物」）
  7. 楽観ロック（conflict。detail `{document_id, group_id}`）：p_base_updated_at と提出の行の updated_at を `date_trunc('milliseconds', …)` で比べる。行がなければ版は null とみなす（null と null は同じ）
  8. 理由を置いて（`private.set_reason`）書く
- 書ける状態（「書ける」＝ファイルを足す・外す）：店長・副店長は未提出・差し戻し、部門長以上は承認でなければ（未提出・提出済み・差し戻し）。部門長以上で店長・副店長も務める人は部門長以上の決まり。
- 代理（proxy）：提出した人がその団体の店長・副店長でなければ真（部門長以上が自分の団体に出すときは代理でない）。
- 提出の行がなければ書くときに作る（同じトランザクション）。同じ提出への書き込みは、提出の行の `for update` で順に処理する。
- 例外の直し（D-19）：外部キーの違反（確かめた後に提出物・団体が消えた）→ not_found、CHECK の違反 → invalid_input（制約で field を決める）、クラス 22 → invalid_input。トップレベルの型つきの引数の形の誤り（22P02 など）は今までどおり PostgREST が返す。
- detail にメール・ファイルの中身・元のファイル名を入れない。

**reserve_document_file(p_document_id uuid, p_group_id uuid, p_file_id uuid, p_content_type text, p_size integer) returns document_files**

呼べる人：その年度の部門長以上（代理）、その団体の店長・副店長。

1. forbidden：団体がない（p_group_id が null を含む）、または呼んだ人がその年度の部門長以上でもその団体の店長・副店長でもない
2. 年度の行を for share。ロールをもう一度。終了 → invalid_state `{status: closed}`
3. invalid_input：p_document_id が null → `{field: document_id}`、p_file_id が null → `{field: file_id}`、p_content_type が3つの形のどれでもない → `{field: content_type}`、p_size が null か 1〜10485760 の外 → `{field: size}`、同じ id のファイルの行がほかの提出物・団体か、違う形・大きさで既にある → `{field: file_id, reason: in_use}`
4. not_found：その年度にその提出物がない、または団体が対象でない（区分・飲食）
5. 同じ id のファイルの行が同じ中身（提出物・団体・形・大きさ）で既にあれば、その行を返す（冪等。状態・数・容量は見ない。送り直しの (B1)）
6. 提出の行を作り（なければ。未提出）、for update でロックして状態を見る：書けない → invalid_state `{status, reason: not_editable}`。その提出のファイルの行が 5 つ → `{status, reason: too_many_files}`。その団体のフォルダ（path の2つ目のフォルダが p_group_id）の、どの提出にも属さない物（bucket documents の物で document_files に行がない）が 5 つ以上 → `{status, reason: too_many_orphans}`（レビューの T19-SEC-2。判断したことの 31）。勧告的ロック `pg_advisory_xact_lock(hashtext('gaapp.document_storage'), 0)` を取り、bucket documents の届いた物の大きさ（metadata の size）＋届いていない予約の申告＋p_size が 943718400（900 MiB）を超える → `{status, reason: storage_full}`
7. 理由は置かない（null）。ファイルの行を入れ（object_path は DB が作る。created_by は auth.uid()）、提出の行の updated_at を進めて（ファイルの組も提出の版で守る）、ファイルの行を返す

**discard_document_file(p_file_id uuid) returns text**

呼べる人：同上（届いていない予約は提出の状態によらない）。

1. forbidden：ファイルの行がない（p_file_id が null を含む）、または呼んだ人がその年度の部門長以上でもその団体の店長・副店長でもない（有無を漏らさない。delete_notice と同じ）

- new_deadline：`((deadline at time zone 'Asia/Tokyo') + (今の年度の festival_start − 複製元の festival_start) * interval '1 day') at time zone 'Asia/Tokyo'`（1日目の差の日数だけずらし、Asia/Tokyo の時刻は同じ）。exists_in_year：同じ題名の提出物がこの年度にある（写すと飛ばされる）。

**copy_previous_documents(p_year_id uuid, p_document_ids uuid[]) returns setof documents**

1. forbidden：その年度の部門長以上でない（年度がない）
2. for share・終了 → invalid_state
3. invalid_input（field: document_ids）：null か空 → `reason: required`、1000 を超える → `too_many`（unnest の前に数で見る）、null の要素か重なり → `invalid`、複製元の年度の提出物でない id がある（複製元がないときも）→ `not_in_prev_year`、ずらした締切が範囲（2000〜2200 年）の外 → `deadline_out_of_range`
4. 理由「提出物の前年度からの写し」。題名・説明・対象の区分・飲食だけ・ファイルが要るを写し、締切はずらす（files_deleted_at は写さない）。`on conflict (year_id, title) do nothing`（同じ題名は飛ばす。Q10）。写した行を返す（何度呼んでも同じ結果）

**delete_year_document_files(p_year_id uuid, p_reason text default null) returns integer**

1. forbidden：その年度の管理者でない（年度がない）
2. 年度の行を for share。ロールをもう一度。終了でない → invalid_state `{status, reason: not_closed}`
3. invalid_input：理由が 500 字を超える → `{field: reason}`（set_reason）
4. 理由は p_reason（前後の空白を除いて空なら「提出物のファイルの削除」）。その年度の document_files の行を全部消し、`app.document_files_deleted` を立てて、その年度の提出物の files_deleted_at を now() にする（null のものだけ。最初の削除の日時のまま）。提出の状態・日時・理由は残す（Q3）。消した行の数を返す（2回目は 0。Storage の物は、画面が document_orphan_paths の path を remove する）

**document_orphan_paths(p_year_id uuid) returns setof text**

- その年度の部門長以上、またはその年度の団体の店長・副店長（どちらでもなければ forbidden）。ロックしない。終了の年度も。
- `private.my_document_orphan_paths()` のうち、1つ目のフォルダが p_year_id のもの（部門長以上は年度の全部、店長・副店長は自団体の分）。

**document_storage_usage(p_year_id uuid) returns table (bucket_bytes bigint, limit_bytes bigint, file_count integer, file_bytes bigint, orphan_count integer)**

- その年度の部門長以上（違えば forbidden）。ロックしない。1行を返す。
- bucket_bytes：bucket documents の全部の物（全年度・どの提出にも属さないものを含む）の metadata の size の合計。limit_bytes：943718400（900 MiB）。file_count・file_bytes：その年度の document_files の行の数と大きさ（届いたものは実際の大きさ、届いていないものは申告）。orphan_count：その年度のフォルダの、どの提出にも属さない物の数。

  join public.years y on y.id = f.year_id

  language sql stable security definer set search_path = '' as $$

    and (split_part(o.name, '/', 1) in (select y::text from private.my_role_year_ids('{admin,head,deputy_head}') as y)

  using (bucket_id = 'documents'

### ロックと同時実行

- 書き込みの RPC：年度の行（for share）→ 提出の行（for update）→ ファイルの行 → 容量の勧告的ロック（reserve だけ。`gaapp.document_storage`）。どの RPC もこの順に取る（飛ばすのはよいが、逆には取らない）。
- 年度の行は for share なので、提出どうしは並行に進み、年度の状態の遷移（set_year_status の for no key update）とは順に処理される（終了と同時に書いても、終了の後には書けない）。振り分けの保存（for no key update）を長く持っている間は待つ。
- 提出物の直接の書き込み（documents）は年度の行をロックしない（events と同じ。終了と同じ瞬間の書き込みは、RLS の can_lead の読みで決まる）。
- 団体の削除（管理者）と予約が重なると、外部キーの確かめでデッドロックし得る（40P01。片方が失敗するだけ。お知らせと同じく受け入れる）。
- 読み取りの RPC（previous_year_documents・document_orphan_paths・document_storage_usage）はロックしない。
- storage.objects のトリガー（Storage API の書き込みのトランザクションの中）：年度の行（for share）→ 提出の行（for share）→ ファイルの行を読み直す。RPC と同じ順で、RPC は storage.objects の行・bucket・Storage の勧告的ロックを取らないので、ロックは輪にならない。承認が先でコミットしていなければ、物を置く書き込みは待ち、承認の後の状態で 42501 になる。物を置くのが先なら、承認がその後に進む（どちらもローカルで2つの psql で確かめた。「レビューで直したこと」）。

16. **base_updated_at**：取り消し・差し戻しは行がある提出だけなので null を invalid_input にする。提出・承認は行がなければ null を渡す。どれも既定値なし（名前つきで null を渡す）。
17. **v_document_status に提出物の列を入れる**：題名・説明・締切・ファイルが要るか（と late）を入れ、店長・副店長の /document とダッシュボードの読み取りを、ビューの1回にできるようにした（計画の 6 は提出物を別に読む形。どちらでも同じ）。団体の名前は入れない（画面は団体を別に持っている）。
18. **容量の数え方**：届いた物は実際の大きさ（metadata の size）、届いていない予約は申告の大きさ。勧告的ロックで予約どうしを順にする。（レビューの T19-SEC-2 で直した）申告より大きい物を上げる抜け道は、トリガー documents_objects_guard が届いた物の metadata の size を申告と比べて止める（Storage API が最後の insert に size を入れる。size のない insert は見ないので、Storage の版が size を入れなくなれば、もとの「bucket の 10 MiB と、1提出 5 つで抑える」に戻る）。外して予約し直す繰り返しで、どの提出にも属さない物を積み上げる道は、予約のときに団体のフォルダのどの提出にも属さない物を数えて止める（判断したことの 31）。

21. **size は integer**（10 MiB は int4 に入る。合計は bigint）。
22. **読み取りの RPC は年度の状態によらない**（previous_year_documents・document_orphan_paths・document_storage_usage）。写す・消すの書き込みだけが状態を見る。
23. **Storage の select のポリシーはフォルダで決める**：DB の行で決めると、どの提出にも属さない物を範囲の人が読めず、消せない（Storage API の remove は読み取りも要る）。
24. **v_document_status は提出を読める団体の行だけを出す**（要件を書くときの見直しで足した）：security_invoker のビューに RLS だけで任せると、閲覧のみも務める店長・副店長（閲覧のみは groups をその年度の全部読める。fixture の viewer は G4 の副店長）に、自団体が対象の提出物 × ほかの団体の行が、提出の行を読めないまま「未提出」として出る（正しくない状況を出す）。where に document_submissions_select と同じ集合（`d.year_id in (select private.my_role_year_ids('{admin,head,deputy_head,staff}')) or g.id in (select private.my_group_ids())`）を置き、問い合わせごとに1回だけ作る（D-47）。総務・店長・副店長だけの人の見える行は変わらない。画面は団体で絞って読むが、それに頼らない。
25. **RPC の補助は2つ**（0016 を書くときに決めた。SQL の約束の「名前は実装で決め」）：`private.lock_document_year(p_year_id uuid, p_group_id uuid) returns boolean`（エラーの順の 1・2：ロール → 年度の行を for share → ロールをもう一度 → 終了なら invalid_state。p_group_id が null なら部門長以上だけが呼べる。返り値は呼んだ人がその年度の部門長以上か）と `private.target_document(p_document_id uuid, p_group_id uuid, p_year_id uuid) returns documents`（4 の not_found）。どちらも SECURITY DEFINER・search_path = ''・VOLATILE（ロックの後の確かめを新しいスナップショットで読む）で、誰も実行できない（010 の「誰も実行できない」一覧に、トリガー関数2つと一緒に足す）。
26. **予約の送り直しが重なったとき**：reserve_document_file は、提出の行を for update で取った後に同じ file_id の行をもう一度読み、同じ中身なら返し、違えば invalid_input（file_id・in_use）にする（ロックを待つ間に同じ予約が入った）。ほかの提出に同じ id の行が同時に入ったときの unique_violation も invalid_input（file_id・in_use）にする（SQL の約束の「例外の直し」に足した。どちらも画面が同じ id を2つの提出に使わない限り起きない）。
27. **理由は提出の行を作る前に置く**：提出・承認は、行がないときに作る insert の監査にも同じ理由（「提出物の提出」「提出物の代理の提出」「提出物の承認」）が残る。予約・外すは `set_reason(null)` で空にしてから書く（同じトランザクションの前の理由を引き継がない）。
28. **予期しない例外の field**（D-19。ふつうは入力の確かめが先に止める）：CHECK・クラス 22 は、予約は content_type・size（制約で分ける）か file_id、提出は document_id、承認・差し戻しは note（review_note の CHECK）か document_id、写すは document_ids（reason は documents_deadline_check なら deadline_out_of_range、ほかは invalid）。外部キーの違反は not_found（予約・提出・承認）。
29. **Storage の書き込みはトリガーでも守る**（レビューの T19-SEC-1。2026-11-01）：storage.objects の insert のポリシー（RLS）だけでは、署名つきアップロード（作るときだけ RLS を確かめ、書くときは service_role）で、承認・終了の後にファイルを足したり、upsert の URL で承認済みのファイルを上書きしたりできた（レビューが Storage API で再現した）。RLS ではなく storage.objects の BEFORE INSERT OR UPDATE の行のトリガー documents_objects_guard で守る（スーパーユーザーの書き込みでもトリガーは動く）。insert は予約の行・年度が終了でない・予約した人（created_by）が今もその段で書ける提出・申告以下の大きさを、update は名前・bucket・版・metadata を変えるもの（上書き・移動）をいつでも止める（42501。detail の reason は not_reserved・closed・not_editable・too_large・immutable）。auth.uid() には頼らない（スーパーユーザーの書き込みにはない）。「予約した人の段」は my_document_upload_paths と同じ条件（その団体の店長・副店長なら未提出・差し戻し、その年度の部門長以上なら承認でない）で、予約した人が店長を外された・ロールを外された・消された後は書けない。update で止めるのを名前・bucket・版・metadata に絞ったのは、Storage の版上げで列を埋める update（owner・last_accessed_at など）を止めないため。ロックは RPC と同じ順（年度 → 提出。for share）で取り、ファイルの行を読み直す（承認・終了と同時でも、終わった後の状態で決まる。ローカルで2つの psql で確かめた）。本番の postgres が storage.objects にトリガーを作れるかは、本番を使い始める前に README の 5 で確かめる（Q15 の本番での確かめの項目に足した）。作れないときの代わりは2つ（どちらも別の PR）：
    - authenticated から storage.objects の update の権限を外す（`revoke update on storage.objects from authenticated`）。upsert の書く前の確かめ（insert … on conflict do update）は更新する列の update の権限が要るので、upsert の署名つき URL を作れなくなり、上書きの道が閉じる（PG の決まりからの見込み。この直しでは流していないので、代わりを入れるときに確かめる）。upsert なしの URL で承認・終了の後に足す道は、下の版の控えで見つける。
    - 提出・承認のときに、各物の版（storage.objects の version）を document_files に控え、違えば v_document_files と承認で見つける（承認の後に足された・差し替えられた物を、承認したものとして扱わない）。
30. **テストの準備で予約の外の物を置くときは session_replication_role = replica**（レビューの直しで決めた）：トリガーは postgres の SQL の書き込みも止めるので、fixture・026・027・013・002 の準備（どの提出にも属さない物・形の違う名前・大きな物・届いた物の metadata の書き換え）は、fixture の `tests.put_object`（`set local session_replication_role = replica` の間に insert して origin に戻す）で置く。トリガーに「設定を立てれば飛ばす」道（app.* など）を作らなかったのは、確かめを飛ばす道をトリガーの中に持たず、PG の決まりの道（postgres だけが設定できる）にだけ任せるため（027 の⑦で、service_role はこれを設定できないことも確かめる）。予約と状態の流れのとおりに置ける物（予約した店長の未提出の物など）は、トリガーを通して置く（026・027 の流れの insert）。
31. **どの提出にも属さない物の上限は、団体のフォルダで 5 つ**（レビューの T19-SEC-2）：届いた物を外して予約し直す繰り返しで、1つの団体が bucket の 900 MiB を埋め、ほかの団体の予約を storage_full にできた。レビューの2案のうち「予約のときに、その団体のフォルダのどの提出にも属さない物の数に上限を設ける」を選んだ（invalid_state、reason too_many_orphans。5 つ以上で止める。数は path の2つ目のフォルダがその団体の、bucket documents の、document_files に行のない物）。もう1案の「届いていない予約を最大の 10 MiB で数える」は、外す繰り返し（届いた物は実際の大きさで数える）を止めず、予約だけして上げない団体が 1提出 50 MiB 分を押さえられる道を新しく作るので選ばなかった。上限は、画面が外した直後に remove する（パート B）ので、ふつうは 0〜1 つ。提出物・団体を消した連鎖で 5 つ以上になった団体は、画面が document_orphan_paths の path を remove してから予約し直す（部門長以上は提出状況を開くと消える）。順は not_editable → too_many_files → too_many_orphans → storage_full。冪等の送り直し（同じ file_id・同じ中身）は数を見ない。
32. **同じ操作が重なったときは invalid_state**（レビューの F1）：店長と副店長が同時に「提出した」を押すと、後の方はロックを待った後に提出済みを見て invalid_state（not_editable と submitted）になる（計画とこの記録の E2E では conflict と書いていた）。エラーの順（状態が版より先）は変えず、04 の「提出物」と「SQL の約束」に書いた。画面は読み直して今の状態を出す。conflict の E2E（パート C）は、片方がファイルを足した後に、もう片方が足す前に読んだ古い版で提出する場合で確かめる。
33. **共有の一覧は、ぶつからない形にできる所だけ分けた**（レビューの F3）：並行の T20・T21 も同じ一覧の行を直しているので、行の数え直しはマージで避けられない（下の「マージの後にまとめること」に、ファイルと行を挙げた）。行を直さずに済む所は、提出物の分を別の確かめに分けた：001 の audit の一覧と set null の一覧（結合・CTE の条件で提出物の3表を除き、一覧と文は main のまま。提出物の3表は T19 の確かめで見る）、013 の①の表ごとの比べと「中身がある」（提出物の3表を別の文に）、030 の招待のない人の一覧（別の文に）、fixture（T19 の行を T18 の行の前に移し、最後に足す T20・T21 とぶつからないようにした）。
